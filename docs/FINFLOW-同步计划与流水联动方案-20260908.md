## 问题 1：同步任务模块要能自设定时同步

### 现状

- 调度器为「10 分钟网格」：服务启动后第 7 分钟起，每 10 分钟扫一轮全部 ACTIVE 账户，拉取 T-1 窗口（昨日全天）数据
- 幂等设计：同账户同日期窗口重复触发会**复用旧任务**，不会真实重复调银行——但每天仍有约 144 次幂等探测请求打在调度器上
- 首轮真实拉取时间 = 服务启动时间 + 7 分钟，**不可控**（比如今天 09:42 重启，首轮就在 09:49）
- CMB 规范：账务查询与支付共享 20 并发，整点/半点高峰响应慢，需错峰

### 用户的真实诉求

把「什么时候拉昨日数据」的决定权交给管理员：选银行流量低谷期（如凌晨 02:00-05:00）拉取，既减轻银行侧压力，也保证数据完整（银行日切后数据最全）。

### 方案对比

| 方案 | 说明 | 成本 | 缺点 |
|---|---|---|---|
| **A1 页面可配置同步计划**（推荐） | 新表 `bank_sync_schedule`；同步任务页加「同步计划」卡片（ADMIN）：执行时刻多选（HH:mm chips，默认 02:10）、可增删；后端调度器改每分钟心跳，命中计划时刻才发起一轮真实同步 | V25 迁移 + 调度器重写 + 3 个 CRUD 端点 + 1 张前端卡片 | 需同步 CI 迁移断言 6 处（已知清单，可控） |
| A2 配置文件定时 | `bankdata.sync.cron` 环境变量注入，改时间需改 env + 重启容器 | 极小（改一个注解） | 管理员不能自助；改一次动一次生产 |
| A3 先 A2 应急，A1 下迭代 | — | 分两步 | 两期都要动调度器 |

### A1 设计要点

- **语义变化**：从「每 10 分钟探测一轮」改为「命中计划时刻才拉一轮」——每天对银行的探测从 144 次降到计划次数（如 1-3 次），真实调用同样仅一次（幂等兜底）
- **默认种子**：V25 迁移内置一条「每日 02:10」计划，上线即有默认低谷期行为
- **错峰护栏**：计划时刻禁止整点/半点（:00/:30），前端校验 + 后端拒绝
- **页面展示**：同步任务页顶部「同步计划」卡：时刻 chips、下次执行倒计时、最近执行结果
- **权限**：`bank:manage`（ADMIN）可改，只读对所有人可见

## 问题 2：余额/流水查询在 20+ 账户后的便利性

### 现状澄清

账户筛选是**可清空单选**——不选账户 = 查询全部可见账户，并非「只能按所选账户查」。真正的痛点是 20+ 账户后的**选择效率**与**找账户**。

### 方案对比

| 方案 | 说明 | 成本 | 缺点 |
|---|---|---|---|
| **B1 账户多选 + 两级分组**（推荐） | 账户下拉升级多选（tag 模式）；选项按「公司主体 → 银行」两级分组；与公司主体筛选联动（选定公司后账户列表只显示该公司账户）；支持账号后四位/户名搜索定位 | 纯前端 + 复用既有 data source，无迁移 | — |
| B2 账户组（收藏夹） | 用户自建账户组（如「深圳分公司日常户」），按组一键筛选 | 新表 + 迁移 + 组管理 UI，成本高 | 20+ 账户尚未真实出现，宜远期 |
| B3 维持现状 | showSearch 已可搜 | 零 | 账户多时逐个点选低效 |

### 捎带小改进

- 默认时间窗：20+ 账户全量查询数据量变大，日期默认「近 7 天」并显示数据量提示（分页已有，不影响正确性）

## 问题 3：银行数据 ↔ 流水与入账 为什么不联动

### 根因：上下游关系，但中间断链

```
银行数据模块                          流水与入账模块
bank_data_statement                  statement_record
（银企直连自动拉回的原始流水）    ✗    （标准流水）
只读留存/对账/报文溯源          断链   人工复核 → 凭草稿 → 金蝶收付款单
                                        ↑ 唯一入口：导入流水页手动粘贴/上传 JSON
```

- 银行流水**自动落库**，但标准流水的唯一入口是**手动粘贴 JSON**——没有人会把银行数据模块的行复制成 JSON 再粘贴过去，所以两模块看起来完全割裂
- 设计初衷：银行数据 = 原始凭证留存（审计溯源）；标准流水 = 进入账流程的干净数据。断的是「原始 → 标准」的转换通道

### 方案对比

| 方案 | 说明 | 成本 | 缺点 |
|---|---|---|---|
| **C1 一键转入**（推荐） | 流水查询页行多选 →「转入流水与入账」按钮 → 后端按字段映射（交易时间/方向/金额/对手方/摘要，27 组件全可映射）生成标准流水，来源标记 `BANKDATA` + 银行请求号溯源；走既有导入校验/去重/复核/制证链路 | 1 个端点 + 映射器 + 前端行选择按钮 | — |
| C2 自动全量汇入 | 每轮同步完成自动转入全部新流水 | 同上 + 触发点 | 测试数据/冲正噪音直接进复核队列；建议 9.30 生产后再议 |
| C3 维持手动 | — | 零 | JSON 粘贴反人类，联动形同虚设 |

### C1 设计要点

- **幂等键**：银行请求号 + 交易时间 + 金额，重复转入走既有 duplicate 统计，不产生重复标准流水
- **溯源闭环**：标准流水详情页显示「来自银行流水 #id」，可跳转原始报文页
- **权限**：`statement:import`（与现有导入一致）
- **选择引导**：已转入的行标记「已转入」禁选，防止误操作
