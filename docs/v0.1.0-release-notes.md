# FINFLOW v0.1.0 发布说明

发布日期：2026-08-26  
发布定位：MVP 演示与开发联调版本，不可作为生产资金支付系统直接上线。

## 本版功能范围

FINFLOW v0.1.0 提供企业财务工作台的基础界面与后端服务骨架，覆盖以下范围：

- 登录、注册界面，以及后端的用户名密码登录、JWT 令牌认证、当前用户查询。
- 四类预置角色：系统管理员、财务专员、财务经理、业务查看者；后端可按权限控制用户、角色、银行账户和转账接口。
- 资金仪表盘、交易记录、发起转账和用户管理工作台的演示界面。
- 后端银行账户查询、新增和更新接口；账号对外响应按末四位掩码展示。
- 中信银行适配器边界，以及转账提交、付款账户状态和可用余额的基础校验。
- OpenAPI/Knife4j 接口文档，便于开发联调。

首次启动后端会创建本地演示管理员：账号 `admin`，密码 `Admin@123`。该凭据仅用于本地验证，严禁用于生产环境。

## 使用说明

本版本可用于产品演示、界面评审和后端接口联调。

- 前端工作台可展示登录、注册、仪表盘、交易、转账和用户管理流程。
- 后端接口使用 Bearer JWT 鉴权；接口文档默认位于 `http://localhost:8080/doc.html`。
- 开发环境默认使用内嵌 H2 数据库，初始化后包含 RBAC 基础数据、两条中信银行演示账户及初始管理员。
- 中信银行模拟模式下，转账提交会返回模拟受理结果与模拟参考号。

## 已知限制

### 前端数据与交互

- 当前前端页面使用本地演示数据和本地状态，尚未接入后端 API。登录表单不会校验后端账号或密码；任意填写的非空账号密码均可进入演示工作台。
- 注册、发起转账、保存草稿、交易筛选、导出记录和新增用户均仅完成界面交互或本地演示，不会写入后端数据库，也不会发起银行请求。
- 仪表盘金额、账户余额、待处理数量、交易记录和转账申请编号均为固定演示内容，不代表实际资金、账户或业务处理状态。
- 前端仅按本地演示权限显示用户管理菜单，不能作为服务端权限控制依据；实际权限验证以调用后端接口为准。

### 中信银行与转账

- 默认启用 `CITIC_MOCK_MODE=true`。中信银行 SDK 为本地模拟实现，只返回“已受理”的模拟结果，不连接银行、不扣减余额、不完成实际付款。
- 关闭模拟模式后，当前占位适配器会返回 `501`，明确表示未安装真实中信银行 SDK；不会产生看似成功的真实支付。
- 后端转账接口当前仅支持一次提交到银行适配器，不具备转账草稿、审批、驳回、取消、执行、状态机、幂等键、并发去重或资金流水落库能力。
- 转账调用不会写入交易记录、不会更新银行账户余额，也没有对账或冲正功能。不得据此结果判断付款成功。

### MVP 数据边界与安全能力

- 数据模型为单一系统数据集，未实现企业/租户字段、企业级数据隔离或跨企业访问控制。不得存储或混用多个企业的真实生产数据。
- 交易记录、仪表盘汇总、审批任务、审计日志、操作留痕、通知、导入导出、密码找回、会话撤销和多因素认证均未实现为后端持久化业务能力。
- 用户注册会创建 `PENDING` 状态账号；用户管理接口可创建和更新用户及角色，但未提供邀请、邮件激活、停用后主动撤销既有 JWT、删除用户或管理员防误停用机制。
- 后端以 BCrypt 保存密码，并为接口提供 JWT 与方法级权限检查；但 v0.1.0 未实现登录限流、审计留存、生产级安全响应头、CORS 策略、密钥轮换、传输层终止配置和完整的安全监控。
- 银行账号在接口响应中掩码展示，但数据库仍保存账户原值；生产接入前应补充字段加密、密钥管理与访问审计。
- 后端角色与权限 API 支持查询及新增角色，不支持角色编辑、删除、审批工作流或职责分离校验。

## 部署前须知

### 本地演示

请准备 Java 17+、Maven 3.9+、Node.js 18+ 和 npm。先启动后端，再启动前端开发服务；前端开发服务器会将 `/api` 请求代理到 `http://localhost:8080`。

开发环境使用内存 H2 数据库，服务重启后演示数据会重新初始化。不要将此环境用于保存需要保留的数据。

### 生产或预生产环境

v0.1.0 不满足直接生产投产条件。若部署到预生产或继续进行生产化改造，至少应完成以下事项：

1. 使用 MySQL 与受控备份策略，配置 `prod` profile、`DB_URL`、`DB_USERNAME`、`DB_PASSWORD`、强随机 `JWT_SECRET` 和合理的 `JWT_EXPIRATION`；不得使用开发默认密钥或初始管理员密码。
2. 将前端与后端部署在同源域名下，或由反向代理统一转发 `/api`。当前后端关闭 CORS，不支持未配置代理的跨域前端调用。
3. 通过部署平台的密钥管理服务注入数据库凭据、JWT 密钥、中信银行应用标识、证书和私钥；不得将任何真实凭据或证书提交到代码库或前端产物。
4. 在进行真实支付前，按中信银行授权要求安装 SDK，替换占位适配器，并配置 `CITIC_MOCK_MODE=false`、网关地址、应用标识及证书参数；完成银行侧联调和回执/对账验证后方可开放。
5. 在生产化前补齐企业隔离、交易与审批状态机、职责分离、幂等与事务一致性、审计、账户字段加密、权限变更即时失效、监控告警及自动化安全测试。
6. 首次登录后立即更换初始管理员密码，并创建最小权限的日常账号；演示账户号、演示数据与测试令牌不得进入生产环境。

## 验收摘要

本说明基于当前 README 和代码实现核对，未执行部署、构建、接口联调或真实银行验证。

| 验收项 | v0.1.0 结论 | 说明 |
| --- | --- | --- |
| 前端工作台体验 | 可验收为演示界面 | 登录、注册、仪表盘、交易、转账、用户管理页面可进入和操作；数据为本地样例。 |
| 后端认证与 RBAC 骨架 | 可验收为开发接口能力 | 提供 JWT、权限注解、用户与角色接口；需通过接口调用验证，不由前端演示页面覆盖。 |
| 银行账户管理接口 | 可验收为开发接口能力 | 支持查询、新增、更新和账号掩码返回；未含企业隔离和字段加密。 |
| 中信银行转账 | 仅可验收为模拟联调 | 模拟模式返回受理结果；不代表真实银行受理、扣款或到账。 |
| 交易、审批、对账与审计 | 不在本版可验收范围 | 尚无对应后端持久化模型与流程。 |
| 生产资金操作 | 不通过 | 必须完成上述生产化改造、真实银行联调、安全测试及业务验收。 |

## 建议的验收边界

验收时请使用虚拟账户、虚拟收款信息和测试金额，并明确将结果标记为“演示通过”或“接口联调通过”。任何涉及真实客户、真实企业资金、真实银行凭据或生产数据库的验收，应在后续生产化版本完成控制措施后重新执行。
