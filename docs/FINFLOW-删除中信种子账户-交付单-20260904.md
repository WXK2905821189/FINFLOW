## 1. 背景：为什么必须删

`V1__init_rbac_and_bank_accounts.sql` L84-86 种了两个账户：

| id | bank_code | 账户名 | 账号 | 余额 |
|---|---|---|---|---|
| 1 | CITIC | 中信银行基本户 | 6222000000004821 | 986400.52 |
| 2 | CITIC | 中信银行一般户 | 6222000000007306 | 300000.00 |

这是 v0.1 支付时代的演示种子。在账户级直联语义（`AccountDirectStatusService`，昨日已上线）下，这两行是**反向误导**：中信 9/18 才联通、没有装配任何 REAL 适配器，这两行永远只能是 `NOT_CONNECTED`，但它们带着的模拟余额却在暗示"这个银行有数据"。

仅改成 `DISABLED` 不够 —— 账户行仍在列表里、余额仍在、任何汇总口径都可能被引用到。故按 D1 决策**物理删除**。

## 2. 改动内容

### 2.1 新增迁移 `V15__retire_seeded_citic_accounts.sql`

V1 已应用不可改（Flyway checksum 红线），因此做成新迁移。外键依赖共 **10 张表**，按图自底向上清理：

```
1. bank_data_statement          ← 叶子（引用 task + raw_message）
2. bank_data_balance            ← 叶子（引用 task + raw_message）
3. bank_data_sync_log           ← 引用 task
4. bank_data_raw_message        ← 引用 task
5. bank_data_sync_task          ← 引用 bank_account
6. payment_transfer_audit_event ← 引用 payment_transfer
7. payment_transfer             ← payer_account_id NOT NULL + FK
8. statement_audit_event        ← 引用 statement_record
9. statement_record             ← 引用 bank_account
10. bank_account                ← 最终删除
```

三条设计约束：

- **每条 DELETE 的子查询都指向另一张表**，不使用多表 JOIN-DELETE 语法 —— 该语法 MySQL 与 H2(MySQL mode) 不一致，而 Flyway 迁移在两边都要跑（生产 MySQL / 测试 H2）。已在 H2 实测通过。
- **最终删除带 `bank_code = 'CITIC'` + `account_number IN (...)` 双重护栏**，仅凭 `id IN (1,2)` 不删，防止将来 id 被回收复用时误删真实建档账户。
- **清理范围限定在这两个账户**，其它账户的数据一行不动。

`payment_transfer` 的清理说明：该表的 `/api/transfers` 端点已在 v0.4 移除、V14 已注销其权限，当前只剩 entity + mapper，**无 Service / Controller 消费**，属死表；绑定在这两个演示账户上的行是不可达的历史遗留。

### 2.2 测试同步（3 个文件）

删掉种子后 4 个测试因依赖它而失败，全部改为**自建账户**，不再依赖任何种子数据：

## 3. 部署侧操作

### 3.1 执行前：核查 + 备份（**必做，物理删除不可逆**）

先连生产库看一眼这两个账户牵连了多少数据：

```sql
-- ① 确认目标账户仍在（应返回 2 行；返回 0 行说明已删过，直接跳过本交付）
SELECT id, bank_code, account_name, account_number, available_balance, company_id
FROM bank_account
WHERE account_number IN ('6222000000004821','6222000000007306');

-- ② 各表牵连行数（心里有数再执行）
SELECT 'bank_data_statement'  t, COUNT(*) FROM bank_data_statement  WHERE bank_account_id IN (1,2)
UNION ALL SELECT 'bank_data_balance',    COUNT(*) FROM bank_data_balance    WHERE bank_account_id IN (1,2)
UNION ALL SELECT 'bank_data_sync_task',  COUNT(*) FROM bank_data_sync_task  WHERE bank_account_id IN (1,2)
UNION ALL SELECT 'bank_data_raw_message',COUNT(*) FROM bank_data_raw_message
             WHERE task_id IN (SELECT id FROM bank_data_sync_task WHERE bank_account_id IN (1,2))
UNION ALL SELECT 'bank_data_sync_log',   COUNT(*) FROM bank_data_sync_log
             WHERE task_id IN (SELECT id FROM bank_data_sync_task WHERE bank_account_id IN (1,2))
UNION ALL SELECT 'payment_transfer',     COUNT(*) FROM payment_transfer WHERE payer_account_id IN (1,2)
UNION ALL SELECT 'payment_transfer_audit_event', COUNT(*) FROM payment_transfer_audit_event
             WHERE payment_id IN (SELECT id FROM payment_transfer WHERE payer_account_id IN (1,2))
UNION ALL SELECT 'statement_record',     COUNT(*) FROM statement_record WHERE bank_account_id IN (1,2)
UNION ALL SELECT 'statement_audit_event',COUNT(*) FROM statement_audit_event
             WHERE statement_id IN (SELECT id FROM statement_record WHERE bank_account_id IN (1,2));
```

若 ② 中 `payment_transfer` 或 `statement_record` **不为 0**，说明有真实业务留痕绑在演示账户上 —— **先回传行数，不要直接执行**，需要小棵确认后再删。

备份（一行即可，删错了能捞回来）：

```sql
CREATE TABLE bank_account_bak_20260904 AS
SELECT * FROM bank_account WHERE account_number IN ('6222000000004821','6222000000007306');
```
