## 1. 现状诊断

### 1.1 流水：30 个真实字段，只落了 7 个

`RealCmbBankDataAdapter` L184-190 当前的解析：

```java
transactionTime = transactionTime(transDate, transTime)   // 合并成一个时间戳
direction       = direction(loanCode)                      // C/D → 方向词（投影）
amount          = magnitude(transAmount)                   // 取绝对值，符号丢弃
statementNo     = transSequenceIdn
summary         = firstNonBlank(businessText, remarkTextClt)
counterpartyName/Account = ctpAcctName / ctpAcctNbr
```

**丢弃的 23 个字段**（按价值排序）：

| 丢弃字段 | 含义 | 为什么可惜 |
|---|---|---|
| `acctOnlineBal` | **每笔交易后的余额** | 最有价值——可对账、可验证连续性，现在完全没落库 |
| `valueDate` | 起息日 | 与交易日不同，涉及利息与跨期核算 |
| `textCode` | 交易类型 | 银行侧业务分类（如"网联付款申请收款"） |
| `reversalFlag` | 冲账标志 | `*`冲账 / `X`补账，冲账借贷相反，不落库会算错方向 |
| `infoFlag` | 信息标志 | 决定"收付方"到底指收方还是付方（空/1/2/3 四义） |
| `extendedRemark` | 扩展摘要 | 银行侧附加追踪串 |
| `ctpBankName` / `ctpBankAddress` | 收付方开户行名/地址 | 对手方开户行信息 |
| `fatOrSon*` 系列（4 个） | 母子公司账号/名称/开户行名/地址 | 集团账户场景必需 |
| `businessName` / `yurRef` / `requestNbr` / `virtualNbr` / `mchOrderNbr` / `transCardNbr` / `billNumber` / `reserve` | 业务关联号 | 与内部业务单据对账的桥梁 |
| `currencyNbr` | 币种 | 当前硬编码取 null（多币种账户会错） |

### 1.2 余额：10 个真实字段，只落了 1 个

`NTQADINF` 响应 `ntqadinfz` 返回 10 个字段，当前 `BankDataBalanceEntry` 只取了「余额」一个数：

| 字段 | 含义 | 现状 |
|---|---|---|
| `accblv` | 上日余额 = 联机余额 − 当日金融交易发生额 | ❌ 丢弃 |
| `onlblv` | 联机余额（账户实际资金） | ❌ 丢弃 |
| `hldblv` | 冻结余额（司法冻结+银行冻结等合计） | ❌ 丢弃 |
| `avlblv` | 可用余额 | ✅ 落地（当前唯一） |
| `accitm` 科目 / `bbknbr` 分行号 / `accnam` 户名 / `relnbr` 客户关系号 / `ccynbr` 币种 | 账户标识 | ❌ 丢弃 |

> 只留「可用余额」意味着：**看不到被冻结了多少、看不到当日动了多少钱**，而这恰是财务最关心的两个口径。

### 1.3 原始报文：已留存，但不可见

`bank_data_raw_message` 表（V4 建）结构完整——`payload TEXT` + `content_sha256` + `retention_until` + `adapter_code` + `bank_request_no`。数据一直在写。

缺的只是**出口**：没有查询接口、没有前端页面。所以现在要确认"是不是真的连上了"，只能翻数据库。

## 2. 需求 ① ：原始报文独立模块

### 2.1 定位

这个模块的产品价值不是"看数据"，而是**连通性取证**：看到一条来自 `CMB` 适配器、带银行请求号、带真实响应体的报文 = 连通这件事有了物证。

### 2.2 后端

新增 `RawMessageQueryService` + 端点（建议挂在现有 `bankdata` 权限域下）：

| 端点 | 说明 | 建议权限 |
|---|---|---|
| `GET /api/bank-data/raw-messages` | 列表，分页。过滤：账户、任务号、适配器、银行请求号、时间窗 | 新增 `bankdata:raw:view` |
| `GET /api/bank-data/raw-messages/{id}` | 详情，返回完整 payload | 同上 |
| `GET /api/bank-data/raw-messages/{id}/download` | 下载原始报文（`.json`），便于留档比对 | 同上 |

列表**不返回 payload 全文**（避免大载荷拖垮列表页），只返回元信息 + 载荷摘要：

- 任务号 / 适配器代码 / 银行请求号
- 接收时间、保留到期时间
- SHA256（前 12 位展示，完整值详情可见）
- 载荷字节数、条目数
- **连通标识**：该报文是否由 REAL 模式适配器产生（这是"是否真连上"的直接判据）

### 2.3 前端

新增独立页面 `原始报文`（建议路由 `/bank-raw`，菜单独立成项，不塞进现有银行数据页）：

- 顶部筛选：账户 / 任务号 / 适配器 / 时间范围
- 列表：上述元信息 + 连通标识 Tag（绿=真实直联产生 / 灰=其它）
- 详情抽屉/弹窗：**JSON 语法高亮 + 折叠 + 复制 + 下载**，并展示 SHA256 与保留到期
- 空态明确文案：区分「还没有同步过」（去发起任务）与「同步过但没有真实报文」（未接通）

## 3. 需求 ② ：流水 / 余额改成真实字段

### 3.1 关键判断：以 API 字段为准，不以导出件为准

你给的导出件是招行**网银导出**格式（36 列），而我们系统走的是 **API `trsQryByBreakPoint`**（30 字段）。两者**不等价**，最重要的差异在借贷表示：

| | API（我们实际拿到的数据） | 导出件 Excel |
|---|---|---|
| 借贷 | `loanCode`：`C`贷方 / `D`借方 | 「借方金额」「贷方金额」两列 |
| 金额 | `transAmount` **单个带符号值**（贷为正、借为负，文档范例中借方为 `-40.01`） | 两个**无符号**金额列，互斥（实测 13 行：both=0, neither=0） |
| 币种 | `currencyNbr` 代码（`10`=人民币） | 「人民币」文字 |
| 独有 | `virtualNbr` 虚拟户、`transCardNbr` 记账卡号、`yurRef` 业务参考号、`businessText` 网银业务摘要、`reserve` | 账号名称、收付方**分行名**、开户行**行号**、有否附件信息、交易分析码、内部编号、公司一卡通号 |

**结论**：以 **API 字段为存储基准**（忠实于我们真正收到的数据，且不丢符号信息）；导出件的「借方/贷方两列」是展示层与导出层的**派生视图**，由 `loanCode + transAmount` 推导即可，不进主存储。

### 3.2 目标：流水字段（30 个 API 字段全落）

新增列（挂在流水表上）：

| 分组 | 字段 |
|---|---|
| 时间 | 交易日 `transDate`、交易时间 `transTime`、起息日 `valueDate` |
| 金额 | 借贷码 `loanCode`、交易金额 `transAmount`（**保留符号**）、币种 `currencyNbr`、**余额 `acctOnlineBal`** |
| 业务 | 交易类型 `textCode`、票据号 `billNumber`、业务名称 `businessName`、网银业务摘要 `businessText`、你方摘要 `remarkTextClt`、扩展摘要 `extendedRemark` |
| 状态 | 冲账标志 `reversalFlag`、信息标志 `infoFlag` |
| 对手方 | 收付方账号/名称/开户行名/开户行地址 `ctpAcctNbr` `ctpAcctName` `ctpBankName` `ctpBankAddress` |
| 母子公司 | `fatOrSonAccount` `fatOrSonCompanyName` `fatOrSonBankName` `fatOrSonBankAddress` |
| 关联号 | 流水号 `transSequenceIdn`、流程实例号 `requestNbr`、业务参考号 `yurRef`、虚拟户编号 `virtualNbr`、商务支付订单号 `mchOrderNbr`、记账卡号 `transCardNbr`、保留字 `reserve` |

### 3.3 目标：余额字段（10 个 API 字段全落）

上日余额 `accblv`、联机余额 `onlblv`、冻结余额 `hldblv`、可用余额 `avlblv`、科目 `accitm`、分行号 `bbknbr`、账号 `accnbr`、户名 `accnam`、客户关系号 `relnbr`、币种 `ccynbr`。

### 3.4 代码改动点

| 层 | 文件 | 改动 |
|---|---|---|
| 解析 | `BankDataEntry`（record） | 从 10 字段扩到 30 字段 |
| 解析 | `BankDataBalanceEntry`（record） | 从 5 字段扩到 10 字段 |
| 解析 | `RealCmbBankDataAdapter` | 全字段映射；**不再**把 `transAmount` 取绝对值、`loanCode` 不再翻译成方向词（原值保留） |
| 存储 | V16 迁移 | 流水表 / 余额表新增列 |
| 实体 | `BankDataStatement` / `BankDataBalance` | 新增对应字段 |
| 查询 | `BankDataQueryService` + 响应 DTO | 输出真实字段，不再做投影 |
| 前端 | `BankDataQueryPage.tsx` | 列表列改为真实字段（交易日/时间/起息日/借贷/金额/余额/交易类型/对手方…），支持列显示控制 |
| 前端 | 导出 | 新增导出件格式（对齐你给的 36 列网银格式，含借贷双列），方便与银行对账单逐列核对 |

## 4. 迁移方案

- **V16**：`bank_data_statement` 新增列（可空，历史行不回填——历史数据本就是投影的残缺数据，不伪造）。
- **V17**：`bank_data_balance` 新增列（同上）。
- 两处都遵守：裸 `TIMESTAMP` 在 RDS OFF 模式非法 → 用 `TIMESTAMP NULL DEFAULT NULL`；跨库兼容 → 不用多表 JOIN-DELETE 语法。
- 唯一键 `uk_bank_statement_business` 暂不动（仍可用于防重复同步）。

**历史数据处理**：新增列为空的历史流水，前端显示为 `--`，并在页面上标注「该记录产生于字段扩展前，缺少银行原始字段，建议重新同步该窗口」。不虚构数据。
