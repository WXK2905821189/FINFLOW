# 自动入账一期测试与联调计划

## 1. 目标与范围

**目标版本**：2026-09 自动入账一期。

**验收目标**：证明受控 `FILE`/`MOCK` 来源的流水，能够在不触碰真实银行和真实金蝶的前提下，完成幂等导入、精确校验、职责分离复核、单次模拟制证、模拟对账和不可篡改审计；并为首个完整自然月节省 **6-7 人天/月** 建立可复盘口径。

**纳入测试**：文件/模拟来源、导入批次、标准流水、校验、复核、金蝶云星空模拟网关、模拟对账、RBAC、企业隔离、审计、迁移和前后端联调。

**明确不测**：真实银行 SDK/API、真实银行文件拉取、余额/回单/清算、真实金蝶接口或账套、真实凭证创建、真实银行/总账对账、支付/调拨状态机。发现上述调用、配置或成功表述即记为 P0 越界缺陷。

## 2. 准入、准出与证据

### 准入条件

- 测试环境使用专用企业、专用银行账户、测试凭据和金蝶模拟网关；环境变量、网络白名单和日志中均无真实银行/金蝶凭据。
- 已部署包含自动入账迁移的候选版本；提供 API 契约、固定文件模板、模拟网关故障开关和可查询日志/审计。
- 准备五个受控账号：`importer`（`statement:view, statement:import`）、`reviewer`（`statement:view, statement:review`）、`voucher`（`statement:view, voucher:push`）、`recon`（`statement:view, reconciliation:view`）、`denied`（无自动入账权限）。导入人与复核人必须不同。
- 准备第二企业的同名账户、相同流水号和相同凭证号样本，用于越权与隔离测试。

### 准出门槛

- 本计划全部 P0 用例通过；无未批准的越权、重复流水、重复模拟凭证、金额差异、审计篡改、真实连接或虚假成功缺陷。
- P1 用例完成，或有财务、安全、产品负责人签字的风险接受、补偿控制和截止日期。
- 保存版本号/制品哈希、数据库迁移版本、测试数据版本、接口请求编号、脱敏响应、审计截图或查询结果、模拟网关调用记录和缺陷链接。
- 使用本计划第 7 节口径完成 2026-09 后首个完整自然月收益复盘。

## 3. 状态机与不变量

| 对象 | 允许状态/流转 | 不变量 |
| --- | --- | --- |
| 批次 | `PROCESSING -> COMPLETED`、`PARTIAL_COMPLETED` 或 `FAILED` | 批次号唯一；总数 = 有效落库数 + 无效数 + 重复数；部分失败不回滚已验证有效流水。 |
| 校验 | `VALID`、`INVALID`、`DUPLICATE` | 仅 `VALID` 可复核；没有最小识别信息的行不创建流水；重复行无第二条流水或制证机会。 |
| 复核 | `PENDING -> APPROVED` 或 `REJECTED` | 导入人不得复核本人流水；驳回原因必填；终态不可覆盖；原始流水不可编辑。 |
| 模拟制证 | `NOT_PUSHED -> PUSHING -> PUSHED/PUSH_FAILED`；`PUSH_FAILED` 可按同一流水键重试 | 仅已通过复核可推送；同一流水最终最多一个成功模拟凭证号；未知结果不得报告成功或创建新凭证。 |
| 模拟对账 | `UNRECONCILED`、`MATCHED`、`MISMATCH` | 仅核对来源、FINFLOW 流水和模拟凭证；差异必须有类型和可定位的记录，不改变账户余额。 |

## 4. 固定测试数据集

| 数据集 | 内容 | 预期用途 |
| --- | --- | --- |
| `AA-VALID-01` | 2 笔收入、2 笔支出，`CNY`，金额 `0.01`、`100.00`、`999999999999.99`，唯一流水号 | 基本导入、金额边界、复核、成功制证、对账。 |
| `AA-PARTIAL-01` | 1 笔有效；缺流水号、停用账户、非法方向、非 CNY、零/负数、三位小数各 1 笔 | `PARTIAL_COMPLETED`、字段级异常、异常不入账。 |
| `AA-DUP-01` | 同批次重复流水号、与 `AA-VALID-01` 重复流水号、相同关键字段不同流水号 | 同批/跨批去重、统计和可追溯性。 |
| `AA-REVIEW-01` | 由 `importer` 导入的有效流水 | 导入人与复核人分离、驳回原因、并发复核。 |
| `AA-PUSH-01` | 已复核通过的唯一流水 | 模拟网关成功、失败、超时/未知、重试和并发单次性。 |
| `AA-RECON-01` | 已制证流水，另注入缺凭证、金额不同、方向不同、计数不同样本 | `MATCHED/MISMATCH`、差异金额和定位。 |
| `AA-ISOLATION-02` | 第二企业相同账户/流水号/凭证号 | 企业隔离、ID/查询参数篡改和存在性隐藏。 |

所有交易对手账号使用虚拟号码；原始载荷仅在受控审计查询中保存，展示、错误响应、日志和测试证据均掩码。

## 5. 执行用例

| ID | 优先级 | 场景与操作 | 通过标准/证据 |
| --- | --- | --- | --- |
| AA-01 | P0 | `importer` 导入 `AA-VALID-01` 的 `FILE`；再以 `MOCK` 空记录触发模拟来源。 | 各生成唯一批次号；流水为 `VALID + PENDING + NOT_PUSHED`；MOCK 全链路带模拟标签；无支付/调拨、余额变动或银行网关调用。保存批次、流水和审计。 |
| AA-02 | P0 | 用同一导入请求/文件同时发起两次，并在首个响应超时后使用同一幂等键重试。 | 只创建一个逻辑批次或由契约返回同一结果；每个唯一流水号最多一条记录，统计不重复，审计能关联重试请求。 |
| AA-03 | P0 | 导入 `AA-DUP-01`，并重新导入已完成文件。 | 同批和跨批重复均被识别；重复数准确，无第二流水、无第二次复核/制证机会；可定位原流水和原批次。 |
| AA-04 | P0 | 导入 `AA-PARTIAL-01`。 | 批次为 `PARTIAL_COMPLETED`；每条异常有安全的字段/业务原因；最小识别信息不足的行不落流水，其他异常仅为 `INVALID`；有效行不受回滚影响。 |
| AA-05 | P0 | 对 `0`、负数、`1.001`、超大金额、空值、科学计数法、非法方向和非 CNY 分别导入。 | 非法值不成为 `VALID`；金额不静默四舍五入；有效汇总精确至两位，收入/支出按方向分别汇总。 |
| AA-06 | P0 | 用 `importer` 复核自己导入的流水；再由 `reviewer` 通过、驳回无原因、驳回有原因；对同一流水并发复核。 | 自审服务端返回 `403`；无原因驳回为 400；通过/驳回各仅一次成功，另一个并发请求返回状态冲突；审计保存操作者、意见、前后状态和请求编号。 |
| AA-07 | P0 | 未登录、`denied`、仅查看、导入、复核、制证、对账账号分别访问各页面、深链接和 API。 | 权限矩阵严格生效；无权返回 `401/403`，不返回资源详情。前端隐藏不是唯一控制，后端记录权限拒绝审计。 |
| AA-08 | P0 | 将批次/流水/凭证/企业 ID 替换为 `AA-ISOLATION-02` 的值，遍历列表、详情、复核、推送和对账请求。 | 当前企业外数据不可枚举、读取或修改；响应不泄露对象存在性、金额、账号、凭证号或审计信息。 |
| AA-09 | P0 | 对 `AA-PUSH-01` 注入模拟制证成功；重复点击、刷新、同键重试及并发推送。 | 仅一次模拟网关成功调用或可证实的同一外部幂等请求；流水为 `PUSHED`，只有一个凭证号、推送时间和成功审计。 |
| AA-10 | P0 | 对 `AA-PUSH-01` 注入明确失败及超时/未知结果，再用授权账号重试。 | 失败后为 `PUSH_FAILED` 或保留 `PUSHING` 供查询，不改变 `APPROVED` 结论；错误脱敏；重试沿用流水业务键并记录所有尝试；成功后仅一个凭证号。 |
| AA-11 | P0 | 对 `INVALID`、`DUPLICATE`、`REJECTED`、未复核和已 `PUSHED` 流水直接调用推送 API。 | 均被拒绝，无模拟网关调用、凭证、状态覆盖或误导性“成功”提示。 |
| AA-12 | P0 | 对 `AA-RECON-01` 按批次和日期范围执行模拟对账。 | 来源 = 有效 + 无效 + 重复；收入/支出笔数和金额口径一致；缺凭证、金额/方向/计数差异全部 `MISMATCH` 且定位流水与差异类型；不改账户余额。 |
| AA-13 | P0 | 分别通过批次号、流水号、凭证号查询详情和对账；尝试修改/删除原始流水、成功凭证和审计记录。 | 可双向看到来源、批次、校验、复核、推送、对账和时间线；写入/删除被拒绝，历史不被覆盖；默认输出只有账号末四位。 |
| AA-14 | P1 | 注入解析失败、数据库唯一约束/审计写入失败、服务重启和模拟网关延迟。 | 每个对象保持明确可恢复状态；不存在“批次成功但统计错误”“凭证成功但无记录”等半成功；告警/日志具备请求编号且无敏感数据。 |
| AA-15 | P1 | 在桌面与窄屏执行导入、部分成功、复核冲突、制证失败/重试、403 和会话失效流程。 | 状态文字与数据一致，重复按钮受控；文件名、敏感账号、原始载荷不泄露到浏览器存储、控制台或错误页面。 |

## 6. 联调顺序与每日退出条件

1. **环境与契约**：确认模拟开关、专用企业、权限账号、固定模板、网关故障注入和请求编号。完成 AA-01、AA-07、AA-08。
2. **导入与数据质量**：执行 AA-02 至 AA-05，核对数据库、批次汇总与页面一致性。
3. **人工复核与状态机**：执行 AA-06，覆盖正常、拒绝、并发和非法状态。
4. **模拟制证**：执行 AA-09 至 AA-11，逐项保存模拟网关调用记录和凭证唯一性证据。
5. **对账、追溯与韧性**：执行 AA-12 至 AA-15，核对审计、脱敏、失败恢复和告警。

每天结束前，QA 与开发共同确认：新增 P0 缺陷、未解释的批次/流水/凭证计数差异、未关联请求编号的失败、任何真实外部调用均为零。任一 P0 未关闭时，不进入下一联调阶段。

## 7. 6-7 人天/月收益复盘口径

| 指标 | 基准月与统计方式 | 通过标准 |
| --- | --- | --- |
| 基准工时 | 财务负责人确认上线前连续一个自然月；逐项记录人工下载/整理、导入、异常处理、复核、制证和追溯的实际小时。 | 样本业务量、账户范围、人员和统计口径已签字。 |
| 上线后工时 | 2026-09 后首个完整自然月按相同分类记录人工介入时间；系统处理时长不计为人工工时。 | 数据可由工单、批次审计和工时表交叉核对。 |
| 节省计算 | `(基准人工小时 - 上线后人工小时) / 8`，只在业务量和处理范围可比时计算。 | 结果为 6-7 人天/月；未达标时提交差异原因、补偿措施、负责人和目标日期。 |
| 排除项 | 真实银行/金蝶故障、范围外手工调整、非可比业务量和非一期功能。 | 不将范围外收益或损失计入一期结论。 |
