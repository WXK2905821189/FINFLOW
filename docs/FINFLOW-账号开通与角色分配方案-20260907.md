## 2. 角色结构方案（三选一，推荐 D1）

| 方案 | 内容 | 适用 | 代价 |
|---|---|---|---|
| **D1 仅用 4 内置角色**（✅ 已拍板 2026-09-07） | ADMIN / FINANCE_STAFF / FINANCE_MANAGER / VIEWER，不自建角色 | 当前团队规模小、岗位边界清晰 | 无额外维护成本 |
| D2 = D1 + 代发操作员 | 自建 `PAYROLL_OPERATOR`：dashboard:view + bankdata:payroll:view + bankdata:sync:trigger | 若有专人只做代发查询/触发同步、不给其他财务权限 | 多一个角色要维护权限集 |
| D3 = D1 + 外部审计角色 | 自建 `AUDITOR`：dashboard:view + audit:view（仅审计中心） | 有外部审计/集团检查需要临时最小账号 | 审计结束需停用该账号 |

> 推荐理由：D1 最小权限 + 零新增维护；D2/D3 在页面「角色与权限」页签随时可加（本次 GAP-6 已支持自定义角色全生命周期），出现真实需求再加不迟。

## 3. 岗位 → 角色映射（D1 口径）

| 岗位 | 角色 | 数量建议 | 能做 / 不能做（关键差异） |
|---|---|---|---|
| 系统管理员（IT/运维，建议 2 人互为备份） | ADMIN | 2 | 全部管理 + 全部业务查看；**上限 2**（最小化），受「末位 ADMIN 保护」约束 |
| 出纳 / 财务专员（付款经办、导入流水、制证） | FINANCE_STAFF | 1-2 | 导入流水、金蝶制证、触发银行同步、查余额/流水/回单/代发、看原始报文；**不能**人工复核、结账审批、用户管理 |
| 财务经理（复核、监控、结账审批） | FINANCE_MANAGER | 1 | 人工复核、直联监控、日志查询、结账管理、审计中心；**不能**制证/导入（职责分离）、**不能**看原始报文 |
| 领导 / 查看者 | VIEWER | 1-2 | 只读全部业务 + 审计中心；无任何管理/操作入口 |

**职责分离红线（系统已天然保证，分配时勿破坏）**：
- `statement:review`（复核）只有 ADMIN/MANAGER 持有；`voucher:push`（制证）只有 ADMIN/STAFF 持有 → **除 ADMIN 外无任何角色同时持有两权**。不要自建同时含两权的自定义角色。
- ADMIN 账号不做日常业务操作（用业务账号操作，审计才可归因到人）。

## 6. 密码与交付规范

- 初始密码由 ADMIN 创建账号时设置：**≥8 位且同时含字母和数字**（系统前后端双重强制，弱口令直接拒绝）。
- 交付：**线下单独渠道**告知本人（当面/电话），不经群聊/邮件明文传密码；页面不回显任何明文密码（单向哈希存储，含 ADMIN 在内无人可查看）。
- 忘记密码：ADMIN 在「用户与角色 → 编辑 / 重置密码」重置；**重置后该用户所有已登录会话立即失效**（9/7 已上线该机制）。
- 禁止共享账号；发现共用即停号重开。

## 7. 开通 SOP（新页面操作）

1. ADMIN 登录 → 系统管理 → 用户与角色 → 账号管理 → **新增账号**
2. 填用户名/邮箱/手机号/状态=ACTIVE/角色（多选）→ 初始密码 → 保存（页面提示"请线下告知初始密码"）
3. **审计核对**：审计中心查 `action=USER_CREATE`，确认记录存在且 detail 无密码
4. 通知本人首次登录，本人核对工作台菜单与岗位匹配（对照 §3 能做/不能做）
5. 在 §5 清单打钩归档

**变更/离职 SOP**：
- 离职：账号管理 → 停用（该账号所有在线会话**立即失效**，无需改密码）；账号永久保留作审计线索，不物理删除
- 转岗：编辑账号改角色即可，权限即时生效（下一请求按新权限鉴权）
- ADMIN 变更：系统保证永远剩余 ≥1 个 ACTIVE ADMIN（试图停用/降级最后一个会被 400 拦截）
