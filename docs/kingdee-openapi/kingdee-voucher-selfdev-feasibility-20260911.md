# 金蝶制证自研可行性调研与评估（2026-09-11）

> 背景：金蝶方贾经理表示「2 万部署费」的制证工作（收付款单→凭证模块配置/逻辑设置）只有金蝶内部技术可做。
> 本报告基于：线上公开资料调研 + 真实账套（xyrc.ik3cloud.com）只读实测，评估自主开发可行性。

## 一、贾经理说的「制证工作」到底是什么

从聊天记录拆解，2 万对应的实施内容 = 两块：

| # | 工作内容 | 技术门槛 | 我们现状 |
|---|---|---|---|
| 1 | 与开发同步「哪些必要字段必须传过来」（收付款单字段校准） | 熟悉金蝶单据模型 | ✅ **已完成**：9/4~9/7 经演示环境实测校准全部必填字段，9/9 真实账套二次验证一致 |
| 2 | 「设置凭证模块、逻辑」（单据→记账凭证的科目映射/生成规则） | 会计口径 + 金蝶配置 | ❗ 本报告评估对象 |

## 二、实账只读验证结果（2026-09-11，授权登录后仅执行查询）

| 探测项 | 结果 | 含义 |
|---|---|---|
| 总账 GL_VOUCHER | ✅ 可查（存有 2016 年起的凭证） | **总账模块已购买且在用** |
| 智能会计平台（凭证模板所在模块） | ❌ **「模块未购买」** | 标准「单据→自动凭证」功能此账套用不了；金蝶若要做须先卖模块或手工/导入方式 |
| 科目表 BD_Account | ✅ 可读（1001 库存现金 / 1002 银行存款 / 1122 应收…标准科目体系） | 自研拼分录的「原料」完整可读 |
| WebAPI 权限 | ✅ 已打通（LoginByAppSecret + ExecuteBillQuery） | 推凭证走同一通道，零新增依赖 |

**关键推论：账套没买智能会计平台 → 金蝶实施要交付「制证」，要么推荐买模块（另收费），要么走手工录凭证/凭证引入。而「API 直接写总账凭证」这条路不需要任何额外模块，且不在金蝶实施报价的默认路径里。**

## 三、三条路径对比

### 路径 A：购买智能会计平台 + 自配凭证模板
- 官方文档明确：「系统预置了日常经营活动常用的凭证模板，用户可以根据企业实际情况修改或细化」——**配置本身不是金蝶内部专属技能**，是标准产品功能，公开文档齐全（open.kingdee.com/K3Cloud/help/BAS_VCHTEMPLATE.html）。
- 但前提是买模块（费用另计，可能不低于 2 万），且本账套当前无此模块。**不推荐现在走**。

### 路径 B：FINFLOW 直接推 GL_VOUCHER 记账凭证（推荐）
- 第三方集成平台（轻易云等）批量 API 推凭证是成熟做法，字段映射完全公开：
  - 表头：FDate 日期 / FVOUCHERGROUPID 凭证字 / FAccountBookID 账簿 / FBUSDATE 业务日期
  - 分录 FEntity：FEXPLANATION 摘要 / FACCOUNTID 科目 / FDC 借贷方向 / FDEBIT 借方 / FCREDIT 贷方 / FCURRENCYID 币别(PRE001) / FEXCHANGERATETYPE(HLTX01_SYS) / FDetailID 核算维度（客户/供应商/部门等）
- **我们已有的资产几乎全部复用**：KingdeeSdkClient（save/excuteOperation 通用）、三态网关、对手方解析、幂等状态机、连接测试按钮。新增开发 = 一个 `GlVoucherPayloadBuilder`（按科目映射规则把流水拆成借贷分录）+ 科目映射配置表，预估 1~2 天开发 + 联调。
- 附带收益：分录可带流水号摘要，FINFLOW 侧天然留存「流水↔凭证」血缘（我们的原始报文留存架构直接覆盖凭证推送）。

### 路径 C：付 2 万给金蝶实施
- 买到的是「字段校准 + 模板/凭证配置」。字段校准我们已完成且验证过；凭证配置的真实瓶颈是**会计口径（借什么科目/贷什么科目），这必须由我们财务拍板，金蝶实施代做不了**。
- 结论：**2 万买的东西里，技术部分我们已具备且大部分已完成**。

## 四、可行性结论

**结论：可以自主开发，且推荐路径 B。**

1. 「不懂金蝶没法整」对普通客户成立，对我们不成立——对接难度集中在字段与鉴权，我们 9/4 起已逆向文档 98 篇 + 演示环境全链路实证 + 真实账套 T0 全绿。
2. 真正的专业瓶颈是**会计分录口径**（收款单 → 借 银行存款 1002.xx / 贷 应收账款 1122.xx 之类），这是财务专业决策不是金蝶技术黑盒；技术侧做成可配置映射表（按结算方式/往来类型定科目），由财务逐条确认即可。
3. 建议对金蝶方：**暂缓 2 万部署费决策**，先让我把路径 B 的凭证推送打通（测试凭证建→立即删，不留痕），有实物再对比报价。

## 七、风险提示

- 直接写总账凭证 = 绕过业务单据→凭证的标准关联（智能会计平台未购买，本账套本来也没有这条链），凭证与收付款单的关联溯源由 FINFLOW 血缘字段承担，报表口径无影响（总账只认凭证）。
- 凭证是法律效力最强的会计数据，推送逻辑上线初期建议 auto-audit 保持关闭，凭证由财务在金蝶里复核后再审核，与现有 T8 拍板一致。
