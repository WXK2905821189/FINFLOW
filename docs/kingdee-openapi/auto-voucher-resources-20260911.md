## 1. 业务类型 → 科目规则表（核心输入）

### 是什么
把公司常见的银行流水分成若干「业务类型」，每种类型指定做账时用的**借方科目、贷方科目**，以及要带的辅助信息。

### 为什么
系统生成凭证时按这张表「对号入座」。这张表覆盖得越全，自动化比例越高；没覆盖的流水才需要人工判断。**这张表本身就是公司做账口径的固化，只能由财务定，技术侧无法代定。**

### 给什么格式（模板，直接在 Excel 里填）

| 业务类型 | 识别关键词/对手方 | 借方科目（编码+名称） | 贷方科目（编码+名称） | 辅助维度 | 备注 |
|---|---|---|---|---|---|
| 客户回款-会员收入 | 摘要含「会员」「充值」 | 1002 银行存款 | 6001.01 主营业务收入_会员收入 | 客户、项目 | 收入类 |
| 收支付宝提现 | 对手方=支付宝(中国) | 1002 银行存款 | 2202.01 应付账款_外部往来 | 供应商 | 结清往来 |
| 付服务器费 | 摘要含「阿里云」「腾讯云」 | 6602.02.07.02 管理费用_办公费_云服务 | 1002 银行存款 | 部门 | 费用类 |
| 代发工资 | 摘要含「代发工资」 | 6602.01.01 管理费用_人力成本_工资 | 1002 银行存款 | 部门 | 实务中工资经 2211 过账，按财务习惯定 |
| 缴社保公积金 | 摘要含「社保」「公积金」 | 6602.01.02/03 管理费用_人力成本_社保/公积金 | 1002 银行存款 | 部门 | |
| 缴税 | 对手方=税务局 | 2221 应交税费 | 1002 银行存款 | 无 | |
| 付房租 | 对手方=房东/物业 | 6602.02.01 管理费用_行政费用_房租 | 1002 银行存款 | 部门 | |
| 手续费 | 摘要含「手续费」「年费」 | 6603 财务费用 | 1002 银行存款 | 无 | |

> 上表「识别关键词」「科目示例」是技术侧按贵科目表拟的**示意**，请财务逐行修正为真实口径，并补充遗漏的业务类型（建议先列 10~20 个最常见的）。
> 收入类科目的客户/项目维度怎么取（对手方即客户？还是有别的对照表？）请在备注列说明。

## 2. 历史流水摘要样例（注意：不是金蝶凭证）

### 是什么
**银行流水记录里的「摘要 / 用途 / 附言」字段的真实文字样例**，即网银流水里能看到的那段描述文字。例如：

```
对手方名称                    摘要/附言                    金额        方向
支付宝(中国)网络技术有限公司    货款                          12,345.00   收
财付通支付科技有限公司         平台服务费                     3,200.00    付
北京市海淀区税务局             税款缴纳                       8,765.00    付
```

### 为什么
系统识别业务类型靠的就是这段文字（加上对手方名称）。需要看**真实摘要长什么样、写法有多不规范**，才能设计匹配规则和给 AI 的提示词。样例越真实，自动化准确率越高。

### 给什么格式
- 最好：从网银导出一份**近 1~3 个月的流水 Excel**（含摘要列、对手方列），发我即可，**不需要调凭证、不影响账**；
- 也可：直接截图几屏有代表性的流水。

### 那金蝶的历史凭证有用吗？
**有，但属于可选加分项**：如果金蝶里存有过去手工录的凭证，导出几条例子（摘要写法 + 借贷科目怎么挂），相当于告诉我们「财务手工做账的标准答案」，能帮我们校准科目选择习惯。没有也不影响开工，规则表（第 1 项）才是主输入。

## 3. 银行账户映射（每账户一行）

### 是什么
FINFLOW 系统里的每个银行账户 ↔ 金蝶「银行账号」核算维度（CN_BANKACNT）里的账户编码，一一对应。因为贵科目表里 **1002 银行存款强制要求「银行账号」维度**（金蝶实测验证过，缺了会被拒），所以每一笔流水的凭证必须带这个信息。

### 给什么格式

| FINFLOW 银行账户（名称/后四位） | 金蝶 CN_BANKACNT 编码 | 金蝶账户名称 |
|---|---|---|
| 招行 1234 | 11050160520009100036 | （银行账户全名） |
| 中信 5678 | 8110701012302119845 | |
| （测试账户） | 11050160520009100036（暂用默认） | |

> 测试阶段给一个默认映射即可跑通；真实联通后逐账户补全。金蝶里现有账户编码技术侧可以自行查询，只需财务确认「哪个 FINFLOW 账户对应金蝶哪个账户」。

## 4. 两个口径拍板（选择题）

### 4.1 费用科目的「部门/项目」维度怎么带？
费用类科目（管理费用/销售费用等）强制要求部门维度，部分还要求项目。可选：
- **A（推荐起步）**：先统一挂一个默认部门，财务月底在金蝶里调整；
- **B**：FINFLOW 制证页面上逐笔手选部门/项目；
- **C**：按对手方/摘要关键词自动匹配部门（需要给一份「关键词→部门」对照，维护成本高）。

### 4.2 审批放在哪一环？
- **推荐流程**：FINFLOW 复核流水（现有环节）→ 系统生成凭证草稿推入金蝶 → **财务在金蝶里审核生效**（审批权仍在财务手里，金蝶侧流程零改动）；
- 备选：财务先在 FINFLOW 页面确认科目再推金蝶。
请确认用推荐流程，或指定调整。

## 交付方式与节奏

1. 财务把第 1、2 项（规则表 + 流水样例）发给王小棵转技术侧；
2. 技术侧 3~5 天完成一期开发：424 个科目导入系统做搜索选择、AI 按规则表预填科目、人工确认后推金蝶生成草稿凭证；
3. 财务在金蝶审核几张实际凭证，反馈口径偏差，技术侧修正规则表；
4. 跑顺后再评估「高置信度流水免确认自动推」的二期能力。
