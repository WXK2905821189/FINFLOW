## 一、规则数据模型（kingdee_voucher_rule 表，实装时建）

| 字段 | 说明 |
|---|---|
| id / priority | 优先级：数值越小越先匹配。对手方精确规则 20 < 附言宽泛兜底（对公收入）30 |
| scope | 适用范围：orgs（FINFLOW companyId，来自流水所属公司）+ bankChannels（CITIC/CMB/空=全部） |
| business_type / category | 业务类型、类别（费用类/往来类/五险一金/薪资/收入类…，用于页面分组展示） |
| match_conditions JSON | 条件数组，field ∈ {SUMMARY, COUNTERPARTY_NAME}，op ∈ {CONTAINS, CONTAINS_ANY, IN_ORG_LIST, EMPLOYEE_NAME}，logic=ALL/ANY |
| direction | EXPENSE / INCOME / ANY（资金方向预过滤） |
| amount_min / amount_max | 金额区间（社保 vs 个税的同附言区分，阈值待财务给） |
| debit_lines / credit_lines JSON | 分录模板：account+name+dimension+share，见下 |
| extra_voucher JSON | 「直接确认费用」第二张凭证模板（规则 1、14） |
| enabled / remark | 启用开关、原文备注 |

### 分录的 dimension（辅助维度来源，8 种）

| 来源 | 解析方式 |
|---|---|
| BANK_ACCOUNT | 流水所属 FINFLOW 账户 → CN_BANKACNT 编码（**账户映射表**，当前全局占位待逐账户化，对应 pending-fixes 挂起项） |
| ORG | 流水所属主体 → 组织编码 |
| SUPPLIER / CUSTOMER / COUNTERPARTY | 对手方自动建档 FNumber（已有能力，客户类别 KHLB001_SYS 实测一致） |
| EMPLOYEE | 对手方个人姓名或人工选择（金蝶员工基础资料，需核对该维度槽位字段） |
| FIXED | 固定值（部门=综合管理部、项目=即时行乐/wegic/图虫） |
| BY_SUMMARY_BRANCH | 按摘要分支选供应商（规则 18 腾讯云：图虫账号/即时账号） |
| NONE | 无维度 |

### 分录金额分摊 share

| 策略 | 用途 |
|---|---|
| FULL | 单科目全额（绝大多数规则） |
| EQUAL | 均分（规则 12 公积金两科目） |
| MANUAL | 推送确认页人工逐科目填金额（规则 10 社保 8 借方科目，按上月工资表） |

## 二、匹配算法

1. **预过滤**：流水 direction（收支）+ 所属主体 + 账户渠道 过滤 scope 不符的规则。
2. **条件求值**：SUMMARY 用流水的摘要/附言字段（多来源字段合并匹配），COUNTERPARTY_NAME 用对手方户名；EMPLOYEE_NAME = 对手方为个人姓名（金蝶员工档案/历史报销对手方库匹配）。
3. **优先级排序**：priority 升序；同优先级多条命中 → **不自动定案，全部进人工确认队列**（AI 预填多候选）。
4. **金额门**：同附言冲突对（社保/个税）在财务给阈值前强制人工确认。
5. **未命中**：进 AI 兜底推荐（已有设计：科目列表 424 个 + 摘要推荐 + 置信度），人工确认后可顺手固化为新规则。
6. **主体简称映射**（seed 内置，2026-09-16 实查核实）：即设=300、雪云=400、海南=900、长沙=710、广州=720；渠道 CITIC/CMB。

## 三、分录生成与推送链路对接

```
APPROVED 流水 → 规则解析（命中 1 条且无需人工 → 预填；多条/含 MANUAL/未命中 → 确认队列）
  → 确认页展示：借贷科目+维度+金额（可改） → 生成 GL_VOUCHER payload（借贷合计校验）
  → [可选] extra_voucher 同时生成第二张费用确认凭证（同摘要，先往来凭证后费用凭证，顺序固定）
  → Save（草稿）→ 回写 voucher_no；不自动 Submit/Audit（T8 拍板维持关闭）
```

- 1002 银行存款科目强制带「银行账号」维度（2026-09-11 实测报错验证过）——来自 BANK_ACCOUNT 映射，规则模板已内置。
- 1002.02 利息收入这类**收入方向银行科目**若未来出现在贷方，同样带银行维度。
- 借贷不平/科目不存在 → 推送失败回 FAILED + message（复用现有状态机，不改 pushVoucher 接口）。
