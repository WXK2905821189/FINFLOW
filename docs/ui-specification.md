# 企业级财务管理平台 UI/UX 规范

> 版本：v1.0
>
> 适用范围：登录、注册、仪表盘、用户管理、自动入账、连接与运营、银行数据查询及 403 无权访问页面。
>
> 当前仓库未提供可读取的源码、路由或依赖清单，本文先定义可直接落地的产品基线；接入实现时应将其中的路由别名、权限编码和接口字段映射到实际项目。

## 1. 设计目标与原则

- **准确优先**：金额、币种、收付款方、交易状态和时间必须有明确层级，避免仅靠颜色传达含义。
- **低风险操作**：删除用户、修改权限、导入、复核和制证等高风险行为采用二次确认，并在确认步骤再次展示关键字段。
- **高密度但可扫描**：桌面端面向财务、运营和管理员的重复工作，减少装饰性容器，保持固定的对齐线和稳定的表格列宽。
- **状态完整**：每个页面至少覆盖加载、空数据、错误、无权限和成功反馈；提交过程必须防重复提交。
- **权限可解释**：用户只能看到有权访问的导航和操作；当用户通过链接访问无权资源时，明确说明原因并提供返回入口。
- **可审计**：影响资金或权限的操作都展示操作者、时间、对象和结果；交易记录支持追溯原始详情。

## 3. 桌面端总体布局

### 3.1 画布与区域

- 设计基准：`1440 × 900`；最低支持宽度：`1024px`。
- 左侧主导航固定宽度 `232px`，右侧主区域自适应；导航宽度不随内容变化。
- 顶部栏高度 `64px`，包含面包屑/页面标题区域、全局搜索（可选）、通知、帮助和用户菜单。
- 主内容区域使用 `24px` 外边距，内容最大宽度建议 `1440px`；表格类页面允许占满可用宽度。
- 页面背景使用中性浅灰，内容区以无边框分区、轻边框表格和少量白色工具面板建立层次，避免卡片套卡片。
- 重要内容从左上向右下排列：页面标题与主操作、筛选/摘要、数据主体、分页或次要说明。

### 3.2 导航

- 一级导航顺序固定为：仪表盘、自动入账、连接与运营、系统管理。主动转账/支付不属于当前版本，因此不创建资金操作导航组；分组标题只承担展开/收起，不触发默认页面跳转。
- 当前页面使用左侧高亮条和浅色背景，同时保留文字对比度；子菜单展开状态在加载、刷新和窗口缩放时不变化，并持久化用户最近一次展开状态。
- 导航项仅在用户至少拥有该页面的 `view` 权限时显示。父级分组无可见子项时整体隐藏。
- “连接与运营”是银行连接配置、运行可观测性和银行侧数据查询的独立域，不混用资金管理的主动转账/调拨或自动入账的导入、复核、制证流程；三域只复用工作台壳层、会话/RBAC、审计呈现、账户主数据、脱敏与金额时间格式。
- 2026-09 一期不启用真实银行直联，不接入银行 SDK/API、生产密钥或真实数据。该分组的所有页面在标题下方或结果区持续显示“真实银行直联未启用，一期仅提供配置、模拟与运营验证”；模拟或样例结果必须明确标识“模拟数据”。
- 个人菜单包含：个人资料、退出登录。退出前不需要确认，但应清除本地会话并返回登录页。
- 面包屑仅用于两级以上层级，例如“自动入账 / 人工复核”；首页不重复显示“仪表盘”。

### 3.3 通用交互

- 主操作按钮放在标题行右侧；页面只有一个主操作，其他动作用次按钮或文字按钮承载。
- 所有表单支持键盘操作，Tab 顺序与视觉顺序一致；Enter 仅在不会误触高风险提交时触发提交。
- 异步操作按钮进入 loading，提交成功使用顶部/局部成功提示；服务端错误在表单顶部给出摘要，并在字段旁保留具体错误。
- 金额统一右对齐，使用人民币（CNY）和两位小数、千分位格式化；不可用数据使用“--”，不使用 `0` 混淆。
- 时间默认显示本地时区，详情中提供完整时间和时区；状态同时显示文字和颜色/图标。

## 4. 导航与权限可见性

### 4.1 权限模型映射

建议采用 `资源:动作` 的粒度：`dashboard:view`、`user:manage`、`account:view`、`account:manage`、`statement:view`、`statement:review`、`posting:confirm`、`reconciliation:view`。主动转账、付款、调拨、支付审批和支付执行不属于当前版本，不在导航、路由、前端 API 或正式验收中出现；后端历史接口默认关闭并单独隔离。前端只负责展示和交互限制，服务端必须对每次请求重新鉴权。

| UI 元素 | 可见条件 | 不满足时的处理 |
| --- | --- | --- |
| 仪表盘导航 | `dashboard:view` | 隐藏；本期所有已激活企业角色均可见 |
| 用户管理导航 | `user:manage` | 隐藏；非系统管理员直接访问进入 403 |
| 新建/邀请用户 | `user:manage` | 隐藏，不能只置灰 |
| 编辑角色、启停、重发邀请 | `user:manage` | 隐藏；列表仍可展示允许查看的信息 |
| 主动转账、付款、调拨、审批和执行 | 不提供 | 不展示导航或操作入口；后端默认返回“当前版本不在产品范围” |
| 银行侧支付记录查询 | `bankdata:payment:view` | 仅只读展示银行历史数据；不得生成支付指令或进入支付流程 |

连接与运营的查看权限与写入/操作权限分离。有查看无操作权限时仅展示只读内容，不以置灰伪装可操作功能；无查看权限时隐藏导航，深链接进入 403，服务端对每次资源与操作请求重新鉴权。

银行数据查询权限细分为 `bankdata:balance:view`、`bankdata:statement:view`、`bankdata:receipt:view`、`bankdata:reconciliation:view`、`bankdata:payment:view` 与 `bankdata:payroll:view`。手动同步另需 `bankdata:sync:trigger`，且只能针对当前企业内已授权账户和范围创建服务端任务。

| UI 元素/动作 | 可见条件 | 不满足时的处理 |
| --- | --- | --- |
| 连接与运营分组 | 至少拥有任一连接、运营或数据查询查看权限 | 无可见子项则整体隐藏 |
| 新建、停用、轮换应用凭据 | `connection:manage` | 隐藏；密钥仅生成瞬间显示一次 |
| 查看签约关系 | `connection:view` | 隐藏；无权深链接为 403 |
| 发起/确认模拟签约变更 | `connection:manage` | 隐藏；一期不得发起真实签约 |
| 编辑个性化设置 | `connection:manage` | 仅查看设置摘要，不显示保存操作 |
| 查看直联状态、健康汇总 | `operation:monitor` | 隐藏 |
| 触发银行数据手动同步 | `bankdata:sync:trigger` + 对应账户/企业授权 | 仅在任务页或对应数据查询页显示；无权限保持纯只读，不显示伪操作 |
| 手动重试模拟任务 | 后续独立重试权限 | 隐藏；确认前展示对象、影响与模拟标签 |
| 查看任务执行明细 | `operation:monitor` 或 `bankdata:view` | 隐藏 |
| 查看运行/审计日志 | `operation:log:view` | 隐藏；结果仍按数据范围脱敏 |
| 各银行数据查询页面 | 对应 `bankdata:*:view` | 单页隐藏；深链接进入 403 |

权限加载中时，不要短暂显示可能被撤销的菜单或操作；使用导航骨架屏或保守隐藏。权限变更后刷新会话权限缓存，正在进行的高风险操作在服务端再次校验并给出明确失败原因。

## 5. 页面规范与状态

### 5.1 登录

**布局**：桌面端为居中的窄表单区，品牌标识、标题、邮箱/用户名、密码、记住登录、登录按钮、忘记密码和注册入口纵向排列。登录页不显示业务导航，背景保持简洁，避免影响表单聚焦。

**状态**：

- 初始：账号输入框自动聚焦；密码支持显示/隐藏，图标按钮需有 tooltip 和无障碍名称。
- 校验：账号格式、密码必填在字段下方即时提示；不要在用户尚未离开字段前显示服务端错误。
- 提交中：登录按钮 loading 且不可重复点击；保留输入内容。
- 失败：表单顶部显示“账号或密码不正确”等不泄露账号是否存在的提示；连续失败可展示服务端返回的验证挑战。
- 成功：清除错误并进入目标页面；若会话过期则回到登录并提示“登录已过期，请重新登录”。

### 5.2 注册

字段为姓名、工作邮箱、密码和确认密码。自助注册只创建待激活账号，不关联企业、不授予角色，也不能查看财务数据；管理员后续通过用户管理邀请或激活企业成员。密码规则为至少 8 位且同时包含字母和数字，规则在输入时可见，使用强度指示器但不只依赖颜色。

- 初始：清楚说明必填字段和密码要求，条款链接在同页打开或新标签打开。
- 校验：确认密码实时比较；工作邮箱重复由服务端返回字段级错误。
- 提交中：按钮 loading，防止重复注册。
- 成功：展示“注册完成，等待管理员激活”状态和返回登录入口，不自动把未激活账户当作已登录。
- 失败：保留可复用字段，清空并保护密码字段；网络错误允许重试。
- 其他认证：登录页提供忘记密码入口；重置成功后既有会话失效。若企业关闭注册，访问 `/register` 显示说明页并提供返回登录按钮，而不是空白或 404。

### 5.3 仪表盘

**目标**：让用户在一个视图内确认现金/账户概况、近期风险和待处理事项。

首屏结构建议：页面标题；账户余额、采集任务、待复核流水、入账失败、对账差异和结账进度等摘要指标；各银行账户列表（名称、账号掩码、余额、最后同步时间）；近 6 个自然月收入/支出/净现金流趋势；最近标准化流水和最近同步任务。当前版本不展示待审批转账或支付执行指标。

- 加载：摘要区使用稳定尺寸骨架屏，图表区域不因数据返回而跳动。
- 有数据：摘要指标支持点击进入对应标准化流水、同步任务或对账详情；图表提供 tooltip、图例和无障碍数据摘要。所有金额均为人民币，保留两位小数并使用千分位。
- 空数据：未获取的金额显示 `--`，列表显示对应空状态；趋势区域显示“暂无足够数据”，不伪造趋势，也不提供主动转账入口。
- 部分失败：失败模块独立显示重试按钮，其他模块仍可用。
- 权限降级：仅渲染用户有权查看的指标和模块；无可见模块时跳转首个可访问页面。

### 5.4 用户管理

**工具栏**：页面标题、新建用户按钮（若有权限）、搜索框、状态/角色筛选、重置筛选。筛选条件应可回填到 URL，便于刷新和分享。

**表格列**：姓名、邮箱、角色、状态、最近登录、创建时间、操作。操作列使用紧凑的图标或文字按钮，包含查看；编辑角色、启用/停用、重发激活邀请按权限显示。邮箱作为身份标识不可直接修改，敏感字段默认脱敏。

- 加载：表头和行使用骨架，不让分页器位置跳动。
- 空数据：区分“尚无用户”和“当前筛选无结果”；前者显示新建入口，后者显示清除筛选。
- 失败：在表格区域展示重试，不覆盖筛选条件。
- 新建/编辑：使用抽屉或宽度约 `520px` 的侧面表单；关闭时若有未保存变更先确认。
- 停用：确认弹窗展示用户邮箱、影响范围，以及是否存在未完成草稿/待审批任务的风险提示；唯一启用系统管理员不可停用。完成后刷新该行并保留当前页。
- 生命周期：管理员创建/邀请的成员在激活并获分配角色前不可访问企业数据；停用账号后旧会话在下一次鉴权时失效。
- 分页：服务端分页，显示总数；停用最后一条时回退到上一页，不提供物理删除。

### 5.5 标准化流水查询

**筛选区**：时间范围、交易类型、状态、银行账户、收付款方/交易编号搜索；提供重置和查询。默认时间范围为最近 30 天，避免首次加载全量数据。

**表格**：流水编号、交易日期、类型（收入/支出/调整）、银行账户、摘要、对方信息、金额、状态、来源、同步任务号和创建时间。金额按收入/支出做方向标识，但同时显示文字；状态使用统一标签。该页面只读，不提供支付、转账、审批或执行操作。

- 加载：保持列宽稳定；服务端查询期间禁用重复查询但允许取消（若接口支持）。
- 空数据：默认范围无数据时提示扩大时间范围；有筛选时提供清除筛选。
- 详情：点击行或详情按钮打开抽屉，展示完整流水、状态变更时间线、备注和可复制交易编号；敏感信息按权限脱敏。
- 冲正：对已入账交易提供“创建冲正”入口（系统管理员、财务专员或财务经理）；以相反金额创建新记录并引用原交易编号，原记录不可修改，双方可相互跳转。本期不提供批量导出。
- 数据异常：金额、状态和时间缺失时标记为“数据异常”并提供联系管理员入口，不自行猜测补值。

### 5.7 自动入账（2026-09 一期）

#### 域边界与信息架构

自动入账是独立业务域，处理“外部资金流水采集、校验、人工复核、金蝶云星空模拟制证、对账和审计追溯”。主动转账、支付、调拨及其审批执行不属于当前版本；自动入账不得创建任何资金指令，或把导入流水展示为已支付交易。自动入账与连接与运营只复用工作台布局、会话/RBAC、账户主数据、审计记录及金额、时间格式。

当前版本不提供主动资金操作页面；自动入账作为独立分组提供以下页面：

```text
自动入账
├── 流水导入
├── 导入批次
├── 人工复核
├── 金蝶制证
└── 对账与追溯
```

建议路由与权限：`/auto-accounting/imports`（`statement:import`）、`/auto-accounting/batches`（`statement:view`）、`/auto-accounting/review`（`statement:review`）、`/auto-accounting/vouchers`（`voucher:push`）与 `/auto-accounting/reconciliation`（`reconciliation:view`）。页面均要求已登录；导航项只向拥有对应查看或动作权限的用户展示，分组无可访问页面时隐藏。真实银行 SDK/API 或直连采集不在本期，入口仅为规范化文件导入和受控模拟来源。

#### 桌面布局与核心对象

沿用 `232px` 侧栏、`64px` 顶栏、`24px` 内容边距。页面采用“顶部任务栏 + 可筛选数据表 + 详情抽屉”的高密度作业布局，不使用营销式卡片。批次号、流水号、凭证号使用等宽字体或稳定列宽且可复制；金额右对齐、人民币两位小数；账号和敏感对方信息必须脱敏。

导入批次包含原始文件或模拟来源及处理结果；批次产生标准流水；流水依次经历校验、复核与制证；制证记录关联金蝶模拟凭证号；对账关联流水、交易或账户余额快照。详情以只读时间线展示来源、操作者、时间、请求编号、前后状态与失败原因，形成审计追溯链。

#### 流水导入

页面标题为“导入流水”，主操作为“选择文件”；“运行模拟来源”放在次按钮或菜单中并明确标记为模拟，不能伪装成真实银行连接。表单包括来源类型、银行账户、文件、账期/日期范围（文件未包含时）和备注。上传区显示支持格式、最大大小和模板下载，并支持拖放和选择文件。

流程为“选择来源与文件 -> 字段预检 -> 提交处理 -> 批次结果”。预检只检查格式、必填列、编码、日期/金额格式与账户映射，不写入正式流水；确认后才创建批次。重复判定由服务端以来源、企业、银行账户、原始流水唯一标识/文件指纹和交易关键字段为准，前端只呈现结果。

- 初始：来源、账户和文件均有效前禁用导入；只列出当前用户可用且启用的账户。
- 上传/解析中：显示批次进度和可离开提示，不允许重复创建同一提交；后台完成后可在批次页继续查看。
- 预检失败：按文件级、列级、行级展示错误数量和样例；允许替换文件或下载错误行清单（一期接口提供时），不产生有效流水。
- 导入成功：展示批次号、总行数、有效/异常/重复行和批次详情入口。成功仅表示接收或落库，不表示复核完成或已制证。
- 完全重复：提示“未创建新流水”，展示原批次链接和去重依据摘要；不得再次生成流水、凭证或伪重复成功审计。
- 部分重复：分别显示新入库、重复跳过、异常待处理数量；重复行可筛选，不自动覆盖既有流水。
- 网络/服务失败：保留表单和本地文件名，展示请求编号与重试入口；结果以服务端幂等响应为准。

#### 导入批次与异常校验

“导入批次”默认按创建时间倒序，可按来源类型、账户、账期、处理状态、创建人、批次号筛选。表格列为批次号、来源、账户、文件/模拟任务、账期、总行数、有效、异常、重复、状态、创建时间、创建人和操作。详情抽屉含概览、流水、校验异常、审计四个页签。

校验分文件级、字段级和业务级。文件级问题阻断处理；字段级问题将流水标为异常；业务级至少覆盖缺失或非法流水号、日期、金额、方向、账户映射、重复流水与余额/对账关联异常。异常同时用文字、图标和颜色表达。批次页只用于查看、筛选、重新导入或进入复核，不能直接篡改已落库原始流水。

加载时表头、统计和行高保持稳定；空批次引导至导入；筛选为空可一键清除；查询失败保留筛选和上次结果并提供局部重试。处理中可轮询或手动刷新，状态不得通过刷新页面伪造完成。

#### 人工复核

“人工复核”是异常或待复核流水的工作队列，默认显示待复核，可按账户、来源、异常类型、金额区间、日期、批次和处理人筛选。列表保留流水日期、摘要/对方（脱敏）、方向、金额、账户、异常标签、批次号、制证状态与操作。

详情使用右侧抽屉：左侧显示原始/标准化字段与校验结果，右侧显示建议处理和操作审计；底部固定“通过复核”“驳回”“标记需补充”。通过前要求确认账务归类或规则匹配；驳回和需补充必须填写原因。若流水已被他人处理，返回“状态已变化”，关闭操作并刷新详情，禁止覆盖。

拥有 `statement:review` 才能处理队列；仅有 `statement:view` 可只读查看状态与详情；无权入口隐藏，深链接进入 403。复核人、时间、意见与前后状态写入时间线，复核后原始字段不可编辑。支持批量复核时，先展示选中数量、异常类型分布和不可处理项；确认后逐条由服务端校验并返回明细，禁止静默全量通过。

#### 金蝶制证状态

“金蝶制证”只展示已复核且可制证的流水及推送记录。金蝶为一期模拟适配器，所有结果必须标注“模拟制证”，不得声称已连接生产金蝶。列包括流水号、业务日期、账户、借贷方向、金额、复核状态、凭证状态、模拟凭证号、最近推送时间、操作人与操作。

凭证状态统一为待制证、推送中、制证成功、制证失败、需人工处理。仅 `voucher:push` 可见“推送模拟制证”或重试；其他用户只读。推送确认框展示流水数、金额合计、目标账期和模拟标签；推送中禁用重复点击，并按服务端幂等键保证同一流水不重复制证。

成功后展示可复制的模拟凭证号、时间和关联流水；失败展示安全的错误摘要、请求编号与重试条件，不泄露金蝶凭据或堆栈。成功流水不得再次推送；更正走新的冲正/更正流程并保留双向追溯，不能覆盖历史制证记录。

#### 对账与追溯

“对账与追溯”核对账户、流水、入账结果和模拟凭证的一致性。顶部展示选定账户和账期的导入总笔数、已复核、待处理、已制证、异常/差异笔数与差异金额；指标只做导航，不能以零值掩盖加载或失败。

表格列为业务日期、流水号、账户、方向、金额、批次号、复核状态、凭证状态、模拟凭证号、对账状态和操作。点击引用进入同一流水追溯抽屉，按时间线展示原始来源、导入批次、校验、复核、制证、交易/账户关联和审计事件。对账差异可标记待处理或分派（一期后端支持时），但不得直接调整余额；修正必须新增更正/冲正记录并保留关联。

`reconciliation:view` 可查看汇总和追溯；复核、制证、再导入仍按各自权限判断，不得以查看权限提升写入能力。空状态区分“账期尚未导入流水”和“当前筛选无差异”；失败时保留筛选并提供局部重试。跨账户、跨企业或无权引用使用 403/安全空结果，不泄露对象存在性。

#### 自动入账权限矩阵

| UI 元素/动作 | 权限 | 不满足时处理 |
| --- | --- | --- |
| 自动入账导航及批次/流水只读查看 | `statement:view` | 隐藏；深链接进入 403 |
| 选择文件、提交导入、运行模拟来源、重新导入 | `statement:import` | 隐藏；接口仍须鉴权 |

所有页面遵循既有会话过期、权限撤销和 403 规则。权限加载中采用骨架或保守隐藏，不能短暂露出制证、复核、导入等高风险动作。批次、流水、复核、制证和对账详情至少展示操作者、时间、对象、动作、结果和请求编号。

### 5.8 连接与运营（2026-09 一期）

#### 通用布局、边界与状态

所有子页面采用桌面优先的 `24px` 内容边距和“标题 + 主操作 + 持续边界 Alert + 紧凑筛选区 + 服务端表格 + 右侧详情抽屉”结构。详情由行点击或查看图标触发，包含概览、关联对象、状态时间线/审计，支持复制长编号；关闭后焦点回到触发元素，筛选、分页和滚动位置保持不变。

每页均持续显示“真实银行直联未启用，一期仅提供配置、模拟与运营验证”。2026-09 不接 SDK/API、生产密钥或真实银行数据；模拟/样例一律标为“模拟数据”，不得以真实银行成功状态或数据呈现。加载使用稳定骨架和行高；空态明确区分“未启用真实直联”“当前筛选无数据”“尚无模拟配置”；失败保留筛选和上次成功数据，展示安全错误摘要、请求编号和局部重试。会话过期、撤权或资源无权继续复用登录跳转和 403，且不泄露资源存在性。Alert、表格、抽屉和 toast 均不得泄露密钥、令牌、完整账号、原始敏感载荷或内部堆栈。

v0.2 银行数据底座归属“连接与运营 / 数据查询”，与自动入账保持独立；主动转账、支付、调拨及其审批执行不属于当前产品。自动入账负责文件/模拟来源导入、校验、复核、金蝶模拟制证和对账追溯；连接与运营只承载连接配置、任务可观测、日志审计和银行侧只读查询。前端只能消费 FINFLOW API 返回的企业、账户和角色过滤后的业务事实或查询投影，不直连银行 SDK/API，不展示或缓存原始报文、同步日志全文、银行专有字段、完整账号、凭据令牌/私钥、原始载荷和内部堆栈。数据查询页不得提供转账、支付、审批、执行、复核、制证、修改余额或重放银行请求动作，只能按权限跳转到自动入账的只读详情。

#### 直联管理

**应用管理**：表格列为应用名称、应用标识、环境、状态、最近轮换、最后使用、创建人和操作。仅 `connection:manage` 可见新建、停用和轮换；生成的密钥或令牌只在该瞬间展示一次，提供复制与“已保存”确认，绝不写入表格、日志、导出、审计详情或错误信息。停用/轮换需二次确认并展示受影响的模拟任务；环境和状态仅可标示“模拟/未启用”，不能声称已连通生产银行。

**签约管理**：表格列为签约主体、银行/模拟通道、产品能力、环境、签约状态、有效期、最后变更和操作。抽屉展示签约摘要、能力范围、变更记录和审计。真实直联未启用时，操作只可为“模拟签约变更”，确认弹窗再次说明不会向银行发送请求；状态统一为未配置、模拟待确认、模拟生效、已失效、异常，不伪造真实签约状态。

**个性化设置**：按通知与告警、默认查询范围、任务保留、数据掩码分段表单，显示当前生效值和上次更新时间。保存为局部提交；并发冲突提示“设置已被其他管理员更新”，提供刷新与比较。敏感设置只显示是否已配置，不回显具体值；无编辑权限用户只读。

#### 监控与日志

#### 飞书协同

页面分为“模拟连接配置”“接收对象与通知策略”“发送记录”三个作业区。标题下持续显示“真实飞书未启用，一期仅提供模拟协同验证”。企业管理员可创建模拟连接、接收对象和事件策略；有 `feishu:view` 无管理权限时仅查看脱敏配置和发送记录；`feishu:notify` 用户可发送受控模拟通知。所有发送结果展示事件编号、请求编号、状态和模拟消息号，不展示任何凭据或原始请求。

通知发送按“填写安全摘要 -> 确认事件与接收对象 -> 创建 FINFLOW 事件 -> 查看发送结果”执行。成功表示模拟发送记录已创建，不表示真实飞书送达；相同企业、相同 `event_id` 的重试复用已有事件和投递记录，不创建重复消息。失败记录保留安全错误摘要和请求编号，后续重试必须由服务端判断可重试性并写入审计时间线。

发送记录表格列为事件类型、风险级别、业务引用、状态、尝试次数、请求编号、模拟消息号和时间；详情抽屉包含事件概览、接收对象、状态时间线和审计。空态区分“尚未配置模拟接收对象”和“尚无发送记录”，失败保留筛选并支持局部重试。飞书消息中的链接始终回到 FINFLOW，经会话和权限校验后才能访问。

**直联状态监控**：顶部显示模拟通道健康、最近模拟任务结果、延迟/失败趋势和待处理告警数量。指标加载采用固定尺寸骨架，失败模块独立重试；未启用时状态为“未启用”而非“正常”，状态同时使用文字、图标和颜色，所有模拟来源恒带模拟标签。列表可按通道、环境、状态和时间筛选。

**任务执行**：任务队列覆盖导入、模拟拉取、模拟签约验证、模拟制证等后台作业，列为任务编号、类型、关联对象、发起方式、状态、进度、开始/结束时间、耗时、重试次数和操作。详情抽屉显示脱敏参数、分阶段时间线、结果、可公开错误摘要、请求编号和审计。状态至少有排队中、执行中、成功、失败、已取消、需人工处理；仅 `connection:task:retry` 可重试，服务端以幂等规则保证不创建重复业务记录，成功任务没有可覆盖结果的重试入口。

**日志查询**：提供时间范围、模块、事件类型、关联编号、操作者、结果和请求编号的组合筛选，默认最近 24 小时，使用服务端分页。列表和详情不得显示密钥、会话令牌、完整银行/收款账号、原始文件内容或堆栈，只展示脱敏上下文和可公开错误摘要。空态说明当前范围无记录；失败保留筛选、显示请求编号并局部重试；日志不得由前端修改或删除。

#### 银行数据同步任务（v0.2）

银行数据同步任务挂在“监控与日志 / 任务执行”和六类数据查询页的受控入口中，使用同一服务端任务、幂等和审计模型。`operation:monitor` 或 `bankdata:view` 可查看任务计划和执行详情；`bankdata:sync:trigger` 仅允许用户在任务页或对应银行数据查询页选择企业内授权账户与时间范围后创建服务端同步任务；后续独立重试权限只在服务端标记为可重试的失败任务上显示。拥有查看权限但无触发/重试权限时页面保持纯只读，不放置置灰按钮制造可操作预期。

定时计划只读展示计划名称、掩码账户/连接范围、频率、上次开始/结束/结果、下次运行时间、最近任务号和请求号。浏览器打开、刷新、恢复页面或轮询状态都不得触发银行同步；同步只能由服务端计划或授权用户显式确认创建任务。

手动同步流程为“选择账户与时间范围 -> 确认影响范围和去重说明 -> 创建 FINFLOW 同步任务 -> 查看任务状态”。确认弹窗展示掩码账户、日期范围、任务类型、去重规则摘要和“数据由 FINFLOW 服务端同步”的提示。创建成功仅提示“同步任务已创建”，展示任务号和请求号，不声称数据已更新；若命中幂等任务，提示“已复用已有同步任务”并展示既有任务号、状态和请求号。离开页面不取消后台任务，返回后通过任务号或筛选继续查看。

任务列表列为任务号、类型、账户范围、触发方式（定时/手动）、状态、进度、开始时间、结束时间、耗时、处理数、重复数、异常数、请求号和操作。状态至少包含已创建/排队中、执行中、成功、部分成功、失败、已取消、需人工处理；成功和部分成功任务不显示可覆盖结果的重试入口。详情抽屉包含概览、脱敏参数、阶段时间线、安全错误摘要、关联结果、审计记录和受控追溯摘要；受控追溯只呈现来源、任务、时间、请求编号、标准化状态和 30 天保留状态，不提供原始报文预览、下载或复制。

#### 数据查询

余额、流水、回单、对账单、支付记录和代发共用“账户 + 时间范围 + 状态/关键字”的紧凑查询区。余额展示当前快照，其余五类默认最近 30 天；只有用户点击“查询”或从已确认的 URL 筛选条件恢复页面时才请求服务端，不在首次进入时拉取全量数据。筛选按 AND 组合，使用服务端分页和稳定默认排序；结果区展示数据来源、最后同步时间、关联任务号和请求号。长编号可复制，金额右对齐并按 CNY 两位小数显示，账号、对方、收款人和摘要按权限脱敏。

查询 loading 时保留筛选和上次成功结果，只替换表格骨架或局部状态；空态区分“未配置/未启用真实直联”“暂无同步运行记录”和“当前筛选无数据”；失败保留筛选和上次数据，展示安全错误摘要、请求号和局部重试。403 不显示企业、账户或对象是否存在。详情抽屉包含概览、关联对象、时间线/审计和受控追溯摘要，关闭后保持筛选、分页、滚动和焦点。模拟数据必须始终带“模拟数据”标签，不能与真实结果混排；无真实结果时显示“未配置”“未启用”或“暂无运行记录”，不得用“正常”“成功”或 `0.00` 代替。

六类只读查询页面的字段和限制如下：

| 页面 | 列表关键字段 | 详情与限制 |
| --- | --- | --- |
| 余额 | 账户、掩码账号、可用余额、账面余额、币种、更新时间、来源 | 未启用时金额为 `--`、状态为“未获取”，不能显示 `0.00`；不提供修改余额或立即拉取银行余额动作 |
| 流水 | 流水号、交易日期、脱敏摘要/对方、方向、金额、账户、来源、状态 | 可展示自动入账或交易引用、去重摘要和任务时间线；只能查看引用，不能复核、制证或改写归属 |
| 回单 | 回单编号、关联支付/流水、日期、金额、状态、来源 | 仅当后端提供受控文件时显示预览/下载，下载必须审计；没有文件时不放置无效按钮 |
| 对账单 | 账期、账户、期初余额、期末余额、收入、支出、差异、来源 | 差异只跳转自动入账或资金管理只读详情，不能直接调整余额或改写对账结果 |
| 支付记录 | 银行侧历史支付编号、业务日期、脱敏收款方、金额、方式、状态、来源 | 仅只读查询银行侧历史记录；可展示异步回执阶段，但不创建、审批、执行、撤销或关联 FINFLOW 主动支付对象；受理超时或未知不得称为成功 |
| 代发 | 批次号、类型、笔数、金额合计、账期、状态、来源 | 收款人明细按权限脱敏；无真实来源时展示未启用或模拟空态，不提供代发提交、复核或银行请求重放 |

### 5.9 403 无权访问

页面保持应用壳层（顶部栏和可见导航），主区域居中展示 403、标题“暂无访问权限”、简短原因和返回上一页/返回仪表盘按钮。不要显示不存在的资源详情、企业信息或泄露权限判断细节；接口响应同样不得暴露资源是否存在。

- 直接访问无权路由：记录必要的目标路径用于诊断，但不把敏感 query 参数回显给用户。
- 会话有效但权限已被撤销：提示“你的权限可能已发生变化”，提供刷新权限/重新登录入口。
- 用户没有仪表盘权限：返回按钮应指向第一个可访问页面，而不是继续跳转 403。
- 无法判断权限（权限服务错误）：使用通用错误页或重试，不误报为 403。

## 6. Ant Design 主题建议

以下 token 以 Ant Design v5 为基线，最终应通过 `ConfigProvider` 统一注入，禁止页面内零散覆盖组件样式。

```ts
const theme = {
  token: {
    colorPrimary: '#1677FF',
    colorSuccess: '#389E0D',
    colorWarning: '#D48806',
    colorError: '#CF1322',
    colorInfo: '#1677FF',
    colorText: '#1F1F1F',
    colorTextSecondary: '#595959',
    colorTextTertiary: '#8C8C8C',
    colorBgLayout: '#F5F7FA',
    colorBgContainer: '#FFFFFF',
    colorBorder: '#D9D9D9',
    borderRadius: 4,
    controlHeight: 36,
    fontSize: 14,
    lineHeight: 1.5714,
  },
};
```

- **色彩语义**：蓝色用于查询、主行动和链接，绿色用于成功/入账，红色用于失败/异常，橙色用于待处理；状态标签必须带文字。银行受理、未知或待对账状态不得使用“成功”语义。
- **字阶**：页面标题 `24px/32px`，区块标题 `16px/24px`，正文 `14px/22px`，辅助文字 `12px/20px`。不使用负字间距，不按视口宽度缩放字号。
- **间距**：以 `8px` 为基础单位，常用间距 `8/12/16/24/32px`；表格单元格上下内边距建议 `12px`。
- **按钮**：主按钮仅用于当前页面最重要动作；危险动作使用 `danger`，图标按钮配合 tooltip 和 aria-label。熟悉的撤销、刷新、查看、复制等操作优先使用图标按钮。
- **表单**：标签置于控件上方，错误信息紧贴字段；金额输入使用 `InputNumber` 或等效数值控件并明确精度，禁止以字符串拼接处理金额。
- **表格**：使用 `Table` 的服务端分页、排序和筛选能力；操作列固定在右侧，宽度稳定；长文本使用省略和 tooltip，交易编号提供复制按钮。默认交易日期倒序，筛选组合按 AND 生效。
- **反馈**：全局结果用 `message`/`notification`，需要用户决策用 `Modal`，页面内流程问题用 `Alert`，不要用 toast 承载关键交易结果。
- **无障碍**：正文与背景达到 WCAG AA 对比度；焦点态可见；键盘可操作；弹窗打开后焦点进入弹窗，关闭后返回触发元素。

## 7. 响应式约束

### 7.1 断点

| 断点 | 视图 | 约束 |
| --- | --- | --- |
| `≥ 1280px` | 标准桌面 | 展开侧栏；表格显示完整关键列；摘要指标四列 |
| `1024–1279px` | 紧凑桌面 | 侧栏可折叠至 `64px`；次要表格列隐藏到详情；摘要指标两列 |
| `768–1023px` | 平板横向 | 使用可收起侧栏；筛选区允许换行；高风险表单保持单列 |
| `< 768px` | 移动端 | 侧栏改为抽屉；顶部操作换行；表格改为关键字段列表/横向滚动；摘要指标单列或两列 |

### 7.2 移动端行为

- 主内容水平内边距 `16px`，桌面端 `24px`；任何页面不得依赖固定最小宽度导致整页横向溢出。
- 表格优先保留交易时间、对手方、金额、状态；完整字段进入详情抽屉。若必须横向滚动，滚动容器独立于页面并保留首列/关键列。
- 筛选条件在抽屉中编辑，顶部只显示已选条件数量和“筛选”按钮；查询与重置固定在抽屉底部。
- 连接与运营在 `>= 1024px` 时保留左侧可折叠分组、紧凑筛选和固定操作列；银行数据底座表格固定状态、金额、最后同步时间、任务号/请求号等关键列，其余字段进入详情抽屉。窄屏将三级导航和筛选分别放入抽屉，银行数据列表保留时间、状态、金额、任务号/请求号和关联编号，详情单列显示。凭据弹窗、状态标签、请求号、错误摘要和长编号必须换行、截断或复制，不能溢出容器；监控指标改为单列或双列，软键盘和固定底栏不得遮挡输入、错误与操作。
- 触控目标最小 `44 × 44px`；点击行与行内操作要有明确区分，避免误触。
- 文字、金额和按钮允许自然换行；编号等长字符串使用截断、换行或复制，不撑破布局。

## 8. 交付验收清单

- 未登录、无权限、权限加载失败三种访问结果可区分。
- 所有当前版本业务页具备 loading、空数据、错误和成功反馈；主动转账、支付、审批和执行页面不在当前版本提供。
- 自动入账具备文件/模拟来源导入、重复导入、异常校验、复核并发、模拟制证幂等及全链路追溯的明确状态和验收反馈。
- 连接与运营分组支持持久化展开/收起，且按权限完整隐藏；无权深链接和服务端接口均正确拒绝访问。
- 所有连接、监控与数据查询页面持续显示真实直联未启用边界，模拟数据不会标识为真实银行数据。
- 凭据只在创建/轮换瞬间可见一次；日志、审计、列表、错误、导出和下载均不得泄露密钥、令牌或完整账号。
- 应用、签约、设置、监控、任务、日志及六类数据查询均覆盖 loading、未启用、空数据、失败、请求编号、详情追溯和 403。
- 模拟任务重试与模拟签约变更服务端幂等，失败、重试与状态变化可在审计时间线追溯，且不创建重复业务记录。
- 飞书协同具备模拟连接、接收对象、通知策略和发送记录；事件按企业和 `event_id` 幂等，权限、脱敏、失败和请求编号可追溯。
- 银行数据查询可安全跳转既有自动入账或资金管理详情，但查询域没有修改资金、审批、复核或制证状态的入口。
- v0.2 定时同步和手动同步复用同一服务端任务模型、请求编号、幂等和审计链路；浏览器刷新、轮询或恢复页面不会触发同步。
- 余额、流水、回单、对账单、支付记录和代发六类查询均为 FINFLOW API 只读查询，使用服务端分页、AND 筛选、稳定排序和详情抽屉。
- 支付记录的异步回执状态不会把银行受理、网络超时、未知结果或技术回执误报为付款成功。
- 原始报文 30 天只允许在任务或对象详情中展示受控追溯摘要，不提供预览、下载、复制或前端缓存。
- 企业隔离、无权深链 403、完整账号/对方/收款人脱敏和模拟数据显著标识均通过验收；403 不泄露对象是否存在。
- 银行数据底座在 `1440px`、`1024px` 和 `375px` 下无状态、金额、请求号、错误、筛选和抽屉操作溢出或遮挡。
- 导航、按钮和字段均按权限编码控制，服务端接口也有对应鉴权。
- 银行侧支付记录仅作为只读查询，任何查询结果不得生成或改变 FINFLOW 支付、转账或调拨对象。
- 桌面端 `1024px` 宽度和移动端 `375px` 宽度无不可接受的内容重叠或横向溢出。
- 颜色不是唯一状态表达方式；键盘、焦点、屏幕阅读器标签和对比度通过基础无障碍检查。
- 金额、时间、时区、脱敏和错误文案遵循企业配置，并在接口异常时保持可解释。

## 9. 关键决策记录

1. 当前版本不实现主动转账、付款、资金调拨、支付审批、支付执行或银行出款；历史支付代码和数据库迁移仅作为隔离的后续模块保留。
2. 采用权限驱动的导航与操作可见性，隐藏无权动作并将绕过 UI 的访问统一导向 403；鉴权责任仍归服务端。
3. 标准化流水和银行侧支付记录仅使用稳定的服务端只读表格能力，筛选条件写入 URL，便于复查、分享和审计。
4. 使用中性浅色布局与高对比语义色，减少金融数据误读；所有状态保留文字标签，满足色觉差异下的可用性。
5. 以桌面高密度工作流为主，同时为 `375px` 移动端保留完整的查看、筛选和追溯能力；不设计主动支付闭环。
6. 自动入账与主动支付/调拨在领域和界面上隔离；当前版本不提供主动支付能力，一期以文件/模拟来源闭环，真实银行 SDK 不在范围。
7. 连接与运营作为平行、可折叠的侧栏业务域，集中承载连接配置、运营可观测性和银行数据查询，避免污染资金操作及自动入账闭环。
8. 一期严格为“未启用真实银行直联”；所有模拟配置、任务和结果均显式标识模拟，真实银行 SDK/API、生产密钥和真实数据采集留待后续受控接入。
9. 连接凭据只显示一次并全链路脱敏，任务重试使用服务端幂等和时间线追溯，保证运营可诊断而不泄露敏感数据。
10. 飞书协同一期只使用 MOCK Adapter；通知采用事件、Outbox、投递记录的服务端模型，前端不直连飞书，真实租户授权和凭据留待后续受控接入。
11. v0.2 前端定位为 FINFLOW API 消费者，只展示服务端标准化后的业务事实和查询投影，不接触银行 SDK/API、原始报文、同步日志全文或银行专有字段。
12. 定时同步和手动同步共用服务端任务、请求编号、幂等与审计模型，前端只负责创建授权任务和解释任务状态，不以浏览器行为直接拉取银行。
13. 支付最终状态必须由服务端标准化回执和对账确认驱动；银行受理、超时、未知或技术回执都只能显示为中间态。
