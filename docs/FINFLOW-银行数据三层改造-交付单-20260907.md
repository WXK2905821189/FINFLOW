## 一、交付内容

### Phase 1：真原文落库（修复 FIX-003 P2-4）

| 项 | 内容 |
|---|---|
| V23 迁移 | `bank_data_raw_message` 加 `response_payload`（银行解密后原文 verbatim）/ `request_evidence`（请求要素 JSON）/ `duration_ms` / `http_status`，每列一条 ALTER（H2 红线） |
| 抓取点 | `CmbHttpGateway.exchangeDetailed()` 结构化返回：加密前明文请求 + 耗时 + HTTP 状态；CITIC 同步（请求 XML + 响应 XML） |
| 载体 | `BankDataCollection` 加第 9 组件 `evidence`，保留 7/8 参旧重载（20 个调用点零改动） |
| 语义修复 | 此前 raw_message payload 存的是解析后重建视图（~300B），适配器丢字段报文跟着丢；现在真原文独立成列，不可变 |
| 行映射抽取 | `CmbRowMapper` / `CiticRowMapper`：adapter 与重放共用同一套映射规则，杜绝规则漂移 |
| 前端 | 报文抽屉升级三段式：银行原文 / 解析视图 / 请求要素（URL、明文请求体、耗时、HTTP 状态、首页余额辅助调用）+ 重放按钮 |

### Phase 2：清洗规则显式化 + 重放

| 项 | 内容 |
|---|---|
| `BankCanonicalizer` | 聚合层 canonical 规则（方向归一、币种归一、trim）抽为独立类，聚合与重放共用 |
| `BankRawReplayService` | 按某条 raw_message 的银行原文按**当前**解析规则重跑，逐条对比存量平台结果，暴露字段漂移 |
| 端点 | `POST /api/bank-data-raw-messages/{id}/replay`，权限 `bankdata:raw:view`（仅 role 1/2） |
| 重放铁律 | 状态走与入库同一条归一路径（`BankDataStatus.fromVendor`）+ 还原 auxiliary 首页余额快照 + 带 pageTotals，否则必假报差异 |

### Phase 3：对账视图

| 项 | 内容 |
|---|---|
| 接口 | 任务级对账：银行 Z1 合计（借/贷笔数与金额）vs 平台侧计数，勾稽差异行标红；`GET /api/bank-data/reconciliation-tasks` |
| 页面 | `BankReconciliationPage`（`/bank-access/data/reconciliation`），权限 `bankdata:view`，导航「数据查询 → 对账核对」 |

## 三、使用方式

1. **看报文**：原始报文页（或余额/流水行详情「查看本次报文」）→ 详情抽屉三段式查看银行原文 + 请求要素。
2. **验证清洗规则**：报文详情点「重放」→ 对比存量平台结果与当前规则结果，字段漂移一秒定位。
3. **对账**：数据查询 → 对账核对 → 银行 Z1 合计 vs 平台计数，差异标红。
