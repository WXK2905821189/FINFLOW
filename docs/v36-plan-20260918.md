### W3 草稿链路合流——修「凭证中心看不到草稿」（需求 3，bug 优先）
**排查任务**：①走读 voucher_group 生成时机（WP-D vouchergroup 代码）②本地 H2 造数复现「有时不可用」③核对 aiVoucher DRAFT 在 MANUAL 账户/账期 BLOCKED/非超管下的分支与报错可见性。
**修复（D2 定案 = 落组）**：`AiVoucherBatchService` DRAFT 分支同步建组（单流水组，status=PENDING）；V36 迁移一次性为存量 PENDING 草稿补组；凭证中心行点击进 VoucherDocPage 草稿单据页链路核通。
**改动文件（后端为主）**：statements 域 AiVoucherBatch 相关 Service、voucher-group Service、V36 迁移 + ci.yml 六处；前端仅当报错提示需改（**改 BankDataQueryPage 提示前与 W1 会话对时**）。
**验收**：流水选 N 笔 → AI 制证为草稿 → 凭证中心立即可见 → 通过 → 推送（MOCK）全链通；财务经理（非超管）同链可用；账期 CLOSED 报错文案明确。

> **W3 实际排查结论（2026-09-18，已完成——与计划假设不同）**：
> 根因**不是** D2 假设的「DRAFT 不落组」。实证：凭证中心（VoucherGroupService.pageGroups）是 StatementRecord 的**投影读模型**（`voucher_group` 表根本不存在），组语义是动态算出来的——DRAFT 草稿本来就在投影范围里。真正的病根是**公司域过滤不一致**：制证链路对持 `bankdata:cross-company:view` 的用户（ADMIN/FINANCE_MANAGER，V24 授予）放行他司流水，而凭证中心与整条复核/推送链（StatementService 全部 `companyIdForUser` 检查）恒锁操作人本公司——他司草稿「制证成功、处处 404/不可见」，且问题随主体数量增加愈发频繁（「有时不可用」）。
> **修复面**：StatementService 的 require/pageStatements/review/batchReview/batchPush/pushVoucher/dashboard/batches 全链改为「有 cross-company 权限 → 可见全部；无 → 仅本公司」（写操作锁定语义不变）；BankDataAccountingService 刷新建议/存草稿同步放开；VoucherGroupService 同口径。**无需任何迁移**（V36 号空置）。测试：VoucherGroupIntegrationTest 反转隔离断言 + 新增跨公司端到端用例（同时修正了旧断言拿 voucherNo 当 statementNo 匹配的永真式错误）。
