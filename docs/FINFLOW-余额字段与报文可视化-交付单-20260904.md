## 二、余额生命周期字段（V21）

对照 NTQADINF 文档，4 个 Y 必返字段此前在 `RealCmbBankDataAdapter.toBalances()` 构造时直接丢弃：

| 字段 | 语义 | 落点 |
|---|---|---|
| `stscod` | 账户状态 A=活动/B=冻结/C=关户 | `account_status` |
| `opndat` | 开户日 yyyyMMdd | `open_date` |
| `inttyp` | 利率类型（ZZZ=不计息等） | `interest_type` |
| `dpstxt` | 存期 | `deposit_term` |

链路：`CmbResponseParser.BalanceRow`（+3 解析）→ `BankDataBalanceEntry`（+4 组件）→ `canonicalBalances()` 透传 → `BankDataSyncExecutor` setter → 实体/V21 迁移（每列一条 ALTER）→ `BankDataBalanceResponse` → 前端表格「账户状态」Tag 列 + 详情 4 字段（inttyp 带中文解码）。CITIC DLBALQRY 无这些字段，置 null。

**注意**：旧行（V21 前入库）新字段为 null 是预期；下次余额同步后自动填充。

## 三、jobs 列表 NPE（生产缺陷，f5d50f4 修复）

- **现象**：`GET /api/bank-sync-jobs` 恒 500；`GET /api/bank-sync-jobs/{id}` 正常。
- **根因**：`BankDataSyncResponseAssembler.tasks()` 的 `connectionCodes.get(item.getConnectionId())` 无守卫——`connection_id` 为 NULL 的任务行（调度创建的任务就是）遇 `Map.of()`（immutable map，**get(null) 抛 NPE**，与 HashMap 不同）直接炸列表；单查走的 `connectionCode()` 有 null 守卫所以幸免。
- **为何看不见**：`GlobalExceptionHandler.handleUnexpected` 吞异常不记日志——排障浪费约半小时。已加 `log.error`（含栈）。
- **补测试**：`BankSyncJobListIntegrationTest`（GET 列表此前零覆盖，所有现存测试只 POST 过 job）。
- **本地复现路径**：直调 `queryService.listJobs()` 绕过异常处理器拿真实栈。
