# 银行接入模块一期测试计划

## 1. 目标与范围

本计划验证“银行接入”独立模块的导航、权限、连接配置、采集监控与日志、数据查询和审计追溯。它与自动入账平行，仅复用会话、RBAC、账户主数据、审计和通用格式；主动转账、支付和调拨不属于当前产品。

2026-09 一期只支持未启用/模拟直联展示和 FINFLOW 服务端事实数据查询，不接入真实银行 SDK/API，不自动拉取银行流水，不查询真实银行余额/回单，不连接真实金蝶。任何真实外部调用或误导性成功文案均为 P0 越界缺陷。

## 2. 测试角色与准入

准备以下最小角色：

| 角色 | 权限 | 预期能力 |
| --- | --- | --- |
| 查询用户 | `data:query` | 仅查看授权范围内事实数据，无配置、重试、导出敏感数据权限。 |
| 运维用户 | `operation:monitor`、`operation:log:view` | 查看监控、任务和脱敏日志；不能修改直联密钥或业务数据。 |
| 连接管理员 | `connection:view`、`connection:manage` | 管理直联元数据和模拟开关；密钥只写不读，所有变更留痕。 |
| 无权用户 | 无相关权限 | 不显示入口，深链接和接口返回 `401/403`，不泄露对象存在性。 |

准入条件：已部署前端、后端、数据库迁移、审计、请求编号、模拟连接开关和测试日志检索能力；准备两个企业、两个账户、已知流水/余额快照、空数据集、失败任务和含敏感字段的脱敏样本。所有账号、流水和密钥均为虚拟值。

## 3. 一期状态与安全不变量

| 对象 | 允许状态/展示 | 不变量 |
| --- | --- | --- |
| 直联应用/签约 | `未启用`、`模拟`、`停用` | 不得显示已连接真实银行；密钥、Token、私钥和完整证书只可在生成后的首次成功响应/一次性确认界面展示（如功能要求），之后不可经刷新、详情、列表、日志、审计或导出再次获取；轮换使旧凭据失效。 |
| 任务 | 未开始、运行中、成功、失败、超时、取消、重试中 | 重试按服务端幂等处理，不重复触发导入、制证、支付或调拨。 |
| 日志/审计 | 可检索、只读、可追溯 | 含操作者、时间、模块、对象、结果、请求编号；不可编辑/删除，敏感字段脱敏。 |
| 查询结果 | 未启用、事实数据、空态、失败态 | 余额、流水、回单、对账单、代发均只来自服务端授权响应；前端不得生成或补造任何记录。失败必须有请求编号和只读审计关联。 |

## 4. 执行用例

| ID | 标记 | 场景与操作 | 通过标准与证据 |
| --- | --- | --- | --- |
| CO-01 | P0 / 联调必验 | 未登录、无权、查询、运维、连接管理员分别在侧栏展开、折叠、刷新和恢复上次导航状态后访问导航、页面深链接和接口。 | 菜单按权限隐藏；折叠只改变显示，不能显示无权子项或绕过路由守卫；无权深链接为 `401/403`，不泄露页面或对象存在性；保存角色矩阵、响应和审计证据。 |
| CO-02 | P0 / 联调必验 | 查看直联应用、签约管理、个性化设置和模拟任务。 | 页面、接口、日志和审计统一标注“未启用”或“模拟”；不得出现已连接、已同步真实银行等表述；保存页面截图和响应摘要。 |
| CO-03 | P0 / 联调必验 | 提交或生成虚拟密钥、Token、私钥、证书和完整账号，记录首次成功响应后依次刷新、重新登录、查看详情/列表、重试、导出和查询审计；再执行凭据轮换。 | 如一期存在凭据回传，明文仅在首次成功响应/一次性确认界面可见一次；之后仅显示掩码和元数据。数据库、日志、审计、错误响应、前端存储和导出均无明文；轮换后旧凭据不可读取或使用，配置变更含操作者、时间、结果、请求编号。 |
| CO-04 | P0 / 联调必验 | 在监控、任务、日志、数据查询和审计详情中查看含完整账号、对方账号、原始载荷的样本。 | 默认账号仅末四位或规定掩码；原始载荷仅受控授权可查；控制台、网络错误、导出和日志均无完整敏感值。 |
| CO-05 | P0 / 联调必验 | 对余额、流水、回单、对账单、代发五类查询逐类构造已知服务端事实、未启用、无数据、接口失败、超时、部分加载和筛选为空。 | 有数据与服务端逐项一致；未启用、空态和失败态使用不同状态与安全文案；失败保留筛选并给出请求编号及只读审计关联；不得使用前端默认值、缓存或随机值伪造结果。 |
| CO-06 | P0 / 联调必验 | 用第二企业的账户、流水、任务、日志和审计 ID 篡改详情、筛选、分页和导出请求。 | 列表、详情、汇总、日志和导出均按企业及角色隔离；统一 `403` 或安全空结果，不泄露存在性、金额、账号和凭证号。 |
| CO-07 | P0 / 联调必验 | 从数据查询、监控任务、日志和自动入账流水进入详情追溯；检查请求编号和审计事件。 | 可定位来源、操作者、时间、对象、动作、结果、前后状态和请求编号；银行接入操作不改变自动入账、交易或余额。主动支付/调拨不在当前产品范围。 |
| CO-08 | P0 / 联调必验 | 分别构造监控未启用/无数据/异常、任务无数据/运行中/失败/超时/重试、日志无数据/查询失败/部分加载和服务异常。 | 每类页面明确区分未启用、空态、加载和失败；保留筛选和上次有效结果；所有失败含安全错误摘要、请求编号和只读审计/日志关联，不显示堆栈、原始载荷或密钥。 |
| CO-08A | P0 / 联调必验 | 对同一失败任务重复点击、刷新、网络超时重试及并发重试；同时检查任务详情、日志和关联业务对象。 | 重试受权限控制并以服务端任务/业务幂等键去重；最多一次逻辑执行和一条连续结果链，不重复触发导入、制证、支付或调拨。任务、日志、审计共享请求编号并可追溯。 |
| CO-09 | P1 / 联调必验 | 按时间、模块、操作者、结果、请求编号、账户和分页组合检索日志/查询数据。 | 筛选由服务端执行，排序稳定，列表/详情/汇总/导出口径一致；超大页、非法参数和深分页受限；无 SQL、堆栈或敏感字段泄露。 |
| CO-10 | P1 / 联调必验 | 触发配置变更、权限拒绝、任务失败、查询失败、审计写入失败和外部调用尝试。 | 事件可追溯；审计写入失败不得静默放行高风险操作；外部调用次数为 0；监控指标和告警不含原始载荷或密钥。 |
| CO-11 | P0 / 上线必验 | 在上线候选环境核对环境变量、网络白名单、DNS、代理、SDK 依赖和模拟开关。 | 银行 SDK/API、真实金蝶和真实回单/余额连接未配置或被明确阻断；真实外部调用次数为 0；生产密钥不进入前端构建产物和日志。 |
| CO-12 | P0 / 上线必验 | 对既有交易记录、用户/账户管理、审计查询执行登录、查看或管理的核心烟囱回归。 | 原路由、菜单、接口、余额、审计和权限无回归；银行接入、自动入账新增入口不替换既有能力。主动转账/支付/调拨不属于当前版本。 |
| CO-13 | P1 / 上线必验 | 上线后使用受控账号执行只读查询、监控、日志和自动入账追溯；检查健康检查、延迟、失败率、积压、告警和值班通知。 | 页面与生产服务端事实一致；告警可收到并关联请求编号；无真实外部调用、敏感数据泄露或未授权入口。 |

## 5. 联调与上线证据要求

### 联调必验

- 保存版本、数据库迁移版本、模拟开关状态、权限矩阵、请求编号、脱敏响应、审计查询和模拟调用记录。
- 对 CO-01 至 CO-10 逐项记录执行人、时间、数据集、结果、缺陷编号；P0 任一失败不得进入上线验收。
- 用网络出口、应用日志、模拟适配器和数据库审计共同证明真实银行/金蝶调用次数为 0，不能只依据页面文案。

### 上线必验

- 由发布人与安全/运维双人复核生产配置、网络策略、日志留存、脱敏规则、告警接收人和值班流程。
- 保存 CO-11 至 CO-13 的环境截图、配置校验结果、外部调用核查、核心回归结果和上线后烟囱请求编号。
- 上线后发现真实连接、密钥暴露、伪造查询数据、越权、既有支付/调拨回归或审计断链，立即阻断放量并按回滚/事件流程处理。
