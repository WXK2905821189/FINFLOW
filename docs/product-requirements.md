# FINFLOW 企业财务管理平台产品背景、需求与验收标准

## 1. 文档目的与范围

本文定义 FINFLOW 企业财务管理平台首期（MVP）的业务背景、目标功能、权限边界和验收标准，供产品、前端、后端、UI/UX、质量安全与发布协作使用。

FINFLOW 是一个前后端分离的企业财务工作台：`frontend/` 使用 React、TypeScript、Vite 与 Ant Design；`backend/` 使用 Java 17、Spring Boot、Spring Security、MyBatis-Plus、Flyway 与 MySQL/H2。平台通过统一的多银行网关抽象接入中信银行，并为后续银行扩展预留适配器边界。

以下内容按“单企业租户、人民币资金管理、银行转账需审批”的业务基线制定；未明确部分以本文为准。当前代码库中的 v0.1.x 是本地联调与演示 MVP，不得连接真实银行或承载真实企业资金。涉及真实银行直连、真实清算、电子签章、发票和多币种的能力均不在本期可发布范围内。

### 1.1 当前实现与目标边界

| 范围 | 当前 v0.1.x 基线 | 本文的目标验收标准 |
| --- | --- | --- |
| 前端 | 已提供登录、注册、仪表盘、用户、转账与交易页面框架；部分页面仍使用演示数据 | 所有业务数据和操作均通过受鉴权的后端 API 获取，不得展示伪造的提交成功或管理员会话 |
| 后端 | 已提供 JWT、RBAC、Flyway、银行适配器接口和中信模拟适配器 | 完成企业隔离、转账申请状态机、审批职责分离、幂等、事务、交易记录与审计 |
| 银行网关 | 中信银行模拟适配器可支持开发联调；真实 SDK 适配器是明确失败的占位实现 | 真实接入必须在授权沙箱完成签名、证书、回执、限额与幂等验证后单独验收 |
| 部署与质量 | 已有前后端构建 CI 与部署指南 | 真实生产前须关闭质量报告中的全部 P0 阻断项，并完成预发布、备份恢复和回滚演练 |

### 1.3 目标

- 让受控用户完成账户、收支和转账的日常操作。
- 通过最小权限与审批机制降低未经授权的资金操作风险。
- 保留可追溯的交易记录、异常处理和审计证据。
- 于 2026 年 9 月交付“财务流水自动入账”一期：将受控来源的银行流水自动校验、落库、人工复核并推送至金蝶云星空模拟制证链路，目标在规则稳定后的完整自然月节省 6-7 人天的人工整理、录入和追溯工作量。

### 1.4 本期不包含

- 银行 API 直连、自动扣款或向外部银行实际发起付款。
- 多企业租户、多币种、汇率换算、总账核算、税务申报和发票管理。
- 单点登录（SSO）、双因素认证、电子签章，以及自动入账范围外的通用批量导入/导出。
- 自助注册后自动获得企业数据访问权。

## 2. 术语与状态

| 术语 | 定义 |
| --- | --- |
| 企业 | 平台中的数据隔离单元。本期每个账户仅归属一个企业。 |
| 银行账户 | 企业名下可用于记录余额及发起转账的账户。 |
| 交易 | 一笔收入、支出或转账产生的资金流水。 |
| 转账申请 | 用户提交、等待审批或执行的内部支付指令。 |
| 财务流水（流水） | 从受控文件或模拟来源采集的收支明细，是自动入账域的原始业务事实，不等同于转账申请。 |
| 导入批次 | 同一次文件导入或模拟采集产生的流水集合及其处理汇总。 |
| 自动入账 | 对流水执行格式与业务校验、持久化、人工复核、金蝶云星空模拟制证和对账追溯的受控流程。 |
| 金蝶模拟凭证 | 由本期模拟网关生成的凭证编号和结果，仅用于流程联调，不代表金蝶云星空已创建真实凭证。 |
| 对账 | 比较来源流水、FINFLOW 已落库流水和模拟制证结果的数量、金额及状态，并标识差异的过程。 |
| 操作人 | 对资金或数据进行操作的登录用户。 |
| 审批人 | 对转账申请执行通过或驳回的有权用户。 |

### 2.1 转账状态

| 状态 | 含义 | 可转移状态 |
| --- | --- | --- |
| 草稿 | 创建人暂存，尚未提交 | 待审批、已取消 |
| 待审批 | 已提交，等待审批人处理 | 已批准、已驳回、已取消 |
| 已批准 | 审批通过，等待财务执行 | 已执行、已取消 |
| 已驳回 | 审批不通过，保留原因 | 草稿 |
| 已执行 | 财务已确认完成记账 | 无 |
| 已取消 | 创建人或有权人员终止申请 | 无 |

已执行、已取消的申请不可编辑、删除或恢复；错误数据通过新增冲正交易处理，不得覆盖历史记录。

## 3. 用户角色与 RBAC

### 3.1 角色定义

| 角色 | 职责 | 数据范围 |
| --- | --- | --- |
| 系统管理员 | 管理企业用户、角色和银行账户配置 | 本企业全部数据与配置 |
| 财务专员 | 维护交易、创建转账、执行已批准的转账 | 本企业财务数据 |
| 财务经理 | 审批转账、查看资金经营情况与全部交易 | 本企业财务数据 |
| 业务查看者 | 查看已授权的仪表盘、银行账户余额和交易 | 本企业只读财务数据 |

默认不提供跨企业管理员。系统初始化时应至少存在一名系统管理员；管理员不可删除或停用自身，除非企业内另有启用状态的系统管理员。

### 3.2 权限矩阵

| 功能/动作 | 系统管理员 | 财务专员 | 财务经理 | 业务查看者 |
| --- | ---: | ---: | ---: | ---: |
| 查看仪表盘 | 是 | 是 | 是 | 是 |
| 查看交易记录与明细 | 是 | 是 | 是 | 是 |
| 新增/编辑草稿交易 | 是 | 是 | 否 | 否 |
| 新增冲正交易 | 是 | 是 | 是 | 否 |
| 管理银行账户 | 是 | 否 | 否 | 否 |
| 创建、编辑、取消本人草稿转账 | 是 | 是 | 否 | 否 |
| 提交本人转账 | 是 | 是 | 否 | 否 |
| 审批转账 | 否 | 否 | 是 | 否 |
| 执行已批准转账 | 是 | 是 | 否 | 否 |
| 查看自动入账流水、批次、凭证状态和对账汇总 | 是 | 是 | 是 | 是 |
| 导入流水文件或触发模拟来源采集 | 是 | 是 | 否 | 否 |
| 复核通过/驳回有效流水 | 是，但不得复核本人导入的流水 | 否 | 是，但不得复核本人导入的流水 | 否 |
| 推送已复核流水至金蝶模拟网关及重试失败推送 | 是 | 是 | 否 | 否 |
| 配置受控来源、文件模板和入账规则 | 是 | 否 | 否 | 否 |
| 查看直联管理（应用、签约、个性化设置） | 是 | 否 | 否 | 否 |
| 管理直联应用、签约和个性化设置 | 是 | 否 | 否 | 否 |
| 查看直联状态、任务执行和操作日志 | 是 | 否 | 否 | 否 |
| 触发或重试模拟运营任务 | 是 | 否 | 否 | 否 |
| 查询余额、流水、回单、对账单、支付记录和代发（按账户授权只读） | 是 | 是 | 是 | 是 |
| 管理用户与角色 | 是 | 否 | 否 | 否 |
| 查看操作审计记录 | 是 | 否 | 是 | 否 |

RBAC 必须在服务端执行，前端菜单隐藏不构成权限控制。无权限请求返回 `403`，且不得在响应中泄露资源是否存在、账户余额、用户信息或交易明细。

### 3.3 职责分离规则

- 转账创建人不得审批自己创建的转账，无论其是否同时具有审批角色。
- 转账审批人不得执行自己审批通过的转账。
- 已执行转账不得被任何角色修改或删除。
- 管理员可管理用户及银行账户，但不默认获得“审批转账”权限；审批必须使用财务经理角色。
- 自动入账的导入操作人与流水复核人不得为同一人；即使用户同时拥有多个角色，服务端也必须拒绝其复核本人导入的流水。
- 金蝶模拟凭证推送仅可针对“复核通过且未成功推送”的流水；推送人不得通过修改原始流水、复核结论或凭证号绕过状态校验。

## 4. 登录与注册

### 4.1 登录

用户通过“邮箱/用户名 + 密码”登录。成功后进入仪表盘，并仅加载其所属企业及权限范围内的数据。

登录页必须提供：账号输入、密码输入、显示/隐藏密码、登录按钮、注册链接、忘记密码入口。错误提示统一为“账号或密码错误”，不得区分账号不存在、密码错误或账号已停用。

### 4.2 注册与账号激活

- 自助注册仅创建“待激活”账号，不关联任何企业、不授予任何角色、不可查看任何财务数据。
- 注册字段：姓名、工作邮箱、密码、确认密码；邮箱必须唯一，密码至少 8 位，且同时包含字母和数字。
- 管理员通过用户管理创建或激活企业成员，分配角色后该用户才可登录企业系统。
- 已停用账号无法登录；已登录会话在下一次鉴权时失效。
- 忘记密码采用一次性、限时的重置凭证；重置成功后所有既有会话失效。

### 4.3 验收标准

- 正确账号密码可登录并跳转仪表盘；错误组合仅显示统一错误信息。
- 未激活注册用户登录时无法访问任何企业页面或接口。
- 停用用户重新登录失败，且使用旧会话访问受保护接口返回未认证或无权限。
- 密码不满足规则时无法提交注册或重置；系统不得存储或返回明文密码。
- 任一受保护页面在未登录状态访问时跳转登录页；登录后回到原目标页面（若该页面有权限）。

## 5. 仪表盘

### 5.1 功能需求

仪表盘是登录后的默认页面，按当前用户权限展示本企业的资金概览。展示数据至少包括：

- 全部启用银行账户的当前余额合计。
- 各银行账户名称、账号掩码、余额和最后更新时间。
- 当前自然月收入、支出、净现金流。
- 待审批转账数量及金额；仅财务经理可看到“待我审批”的列表入口。
- 最近 10 笔交易：日期、类型、摘要、金额、状态、关联转账编号（如有）。
- 近 6 个自然月的收入、支出和净现金流趋势。

统计口径：收入为已入账收入交易总额；支出为已入账支出交易总额；已取消或失败的交易不计入；净现金流 = 收入 - 支出。金额统一按人民币显示，保留两位小数，并使用千分位。

### 5.2 验收标准

- 无数据企业可正常打开仪表盘，金额显示 `0.00`，列表显示空状态，不出现错误或虚构数据。
- 仪表盘金额与交易记录中相同筛选范围的已入账交易汇总一致。
- 业务查看者可查看概览和交易摘要，但不出现新增、审批、执行、用户管理等操作入口。
- 财务经理仅可看到由他人创建、且状态为待审批的申请；本人创建的申请不应进入“待我审批”。
- 银行账户号码在任何仪表盘视图中最多显示末四位，其余字符掩码处理。

## 6. 用户管理

### 6.1 功能需求

仅系统管理员可访问用户管理。页面支持用户列表、搜索和状态筛选，并可查看姓名、邮箱、角色、状态、创建时间、最近登录时间。

管理员可：邀请/创建企业成员、编辑姓名和角色、启用/停用账号、重新发送激活邀请。邮箱作为身份标识不可直接修改；如需变更，应创建变更申请并保留审计记录（本期可由管理员停用旧账号并新建账号替代）。

停用账号前，系统必须提示该用户是否为唯一系统管理员、是否有未完成的转账草稿或待审批任务。唯一系统管理员不可停用；存在未完成任务时允许停用但必须显示风险提示，原任务不自动转移。

### 6.2 验收标准

- 非系统管理员访问用户管理页面或接口，均被拒绝。
- 新建/邀请成员后，成员在激活并获分配角色前不可访问企业数据。
- 管理员修改角色后，新权限在该用户下次接口请求时生效，不依赖重新发布系统。
- 系统阻止停用企业内唯一的启用系统管理员。
- 每次创建、角色变更、启停、邀请重发均记录操作者、时间、目标用户、变更前后值和结果。

## 7. 银行账户与转账

### 7.1 银行账户

系统管理员可维护银行账户：账户名称、开户行、账户号、账户类型、币种（本期固定 CNY）、期初余额、启用状态。账户号必须在保存前校验非空和格式合法；存储及日志中必须脱敏，前端展示仅显示末四位。

停用银行账户后，不可用于新建转账，但历史交易和关联申请仍可查询。存在待审批或已批准转账时，系统不允许停用该账户。

### 7.2 创建与提交转账

系统管理员和财务专员可创建转账草稿，必填字段包括：付款账户、收款方名称、收款账号、收款银行、转账金额、用途/摘要、计划付款日期。金额必须大于 0，最多两位小数，且不超过付款账户可用余额。

草稿仅创建人可编辑和取消。提交时再次校验字段完整性、付款账户启用状态、可用余额及收款账号格式。提交成功后生成不可重复的转账编号，状态变为待审批，并记录提交时间。

### 7.3 审批与执行

- 财务经理可对待审批申请执行通过或驳回；驳回必须填写原因，通过可填写意见。
- 系统必须阻止创建人审批自己的申请。
- 审批通过后状态变为已批准；驳回后状态变为已驳回，创建人可复制/重新编辑为草稿并再次提交。
- 系统管理员或财务专员可执行已批准申请，执行时再次校验付款账户状态和余额；执行人不得为该申请的审批人。
- 执行成功后，系统生成一笔已入账支出交易并关联转账编号，扣减付款账户余额，申请状态变为已执行。
- 因余额不足、账户停用或并发状态变化而无法执行时，不生成交易、不改变余额，申请保持已批准并记录失败原因。

### 7.4 验收标准

- 转账必填字段缺失、金额为零/负数/超过两位小数、余额不足或付款账户已停用时，系统阻止保存或提交并指出对应字段。
- 同一转账在并发提交或刷新后只生成一个有效转账编号和一条申请记录。
- 创建人尝试审批本人申请，或审批人尝试执行本人审批的申请时，界面无操作入口且服务端返回 `403`。
- 已批准转账仅可被执行一次；重复执行请求不得重复扣款或生成重复交易。
- 执行成功后，转账、交易和账户余额三者的数据一致，且可通过转账编号相互追溯。
- 已驳回、已取消、已执行申请均不可编辑金额、收款信息或付款账户。

## 8. 交易记录

### 8.1 功能需求

交易记录展示企业全部资金流水，字段包括交易编号、交易日期、类型（收入/支出/冲正）、银行账户、摘要、对方信息、金额、状态、关联转账编号、创建人和创建时间。

支持按日期范围、交易类型、银行账户、状态、关键字（交易编号/摘要/对方名称）筛选，支持按交易日期倒序分页。默认展示最近 30 天交易。

交易创建或转账执行后不得直接物理删除。发现已入账交易错误时，系统管理员、财务专员或财务经理可创建金额相反且引用原交易编号的冲正交易；原交易与冲正交易均保留并可相互跳转。

### 8.2 验收标准

- 任一筛选条件只返回当前企业内满足条件的记录；组合筛选按 AND 关系生效。
- 分页结果稳定，无重复或漏项；切换页码和筛选条件后汇总与列表一致。
- 用户无法通过交易编号、查询参数或接口访问其他企业的交易。
- 已入账交易不提供编辑或删除能力；冲正后历史交易仍可查询，并清晰显示关联关系。
- 由转账执行生成的交易不可手工取消、删除或解除关联。

## 9. 异常处理与审计

### 9.1 业务异常

| 场景 | 系统行为 | 用户可见信息 |
| --- | --- | --- |
| 无权限访问 | 拒绝请求并记录安全审计 | 无权执行此操作 |
| 会话失效 | 清除会话并跳转登录 | 登录已失效，请重新登录 |
| 并发审批/执行 | 以最新有效状态为准，只允许一次成功 | 该申请状态已变化，请刷新后重试 |
| 余额不足 | 不提交/不执行资金操作 | 可用余额不足 |
| 数据校验失败 | 不落库，不产生半成品业务数据 | 对应字段的明确校验提示 |
| 系统故障 | 回滚同一事务内的数据变更，记录错误详情 | 操作未完成，请稍后重试（含请求编号） |

所有涉及余额扣减、转账状态变更和交易创建的操作必须使用原子事务；任一步失败时，不得出现“已扣余额但无交易”或“已执行但余额未变”的中间状态。

### 9.2 审计要求

系统至少记录登录成功/失败、登出、用户和角色变更、银行账户变更、转账创建/提交/审批/执行/取消、交易创建/冲正、权限拒绝及系统异常。每条审计记录必须包含：事件时间、操作者 ID、企业 ID、操作类型、目标资源 ID、请求结果、请求编号、变更前后摘要（适用时）。

审计记录仅允许追加，不允许通过业务页面修改或删除。本期保留期限不少于 365 天。

## 10. 权限与数据边界

- 所有业务表和查询必须具备企业 ID；服务端从当前会话取得企业上下文，不接受客户端传入的企业 ID 作为授权依据。
- 任何资源详情、列表、搜索、统计和导出能力均须执行企业隔离和 RBAC 校验，避免仅在页面路由层校验。
- 银行账号、密码、重置凭证、会话令牌不得写入应用日志、审计详情或错误响应；账号展示采用掩码。
- 前端不得以本地角色判断替代后端授权；后端必须校验资源归属和操作角色。
- 接口应对枚举、分页、筛选参数执行白名单和边界校验，防止越权查询及超大分页请求。
- 用户退出、密码重置、账号停用、角色降级后，既有令牌必须立即或在下一次受保护请求时不可继续取得超出新权限的数据。

## 11. 关键流程验收

1. 系统管理员创建银行账户并邀请财务专员、财务经理；两人激活后分别仅看到对应操作入口。
2. 财务专员创建并提交一笔余额充足的转账；财务经理可看到该申请并审批通过。
3. 财务专员执行该申请后，申请状态变为已执行，生成一笔关联支出交易，付款账户余额按金额减少，仪表盘统计同步更新。
4. 财务经理无法审批自己创建的申请；审批过该申请的财务经理无法执行该申请，即使直接调用接口也被拒绝。
5. 任意用户尝试读取另一企业的交易、转账或账户，系统均拒绝且不返回对象存在信息。
6. 对已执行交易创建冲正后，原记录和冲正记录均可查，账户余额和仪表盘统计按冲正结果更新，审计记录完整。
7. 在执行接口重复请求、浏览器重复提交或两个用户同时操作时，只有一次执行成功，不产生重复交易和重复扣款。

## 12. 交付与待确认项

研发交付至少应包括：页面与接口权限校验、数据校验、状态机、审计记录、异常提示、自动化测试（RBAC、企业隔离、职责分离、重复执行、事务回滚）及上述关键流程的联调验证。

以下事项需要业务方在进入银行直连或正式上线前确认：单笔/单日支付限额和超额审批规则、收款账户黑白名单、审批层级与代理审批、余额来源与对账方式、财务凭证规则、审计留存期限和数据合规要求。

## 13. 财务流水自动入账一期（目标：2026 年 9 月）

### 13.1 业务目标与成功口径

自动入账一期面向财务人员对银行流水的整理、复核、模拟制证和追溯工作。系统应将受控来源的流水以批次方式采集，自动完成基础校验和去重，将可处理数据落库，经过人工复核后提交至金蝶云星空模拟网关，并持续展示处理和对账结果。

业务收益目标为：规则稳定且业务量与基准月可比时，在 2026 年 9 月后的首个完整自然月，相比上线前人工下载、整理、录入、核对和追溯流水的实际工时，节省 6-7 人天/月。该指标以财务负责人确认的上线前连续一个自然月工时为基准，按相同口径记录导入、异常处理、复核、制证和追溯工时；不将真实银行接入、金蝶真实接口故障或范围外人工调整计入一期收益。

### 13.2 领域边界

| 领域 | 一期职责 | 明确不承担的职责 |
| --- | --- | --- |
| 自动入账/流水域 | 从文件或模拟来源采集收支流水；校验、去重、落库、复核、金蝶模拟制证、状态追踪、对账和审计追溯 | 发起、审批或执行对外付款；修改银行可用余额；向真实银行或真实金蝶发出请求；自动清分、自动核销或总账结账 |
| 支付/调拨域 | 管理既有付款、转账或内部调拨申请的草稿、审批和执行（按第 7 节规则） | 以导入流水替代支付申请；把已导入流水自动反向生成付款指令；把模拟凭证视为银行付款回执 |
| 银行网关域 | 保留现有中信模拟适配器及未来真实银行适配器的技术边界 | 一期自动入账不调用该网关；不实现真实银行 SDK、API、文件拉取、余额查询、回单查询或清算回执 |
| 金蝶凭证域 | 通过金蝶云星空模拟网关返回模拟凭证编号、状态和消息，验证制证流程 | 调用真实金蝶云星空接口、写入真实账套、上传凭证附件、凭证审核、反审核、过账或结账 |

自动入账的“入账”在一期中定义为：流水作为不可篡改的业务事实落库，复核通过后生成可追溯的金蝶模拟凭证结果。它不等同于银行扣款成功、账户余额变更或真实总账入账。支付/调拨与自动入账仅允许通过展示层面的关联线索（如摘要、外部参考号）进行查询，不得共享状态机或相互更新对方状态。

### 13.3 来源、文件和校验落库

一期仅支持以下受控来源：

- `FILE`：人工上传或导入固定模板的流水文件；前端可将文件解析为统一记录结构后提交，后端以批次接收和处理。
- `MOCK`：测试和演示用途的模拟流水来源，可由用户触发；未提供记录时可生成一条明确标识为模拟的样例流水。

文件格式以研发交付的固定模板为准，不提供动态列映射。每条流水至少应提供：来源流水号、银行账户标识、交易时间、收支方向、金额、币种、交易对手名称、交易对手账号和摘要。金额以正数表示，收支方向决定业务正负口径；本期币种仅允许 `CNY`，金额精度最多两位小数。

系统创建导入批次时生成唯一批次号，记录来源类型、来源名称、提交人、提交时间和处理汇总。流水校验至少包括：

- 必填字段、字段长度、时间格式、收支方向枚举、人民币币种、金额大于零且精度合法。
- 银行账户存在且处于启用状态；流水号在全局范围内唯一。
- 同一批次内重复、与既有流水号重复、账户不匹配、非法金额或缺失必要信息必须被识别。
- 原始载荷在校验后保留，用于复核和追溯；页面、日志、导出和错误信息中均须掩码展示交易对手账号。

有效流水须写入 `statement_record`，初始为“校验通过、待复核、未推送”；校验失败流水若具备可追溯流水号也应落库并标记失败原因，无法形成最小识别信息的行不得写入流水表，但必须计入批次失败统计。重复流水不得产生第二条业务流水或第二次制证机会，应计入重复数并保留可定位的批次处理说明。批次允许部分成功，不因单条失败回滚已校验通过的其他流水。

### 13.4 端到端状态与状态追踪

系统以“批次状态”和“流水三维状态”共同表达处理进度，禁止以单一文案覆盖全部业务含义。

| 对象 | 状态 | 含义与允许流转 |
| --- | --- | --- |
| 导入批次 | `PROCESSING` | 正在采集和校验；完成后进入 `COMPLETED`、`PARTIAL_COMPLETED` 或 `FAILED`。 |
| 导入批次 | `COMPLETED` | 全部输入行均已处理，且无无效或重复行；不可重新导入同一批次。 |
| 导入批次 | `PARTIAL_COMPLETED` | 有至少一条有效落库流水，且存在无效或重复行；可查看明细和异常原因。 |
| 导入批次 | `FAILED` | 未产生有效流水的技术或输入失败；保留错误摘要，可用新批次修正后重试。 |
| 流水校验状态 | `VALID` / `INVALID` / `DUPLICATE` | 自动校验结果；只有 `VALID` 可进入人工复核。`DUPLICATE` 不得有独立的二次制证记录。 |
| 流水复核状态 | `PENDING` / `APPROVED` / `REJECTED` | `VALID` 流水进入 `PENDING`；复核人只能通过或驳回一次，驳回必须填写原因，已通过或驳回的原始流水不可编辑。 |
| 凭证推送状态 | `NOT_PUSHED` / `PUSHING` / `PUSHED` / `PUSH_FAILED` | 仅 `APPROVED` 流水可从 `NOT_PUSHED` 进入 `PUSHING`；成功后为 `PUSHED` 并记录模拟凭证号；失败后为 `PUSH_FAILED`，可在保留失败原因的情况下重试。 |
| 对账状态 | `UNRECONCILED` / `MATCHED` / `MISMATCH` | 对账任务计算后更新。仅核对来源、FINFLOW 流水和模拟制证结果，不得推断真实银行或真实金蝶状态。 |

复核通过后的推送应使用流水号作为幂等业务键。重复点击、网络重试或并发请求最多产生一个 `PUSHED` 状态和一个模拟凭证号；若无法确定远端模拟网关结果，状态必须保留为 `PUSHING` 或 `PUSH_FAILED`，不得虚报成功。每次状态变化均应在流水详情、批次详情和对账视图中可查询。

### 13.5 人工复核与金蝶模拟制证

财务经理在“待我复核”中查看校验通过的流水，核对银行账户、时间、方向、金额、交易对手、摘要、校验信息和脱敏原始载荷后，执行通过或驳回。复核通过可填写意见，驳回必须填写原因。系统必须展示导入人和复核人，且服务端执行导入人与复核人分离校验。

财务专员或系统管理员可将复核通过的流水推送到金蝶云星空模拟网关。模拟网关返回的凭证编号必须包含或关联流水号，且返回结果、时间、推送人和错误消息须持久化。模拟成功仅显示为“模拟凭证已生成”，不得使用“已入账到金蝶”“已过账”或“已付款”等可能误导用户的表述。

金蝶模拟推送失败不影响原始流水和复核结论，也不自动创建新的流水。失败可由有 `voucher:push` 权限的用户重试；已成功推送的流水不得再次推送，除非未来通过独立的冲正/重制证流程审批后处理，本期不提供该流程。

### 13.6 对账、查询与追溯

系统应提供按批次、银行账户、日期范围、来源类型、校验状态、复核状态、推送状态、对账状态和关键字（批次号、流水号、凭证号、交易对手、摘要）查询的列表与详情。列表默认按交易时间倒序分页，组合条件按 AND 关系生效。

对账按批次和指定日期范围汇总以下口径：

- 来源输入总数 = 有效落库数 + 无效数 + 重复数；不相等时标记 `MISMATCH`。
- 有效流水的收入、支出笔数与金额应可分别汇总，并能与复核通过、模拟推送成功的笔数和金额比较。
- 每条 `PUSHED` 流水必须有唯一模拟凭证号；复核通过但未成功推送、凭证缺失、金额/方向不一致或来源与落库关键字段不一致时标记差异类型并显示处置建议。

对账报告必须明确标记“模拟对账”，只比较一期内的来源、流水库和模拟制证结果。它不替代银行余额对账、银行回单核验、真实金蝶凭证查询或法定财务核算。业务查看者可查看汇总和脱敏明细，只有具有对应权限的用户可查看完整原始载荷或执行处理操作。

用户应可从任一流水详情追溯至：导入批次、来源类型与名称、校验结果、复核结论、复核人及时间、模拟凭证号与推送结果、对账状态和全部审计事件；也应能从批次或模拟凭证号反向定位流水。原始流水、复核结论、成功凭证号和审计记录不得物理删除或直接覆盖；需要业务修正时创建新的修正批次并保留关联说明。

### 13.7 数据、权限和审计要求

除第 10 节的通用要求外，自动入账域至少需要持久化以下数据：

- 导入批次：批次号、来源类型/名称、处理状态、输入总数、有效数、重复数、无效数、创建人、开始/完成时间和错误摘要。
- 流水：批次、唯一流水号、银行账户、交易时间、收支方向、金额、币种、对手信息、摘要、经保护的原始载荷、校验结果与原因、复核结果与意见、推送状态、模拟凭证号、推送信息与各环节时间。
- 对账结果：对账范围、执行时间、来源/流水/模拟凭证的笔数和金额汇总、差异类型、差异明细、状态和执行人（或系统任务标识）。
- 审计事件：批次创建/完成/失败、每条流水的校验、重复识别、复核、推送开始/成功/失败/重试、对账执行及权限拒绝。事件应记录操作者、时间、批次号、流水号、前后状态、结果、请求编号和脱敏说明。

账号、原始载荷及可能包含的个人或企业信息须按最小必要原则访问；交易对手账号默认仅展示末四位，完整账号与原始载荷不得出现在普通日志、浏览器本地存储、错误响应或无权限页面。批次、流水、凭证和审计查询均必须进行企业隔离及服务端 RBAC 校验。

### 13.8 验收标准

1. 财务专员使用 `FILE` 来源导入一批含有效、无效和重复行的测试流水后，系统生成唯一批次号；批次统计准确，有效流水可落库，无效行显示字段级原因，重复行不产生第二条流水或第二个制证机会。
2. 使用 `MOCK` 来源且未传入记录时，系统仅生成明确标识为模拟的测试流水；全过程不调用任何真实银行 SDK/API、不会读取真实银行余额、不会变更银行账户余额，也不会产生支付或调拨申请。
3. 校验通过的流水初始为 `PENDING` 和 `NOT_PUSHED`；`INVALID`、`DUPLICATE` 或 `REJECTED` 流水无推送入口，直接调用推送接口被拒绝且无副作用。
4. 导入人尝试复核本人导入的流水时，界面不提供操作入口，服务端返回 `403`；财务经理复核通过/驳回后，系统记录意见、操作人、时间和不可篡改的审计事件。
5. 有推送权限的用户仅能推送复核通过且未成功推送的流水。金蝶模拟网关成功后返回唯一模拟凭证号并更新为 `PUSHED`；重复请求、刷新或并发请求不产生多个凭证号。
6. 模拟推送失败时，流水保持已复核，推送状态为 `PUSH_FAILED` 并保存脱敏失败原因；重试成功后可追溯全部失败和重试事件，且只保留一个成功凭证号。
7. 对账可按批次和日期范围输出来源、已落库、已复核、已模拟制证的笔数与收支金额；数目、金额、凭证或关键字段不一致时标记 `MISMATCH` 并定位到具体流水。
8. 从流水号、批次号或模拟凭证号中的任一入口可双向追溯完整处理链路。审计事件包含所需操作者、时间、状态、结果和请求编号，账号和原始载荷在默认视图与日志中保持脱敏。
9. 四类角色对自动入账列表、导入、复核、推送和对账的页面及接口权限均符合第 3.2 节；篡改企业 ID、批次 ID、流水 ID、凭证号或查询参数均不得越权访问其他企业数据。
10. 在业务量和处理范围与基准月可比的前提下，财务负责人以第 13.1 节口径完成一个自然月的工时复盘；自动入账流程的人工工时较基准减少 6-7 人天/月，或对未达标原因、补偿措施和后续优化负责人形成书面结论。

### 13.9 研发交付边界

研发应在既有 `statement` 领域、导入批次、流水、审计事件、来源采集器和金蝶模拟网关的目录边界内完成一期实现；支付/调拨与银行网关继续保持独立。交付内容至少包括受控文件/模拟来源、批次与流水 API、状态机与幂等控制、复核工作台、金蝶模拟网关、对账视图、追溯查询、数据迁移、服务端权限校验、审计记录和本节验收用例的自动化测试。

真实银行 SDK/API、银行文件自动拉取、真实金蝶云星空接口、真实凭证创建和真实银行/总账对账均作为后续独立模块立项、设计、联调和验收；不得通过关闭模拟开关或复用一期接口将其隐式纳入本期。

## 14. 连接与运营模块（一期为未启用/模拟状态）

### 14.1 产品定位与领域边界

“连接与运营”是与“资金管理”和“自动入账”并列的独立工作台模块，面向未来银行直联的配置管理、任务可观测性和只读数据查询。它不改变既有支付/调拨状态机，也不替代自动入账的文件/模拟来源、校验、人工复核、金蝶模拟制证、对账与审计闭环。

一期（目标 2026 年 9 月）仅交付页面结构、权限模型、模拟任务/查询结果和明确的未启用状态，不接入真实银行 SDK、真实银行 API、证书、签名、自动拉取、真实余额、流水、回单或对账单接口。银行 SDK、示例和 API 由后续单独模块提供后，再进行适配器设计、沙箱联调、安全评审和独立验收。

连接与运营与自动入账的边界如下：

| 子域 | 一期职责 | 明确不承担的职责 |
| --- | --- | --- |
| 直联管理 | 展示未来接入的应用、签约和个性化配置模型；支持模拟配置状态 | 保存或使用真实密钥/证书；调用真实银行；改变账户余额或支付状态 |
| 监控与日志 | 展示模拟连接状态、模拟任务执行记录、请求编号、耗时、结果和可安全公开的错误摘要 | 伪造真实银行成功；记录或展示凭据、签名原文、完整账号和内部堆栈 |
| 数据查询 | 提供余额、流水、回单、对账单、支付记录、代发六类查询入口；无真实来源时展示未启用/模拟结果 | 将模拟数据当作银行事实；执行支付、下载真实回单、修改余额或生成入账凭证 |
| 自动入账 | 继续负责文件/模拟来源导入、校验落库、人工复核、金蝶模拟制证、对账和追溯 | 不因连接与运营页面存在而隐式接入银行或把查询结果自动制证 |

### 14.2 业务对象与一期状态

连接与运营采用独立的运营对象，不复用支付/调拨申请、自动入账批次或流水的主键、状态和审计事件。每个对象必须包含企业 ID、创建/更新人、创建/更新时间、状态和不可重复的业务编号；对象之间只允许以受控外键或只读引用关联。

| 业务对象 | 关键字段 | 一期状态与边界 |
| --- | --- | --- |
| 直联应用 | 应用编号、名称、目标银行、环境、所属企业、模拟标记、配置摘要 | `UNAVAILABLE`、`SIMULATED`、`DISABLED`；不得出现 `CONNECTED` 或保存真实 App ID、密钥、证书。 |
| 签约记录 | 签约编号、签约主体、银行、协议类型、有效期、关联应用、模拟标记 | `UNAVAILABLE`、`SIMULATED`、`EXPIRED`；仅表达未来签约准备度，不代表银行签约生效。 |
| 个性化设置 | 设置编号、适用账户范围、查询展示项、模拟任务频率、通知偏好 | `ACTIVE`、`DISABLED`；只影响 FINFLOW 的展示或模拟任务，不得修改银行侧配置。 |
| 连接状态快照 | 应用、环境、采样时间、状态、最近任务、失败摘要 | `UNAVAILABLE`、`SIMULATED_HEALTHY`、`SIMULATED_FAILURE`；不记录真实心跳或真实银行可用性。 |
| 运营任务 | 任务编号、类型、关联应用、模拟输入范围、幂等键、开始/完成时间、结果摘要 | `PENDING`、`RUNNING`、`SUCCEEDED`、`FAILED`、`MANUAL_ACTION_REQUIRED`、`CANCELLED`；任务仅生成模拟运营结果。 |
| 运营日志 | 请求编号、任务、事件时间、级别、结果、脱敏摘要 | 仅追加；不可记录访问令牌、签名、私钥、完整账号、完整响应或堆栈。 |
| 查询快照 | 查询编号、资源类型、账户授权范围、筛选条件摘要、生成时间、来源标记 | `UNAVAILABLE`、`SIMULATED`、`EMPTY`；只读、可过期，不构成银行事实或自动入账来源。 |
| 数据查询结果 | 余额、流水、回单、对账单、支付记录或代发的脱敏展示行 | 只能从查询快照取得；不得修改支付/调拨、账户、自动入账流水或模拟凭证。 |

`UNAVAILABLE` 是一期默认状态，表示尚未接入真实直联；`SIMULATED` 及其派生状态必须有可见标签和模拟来源说明。系统不得通过用户配置、任务重试或路由参数将上述对象切换为真实已连接状态。真实连接状态仅能在后续独立模块经授权沙箱验收后启用。

### 14.3 信息架构、路由与权限

侧栏分组固定为：

```text
资金管理
├── 转账
└── 交易记录

自动入账
├── 流水导入
├── 导入批次
├── 人工复核
├── 金蝶制证
└── 对账与追溯

连接与运营
├── 直联管理
│   ├── 应用管理
│   ├── 签约管理
│   └── 个性化设置
├── 监控与日志
│   ├── 直联状态监控
│   ├── 任务执行
│   └── 日志查询
└── 数据查询
    ├── 余额查询
    ├── 流水查询
    ├── 回单查询
    ├── 对账单查询
    ├── 支付记录查询
    └── 代发查询
```

建议路由及权限编码如下。每个路由都要求用户已登录；权限判断由服务端执行，前端导航隐藏只是可见性优化：

| 页面 | 路由 | 权限 | 默认可见角色 |
| --- | --- | --- | --- |
| 应用管理 | `/connections/apps` | `connection:view`；管理动作需 `connection:manage` | 系统管理员 |
| 签约管理 | `/connections/contracts` | `connection:view`；管理动作需 `connection:manage` | 系统管理员 |
| 个性化设置 | `/connections/preferences` | `connection:view`；保存需 `connection:manage` | 系统管理员 |
| 直联状态监控 | `/operations/connections` | `operation:monitor` | 系统管理员或后续运维角色 |
| 任务执行 | `/operations/tasks` | `operation:monitor` | 系统管理员或后续运维角色 |
| 日志查询 | `/operations/logs` | `operation:log:view` | 系统管理员或后续运维角色 |
| 余额/流水/回单/对账单/支付记录/代发查询 | `/data/{resource}` | `data:query` | 四类企业角色按账户授权只读 |

“连接与运营”父分组仅在用户至少拥有一个子页面权限时展示；每个子项按自身权限展示。无权限用户通过深链接访问统一进入 403，不能因为拥有 `data:query` 而看到直联管理或监控写入动作，也不能因为拥有 `reconciliation:view` 而获得连接或数据查询权限。

### 14.4 页面行为与关键状态

#### 直联管理

应用管理展示应用名称、所属企业、目标银行/环境、启用状态、最近配置时间和操作人；签约管理展示签约主体、银行、协议状态、有效期和关联应用；个性化设置展示查询范围、任务频率、通知偏好和展示配置。真实密钥、证书私钥、签名材料和完整回调地址不在页面展示；一期所有连接状态统一标注“未启用”或“模拟”。

- 加载：使用稳定的表头和表单骨架，不在权限确认前短暂展示管理操作。
- 空状态：分别提示“尚未配置直联应用”和“当前筛选无配置”，提供仅在有 `connection:manage` 时可见的模拟配置入口。
- 未启用：展示原因、适用范围和后续接入说明；“连接测试”“启用直联”“同步银行配置”等动作置为不可用或隐藏，不提供虚假的成功反馈。
- 模拟：明确显示“模拟配置/模拟环境”，模拟变更仅影响本系统演示数据，不触发银行请求。
- 失败：保留筛选和已加载结果，显示请求编号和局部重试；不展示凭证或内部堆栈。

#### 监控与日志

直联状态监控展示连接标识、环境、状态、最近心跳、最近成功/失败时间和失败次数；任务执行展示任务类型、来源、开始/完成时间、耗时、批次或查询范围、状态和重试次数；日志查询支持按时间、应用、任务、请求编号、结果和错误类型筛选。日志默认脱敏，只展示排障所需的安全摘要。

状态至少包括“未启用、模拟正常、运行中、成功、失败、需人工处理”。运行中任务不可通过刷新页面伪造完成；重试必须受权限、幂等键和服务端状态约束。监控和日志的查询本身也要记录审计事件，但读取日志不得再次写入被查询的业务结果。

#### 数据查询

六类页面统一采用截图所示的“查询条件区 + 查询/重置 + 结果表格 + 详情抽屉”结构。支持日期范围、账户、来源/应用、金额区间、方向、状态和业务编号等适用筛选，组合条件按 AND 生效，服务端分页、排序和查询边界由白名单控制。

一期无真实银行来源时，页面顶部和结果区域必须同时显示“未启用真实银行直联”或“模拟数据”标识；结果为空时区分“当前账期尚无模拟结果”“当前筛选无结果”和“真实直联尚未启用”。查询结果只读，不提供支付、改余额、改流水、生成回单或直接制证动作。流水查询可跳转自动入账的追溯详情，但不得把连接查询结果标记为已导入、已复核或已制证。

账号、对方账号、回单文件名中的敏感信息默认只显示末四位或不可逆掩码；完整原始响应、签名、证书、访问令牌和银行返回的敏感字段不得进入浏览器本地存储、普通日志、错误响应或无权页面。导出能力一期默认关闭；未来开放时仍需单独权限、二次确认、字段脱敏和审计。

### 14.5 审计、错误与验收标准

连接与运营至少审计：应用/签约/个性化配置创建、修改、启停和模拟变更；任务创建、开始、成功、失败、重试和取消；日志/查询/导出访问；权限拒绝及配置校验失败。每条记录包含操作者、企业、时间、对象、动作、前后状态、结果、请求编号和脱敏摘要。审计记录只允许追加，不能由页面编辑或删除。

验收标准：

1. 侧栏按“直联管理、监控与日志、数据查询”展示独立模块；现有资金管理和自动入账入口及定义保留，三者不共享业务状态机。
2. 四类角色按 `connection:*`、`operation:*` 和 `data:query` 进行最小权限控制；无权限导航隐藏，深链接返回 403，服务端接口不能仅依赖前端隐藏。
3. 应用管理、签约管理和个性化设置在一期均能明确显示“未启用/模拟”，任何保存或测试动作均不会调用真实银行 SDK/API。
4. 监控与日志能展示模拟任务的运行中、成功、失败、重试和需人工处理状态；刷新、重复点击或重试不会伪造完成或产生重复任务结果。
5. 六类数据查询具备筛选、分页、加载、空数据、失败和详情状态；未启用真实直联时不伪造银行余额、流水、回单、对账单、支付记录或代发结果。
6. 查询和详情按企业、账户和角色范围过滤，账号及敏感响应默认脱敏；越权访问不泄露对象存在性，读取、配置和失败事件均可在审计中追溯。
7. 自动入账仍以文件/模拟来源完成导入、校验、复核、金蝶模拟制证、对账闭环；连接与运营页面不得自动创建流水、付款指令或模拟凭证。

### 14.6 后续接入决策

真实银行 SDK/API 接入作为连接与运营的后续独立版本：先确定银行适配器契约、凭据托管、证书轮换、签名验签、超时重试、回执幂等、限额和审计要求，再在授权沙箱完成联调和安全验收。接入完成前，任何“直联成功”“银行余额”“银行回单”和“已同步”文案均不得用于一期真实业务语义。
