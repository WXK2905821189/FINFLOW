# 企业财务管理平台产品需求与验收标准

## 1. 文档目的与范围

本文定义企业财务管理平台首期（MVP）的功能需求、权限边界和验收标准，供产品、研发、测试和验收共同使用。

当前项目目录未提供已有需求、原型或接口说明。以下内容按“单企业租户、人民币资金管理、银行转账需审批”的业务基线制定；未明确部分以本文为准，涉及银行直连、真实清算、电子签章、发票和多币种的能力不在本期范围内。

### 1.1 目标

- 让受控用户完成账户、收支和转账的日常操作。
- 通过最小权限与审批机制降低未经授权的资金操作风险。
- 保留可追溯的交易记录、异常处理和审计证据。

### 1.2 本期不包含

- 银行 API 直连、自动扣款或向外部银行实际发起付款。
- 多企业租户、多币种、汇率换算、总账核算、税务申报和发票管理。
- 单点登录（SSO）、双因素认证、电子签章和批量导入/导出。
- 自助注册后自动获得企业数据访问权。

## 2. 术语与状态

| 术语 | 定义 |
| --- | --- |
| 企业 | 平台中的数据隔离单元。本期每个账户仅归属一个企业。 |
| 银行账户 | 企业名下可用于记录余额及发起转账的账户。 |
| 交易 | 一笔收入、支出或转账产生的资金流水。 |
| 转账申请 | 用户提交、等待审批或执行的内部支付指令。 |
| 操作人 | 对资金或数据进行操作的登录用户。 |
| 审批人 | 对转账申请执行通过或驳回的有权用户。 |

### 2.1 转账状态

| 状态 | 含义 | 可转移状态 |
| --- | --- | --- |
| 草稿 | 创建人暂存，尚未提交 | 待审批、已取消 |
| 待审批 | 已提交，等待审批人处理 | 已批准、已驳回、已取消 |
| 已批准 | 审批通过，等待财务执行 | 已执行、已取消 |
| 已驳回 | 审批不通过，保留原因 | 草稿 |
| 已执行 | 财务已确认完成记账 | 无 |
| 已取消 | 创建人或有权人员终止申请 | 无 |

已执行、已取消的申请不可编辑、删除或恢复；错误数据通过新增冲正交易处理，不得覆盖历史记录。

## 3. 用户角色与 RBAC

### 3.1 角色定义

| 角色 | 职责 | 数据范围 |
| --- | --- | --- |
| 系统管理员 | 管理企业用户、角色和银行账户配置 | 本企业全部数据与配置 |
| 财务专员 | 维护交易、创建转账、执行已批准的转账 | 本企业财务数据 |
| 财务经理 | 审批转账、查看资金经营情况与全部交易 | 本企业财务数据 |
| 业务查看者 | 查看已授权的仪表盘、银行账户余额和交易 | 本企业只读财务数据 |

默认不提供跨企业管理员。系统初始化时应至少存在一名系统管理员；管理员不可删除或停用自身，除非企业内另有启用状态的系统管理员。

### 3.2 权限矩阵

| 功能/动作 | 系统管理员 | 财务专员 | 财务经理 | 业务查看者 |
| --- | ---: | ---: | ---: | ---: |
| 查看仪表盘 | 是 | 是 | 是 | 是 |
| 查看交易记录与明细 | 是 | 是 | 是 | 是 |
| 新增/编辑草稿交易 | 是 | 是 | 否 | 否 |
| 新增冲正交易 | 是 | 是 | 是 | 否 |
| 管理银行账户 | 是 | 否 | 否 | 否 |
| 创建、编辑、取消本人草稿转账 | 是 | 是 | 否 | 否 |
| 提交本人转账 | 是 | 是 | 否 | 否 |
| 审批转账 | 否 | 否 | 是 | 否 |
| 执行已批准转账 | 是 | 是 | 否 | 否 |
| 管理用户与角色 | 是 | 否 | 否 | 否 |
| 查看操作审计记录 | 是 | 否 | 是 | 否 |

RBAC 必须在服务端执行，前端菜单隐藏不构成权限控制。无权限请求返回 `403`，且不得在响应中泄露资源是否存在、账户余额、用户信息或交易明细。

### 3.3 职责分离规则

- 转账创建人不得审批自己创建的转账，无论其是否同时具有审批角色。
- 转账审批人不得执行自己审批通过的转账。
- 已执行转账不得被任何角色修改或删除。
- 管理员可管理用户及银行账户，但不默认获得“审批转账”权限；审批必须使用财务经理角色。

## 4. 登录与注册

### 4.1 登录

用户通过“邮箱/用户名 + 密码”登录。成功后进入仪表盘，并仅加载其所属企业及权限范围内的数据。

登录页必须提供：账号输入、密码输入、显示/隐藏密码、登录按钮、注册链接、忘记密码入口。错误提示统一为“账号或密码错误”，不得区分账号不存在、密码错误或账号已停用。

### 4.2 注册与账号激活

- 自助注册仅创建“待激活”账号，不关联任何企业、不授予任何角色、不可查看任何财务数据。
- 注册字段：姓名、工作邮箱、密码、确认密码；邮箱必须唯一，密码至少 8 位，且同时包含字母和数字。
- 管理员通过用户管理创建或激活企业成员，分配角色后该用户才可登录企业系统。
- 已停用账号无法登录；已登录会话在下一次鉴权时失效。
- 忘记密码采用一次性、限时的重置凭证；重置成功后所有既有会话失效。

### 4.3 验收标准

- 正确账号密码可登录并跳转仪表盘；错误组合仅显示统一错误信息。
- 未激活注册用户登录时无法访问任何企业页面或接口。
- 停用用户重新登录失败，且使用旧会话访问受保护接口返回未认证或无权限。
- 密码不满足规则时无法提交注册或重置；系统不得存储或返回明文密码。
- 任一受保护页面在未登录状态访问时跳转登录页；登录后回到原目标页面（若该页面有权限）。

## 5. 仪表盘

### 5.1 功能需求

仪表盘是登录后的默认页面，按当前用户权限展示本企业的资金概览。展示数据至少包括：

- 全部启用银行账户的当前余额合计。
- 各银行账户名称、账号掩码、余额和最后更新时间。
- 当前自然月收入、支出、净现金流。
- 待审批转账数量及金额；仅财务经理可看到“待我审批”的列表入口。
- 最近 10 笔交易：日期、类型、摘要、金额、状态、关联转账编号（如有）。
- 近 6 个自然月的收入、支出和净现金流趋势。

统计口径：收入为已入账收入交易总额；支出为已入账支出交易总额；已取消或失败的交易不计入；净现金流 = 收入 - 支出。金额统一按人民币显示，保留两位小数，并使用千分位。

### 5.2 验收标准

- 无数据企业可正常打开仪表盘，金额显示 `0.00`，列表显示空状态，不出现错误或虚构数据。
- 仪表盘金额与交易记录中相同筛选范围的已入账交易汇总一致。
- 业务查看者可查看概览和交易摘要，但不出现新增、审批、执行、用户管理等操作入口。
- 财务经理仅可看到由他人创建、且状态为待审批的申请；本人创建的申请不应进入“待我审批”。
- 银行账户号码在任何仪表盘视图中最多显示末四位，其余字符掩码处理。

## 6. 用户管理

### 6.1 功能需求

仅系统管理员可访问用户管理。页面支持用户列表、搜索和状态筛选，并可查看姓名、邮箱、角色、状态、创建时间、最近登录时间。

管理员可：邀请/创建企业成员、编辑姓名和角色、启用/停用账号、重新发送激活邀请。邮箱作为身份标识不可直接修改；如需变更，应创建变更申请并保留审计记录（本期可由管理员停用旧账号并新建账号替代）。

停用账号前，系统必须提示该用户是否为唯一系统管理员、是否有未完成的转账草稿或待审批任务。唯一系统管理员不可停用；存在未完成任务时允许停用但必须显示风险提示，原任务不自动转移。

### 6.2 验收标准

- 非系统管理员访问用户管理页面或接口，均被拒绝。
- 新建/邀请成员后，成员在激活并获分配角色前不可访问企业数据。
- 管理员修改角色后，新权限在该用户下次接口请求时生效，不依赖重新发布系统。
- 系统阻止停用企业内唯一的启用系统管理员。
- 每次创建、角色变更、启停、邀请重发均记录操作者、时间、目标用户、变更前后值和结果。

## 7. 银行账户与转账

### 7.1 银行账户

系统管理员可维护银行账户：账户名称、开户行、账户号、账户类型、币种（本期固定 CNY）、期初余额、启用状态。账户号必须在保存前校验非空和格式合法；存储及日志中必须脱敏，前端展示仅显示末四位。

停用银行账户后，不可用于新建转账，但历史交易和关联申请仍可查询。存在待审批或已批准转账时，系统不允许停用该账户。

### 7.2 创建与提交转账

系统管理员和财务专员可创建转账草稿，必填字段包括：付款账户、收款方名称、收款账号、收款银行、转账金额、用途/摘要、计划付款日期。金额必须大于 0，最多两位小数，且不超过付款账户可用余额。

草稿仅创建人可编辑和取消。提交时再次校验字段完整性、付款账户启用状态、可用余额及收款账号格式。提交成功后生成不可重复的转账编号，状态变为待审批，并记录提交时间。

### 7.3 审批与执行

- 财务经理可对待审批申请执行通过或驳回；驳回必须填写原因，通过可填写意见。
- 系统必须阻止创建人审批自己的申请。
- 审批通过后状态变为已批准；驳回后状态变为已驳回，创建人可复制/重新编辑为草稿并再次提交。
- 系统管理员或财务专员可执行已批准申请，执行时再次校验付款账户状态和余额；执行人不得为该申请的审批人。
- 执行成功后，系统生成一笔已入账支出交易并关联转账编号，扣减付款账户余额，申请状态变为已执行。
- 因余额不足、账户停用或并发状态变化而无法执行时，不生成交易、不改变余额，申请保持已批准并记录失败原因。

### 7.4 验收标准

- 转账必填字段缺失、金额为零/负数/超过两位小数、余额不足或付款账户已停用时，系统阻止保存或提交并指出对应字段。
- 同一转账在并发提交或刷新后只生成一个有效转账编号和一条申请记录。
- 创建人尝试审批本人申请，或审批人尝试执行本人审批的申请时，界面无操作入口且服务端返回 `403`。
- 已批准转账仅可被执行一次；重复执行请求不得重复扣款或生成重复交易。
- 执行成功后，转账、交易和账户余额三者的数据一致，且可通过转账编号相互追溯。
- 已驳回、已取消、已执行申请均不可编辑金额、收款信息或付款账户。

## 8. 交易记录

### 8.1 功能需求

交易记录展示企业全部资金流水，字段包括交易编号、交易日期、类型（收入/支出/冲正）、银行账户、摘要、对方信息、金额、状态、关联转账编号、创建人和创建时间。

支持按日期范围、交易类型、银行账户、状态、关键字（交易编号/摘要/对方名称）筛选，支持按交易日期倒序分页。默认展示最近 30 天交易。

交易创建或转账执行后不得直接物理删除。发现已入账交易错误时，系统管理员、财务专员或财务经理可创建金额相反且引用原交易编号的冲正交易；原交易与冲正交易均保留并可相互跳转。

### 8.2 验收标准

- 任一筛选条件只返回当前企业内满足条件的记录；组合筛选按 AND 关系生效。
- 分页结果稳定，无重复或漏项；切换页码和筛选条件后汇总与列表一致。
- 用户无法通过交易编号、查询参数或接口访问其他企业的交易。
- 已入账交易不提供编辑或删除能力；冲正后历史交易仍可查询，并清晰显示关联关系。
- 由转账执行生成的交易不可手工取消、删除或解除关联。

## 9. 异常处理与审计

### 9.1 业务异常

| 场景 | 系统行为 | 用户可见信息 |
| --- | --- | --- |
| 无权限访问 | 拒绝请求并记录安全审计 | 无权执行此操作 |
| 会话失效 | 清除会话并跳转登录 | 登录已失效，请重新登录 |
| 并发审批/执行 | 以最新有效状态为准，只允许一次成功 | 该申请状态已变化，请刷新后重试 |
| 余额不足 | 不提交/不执行资金操作 | 可用余额不足 |
| 数据校验失败 | 不落库，不产生半成品业务数据 | 对应字段的明确校验提示 |
| 系统故障 | 回滚同一事务内的数据变更，记录错误详情 | 操作未完成，请稍后重试（含请求编号） |

所有涉及余额扣减、转账状态变更和交易创建的操作必须使用原子事务；任一步失败时，不得出现“已扣余额但无交易”或“已执行但余额未变”的中间状态。

### 9.2 审计要求

系统至少记录登录成功/失败、登出、用户和角色变更、银行账户变更、转账创建/提交/审批/执行/取消、交易创建/冲正、权限拒绝及系统异常。每条审计记录必须包含：事件时间、操作者 ID、企业 ID、操作类型、目标资源 ID、请求结果、请求编号、变更前后摘要（适用时）。

审计记录仅允许追加，不允许通过业务页面修改或删除。本期保留期限不少于 365 天。

## 10. 权限与数据边界

- 所有业务表和查询必须具备企业 ID；服务端从当前会话取得企业上下文，不接受客户端传入的企业 ID 作为授权依据。
- 任何资源详情、列表、搜索、统计和导出能力均须执行企业隔离和 RBAC 校验，避免仅在页面路由层校验。
- 银行账号、密码、重置凭证、会话令牌不得写入应用日志、审计详情或错误响应；账号展示采用掩码。
- 前端不得以本地角色判断替代后端授权；后端必须校验资源归属和操作角色。
- 接口应对枚举、分页、筛选参数执行白名单和边界校验，防止越权查询及超大分页请求。
- 用户退出、密码重置、账号停用、角色降级后，既有令牌必须立即或在下一次受保护请求时不可继续取得超出新权限的数据。

## 11. 关键流程验收

1. 系统管理员创建银行账户并邀请财务专员、财务经理；两人激活后分别仅看到对应操作入口。
2. 财务专员创建并提交一笔余额充足的转账；财务经理可看到该申请并审批通过。
3. 财务专员执行该申请后，申请状态变为已执行，生成一笔关联支出交易，付款账户余额按金额减少，仪表盘统计同步更新。
4. 财务经理无法审批自己创建的申请；审批过该申请的财务经理无法执行该申请，即使直接调用接口也被拒绝。
5. 任意用户尝试读取另一企业的交易、转账或账户，系统均拒绝且不返回对象存在信息。
6. 对已执行交易创建冲正后，原记录和冲正记录均可查，账户余额和仪表盘统计按冲正结果更新，审计记录完整。
7. 在执行接口重复请求、浏览器重复提交或两个用户同时操作时，只有一次执行成功，不产生重复交易和重复扣款。

## 12. 交付与待确认项

研发交付至少应包括：页面与接口权限校验、数据校验、状态机、审计记录、异常提示、自动化测试（RBAC、企业隔离、职责分离、重复执行、事务回滚）及上述关键流程的联调验证。

以下事项需要业务方在进入银行直连或正式上线前确认：单笔/单日支付限额和超额审批规则、收款账户黑白名单、审批层级与代理审批、余额来源与对账方式、财务凭证规则、审计留存期限和数据合规要求。
