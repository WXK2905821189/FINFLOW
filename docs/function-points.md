## 一、登录与会话（进入系统）

> 所有业务功能以"登录成功"为前提；账号、企业、角色、权限由后端统一鉴权，前端按权限渲染菜单。

1. **✅ 登录**：账号 + 密码登录，后端签发会话令牌；失败返回统一安全提示（不暴露"账号不存在/密码错误"等可枚举信息），停用账号拒绝登录；登录与会话写脱敏审计。
2. **✅ 退出登录**：`/logout` 撤销当前会话；前端可随时登出。
3. **✅ 账号开通（管理员限定）**：公开注册已关闭（P0 收敛，匿名注册直接 401）；创建用户需 `user:manage` 权限（管理员开通）。
   - ⚠️ 上线注意：V1 迁移无管理员种子，生产环境需先注册首个管理员账号，再启用本收紧策略。
4. **✅ 当前用户/权限查询**：`/api/auth/me` 返回当前用户信息，前端据此渲染菜单与按钮；越权请求后端返回 401/403。
5. **◻️ 首次登录强制改密 / 自助改密**：PRD 要求"首次初始化管理员强制改密 + 密码复杂度/失败次数限制"；当前未见独立改密/重置密码端点与页面，需补充或经管理员重置。

## 二、工作台（今天要处理什么）

> 登录后首屏，定位为"待办优先"：先看需要人处理的数字，再看整体进度。

1. **✅ 处理概览**：汇总当前企业授权范围内的待办数字（采集流水量、待复核、入账失败、已制证金额等）；接口未接入/失败显示 `--`，不拿本地演示值补齐，无权限显示安全提示。
2. **◻️ 待办清单细化**：PRD 期望工作台细化到"采集失败、待复核、入账失败、对账差异、结账阻断"分项可点击下钻；当前以概览卡片为主，分项下钻待完善。

## 三、银行接入与数据查询（拿数）

> 对应产品导航"银行接入"一级菜单（连接配置 / 银行账户 / 采集运营 / 数据查询四级子菜单）。当前全部基于 MOCK Adapter（CITIC_MOCK、CMB_MOCK、通用 MOCK），真实银行直联未启用，页面持续显示"真实银行直联未启用 / 模拟数据"。

1. **✅ 银行连接管理**：受控管理银行连接的元数据与模拟标记（页面明确"一期不建立真实银行连接"），浏览器不读取/保存密钥、证书或令牌。
2. **✅ 签约准备与采集设置**：展示银行签约准备度（四件套等）与采集配置摘要；不代表银行签约已生效。
3. **✅ 银行账户管理**：账户 CRUD 与启停（历史 `bank` 兼容面，需 `bank:view`，不参与新模块引用）。
4. **✅ 每日定时采集**：`BankDataSyncScheduler` 定时任务已实现，按企业/账户/日期窗口拉取流水；任务走统一状态机（CREATED→QUEUED→RUNNING→SUCCESS/FAILED/PARTIAL_SUCCESS…8 态）。
5. **✅ 手动补采**：授权人员对指定账户 + 日期窗口手动补采，与定时采集共用任务状态机、幂等键、请求号、并发锁与审计；重复触发不产生重复业务事实。
6. **✅ 采集任务/连接监控/失败日志**：任务详情可查触发方式、窗口、处理数、重复数、异常数、耗时、请求号与脱敏错误；日志默认最近 24 小时。
7. **✅ 五类银行数据只读查询**：余额、流水、回单、对账单、代发——统一表格 + 服务端分页 + 筛选 + 来源追溯（任务号/请求号），结果明确标注"模拟数据"；余额未获取显示 `--`，不伪造 `0.00` 或"成功"。
8. **✅ 原始数据留痕与 30 天清理**：原始请求/响应与同步日志先落库（`bank_data_raw_message`），`BankDataRawRetentionScheduler` 按 30 天保留期清理；追溯不因转换失败丢失原始引用。
9. **⏳ 真实银行直联（中信/招行）**：等待银行测试包/白名单（红线 9/10），排期 9/18 联通 + 联调报告；真实 SDK 未通过准入前 Adapter 必须快速失败，不得回退成"成功"。

## 四、流水中心（数据治理与人工复核）

> 用户在此确认"流水是否可信、完整、可复核"，是自动入账前的质量闸口。

1. **✅ 导入流水**：批量导入入口，生成导入批次（`statement_import_batch`），支持来源追溯。
2. **✅ 标准流水**：统一标准化后的流水列表（`statement_record`），按主体/账户/币种/账期/状态/关键字组合筛选 + 服务端分页稳定排序。
3. **✅ 数据校验**：格式/字段/账户/金额/方向/日期/重复/业务规则校验；结果分 VALID / INVALID / DUPLICATE / PENDING_REVIEW，异常带安全原因码与处理建议；金额定长精度，非法值进异常不静默修正。
4. **✅ 人工复核**：复核通过/驳回/转人工，全部审计；复核人不得复核本人导入的记录。
5. **✅ 校验规则与科目往来映射**：`/validation` 页面管理规则与映射，支持版本化激活（activate）；唯一匹配才可自动生成凭证草稿，无匹配/多匹配/冲突转人工。
6. **◻️ 去重降级规则配置界面**：组合键去重逻辑已实现，但"缺少稳定流水号时使用经评审组合键并标记降级规则"的配置可见性/界面化待完善。

## 五、金蝶入账（出凭证）

> 用户在此把"校验通过的流水"变成"会计凭证"。当前为**金蝶模拟网关**制证，凭证带模拟标记，不代表真实金蝶已入账。

1. **✅ 凭证草稿与制证**：对满足入账规则的流水生成收/付款凭证草稿并推送模拟网关；凭证携带映射企业/账簿/科目/往来/银行账户/来源流水号与幂等键、请求号。
2. **✅ 入账结果与失败重试**：成功/失败/超时/未知状态可查；未知结果不盲目二次建凭证；失败可人工重试，链路（流水号↔凭证号↔请求号）双向可追溯。
3. **✅ 高风险金额/关键字段缺失转人工**：仅已批准规则可自动通过；高金额、未知对方、规则冲突强制人工复核。
4. **⏳ 金蝶真实网关替换 Mock**：排期 9/5 前提交 OpenAPI 开通申请、9/11 联调（凭证入测试账套）；真实接入需接口文档/测试账套/凭证规则/账号权限另行验收。

## 六、对账与结账（闭环）

> 用户在此确认"本期账是否闭环"，是结账前的最后闸口。

1. **✅ 三方对账总览**：`/reconciliation/dashboard` 按银行标准流水 / FINFLOW 业务流水 / 金蝶凭证口径核对（MOCK 口径），展示差异总览。
2. **✅ 账期检查与结账**：`/closing` 按账期（period）执行检查（check）与结账（close）；结账前须满足采集完成、异常有结论、差异有归属、入账可追溯；结账后关键记录不可覆盖。
3. **◻️ 差异清单细粒度处理**：PRD 要求差异类型化（缺流水/重复/金额差异/方向差异/缺凭证/状态不一致…）并可认领/说明/复核/关闭；当前以总览与结账闸口为主，差异逐条处理闭环待细化。

## 七、协同通知（飞书）

> 飞书是"通知 + 触达渠道"，不是数据主库；消息回链接必须在 FINFLOW 登录 + 权限校验后才能处理。当前为 MOCK 消息网关。

1. **✅ 飞书连接配置（模拟）**：管理 MOCK 应用/连接配置，明确安全边界（密钥不进代码/数据库明文/前端/日志）。
2. **✅ 接收对象与通知策略**：配置接收对象与通知策略（通知开关、接收角色/群组、事件模板）。
3. **✅ 发送记录与重试**：通知事件幂等发送、失败重试、发送记录查询（`notification_*` 表族）；消息脱敏，不含完整账号/密钥/身份证/敏感金额明细。
4. **✅ 事件触发面**：采集失败、任务部分成功、流水待复核、入账失败等事件具备触发通知的落点（MOCK 验证）。
5. **⏳ 飞书真实应用接入**：需企业管理员授权 App ID/Secret、机器人/群组权限、事件订阅与出口网络，当前未启用。

## 八、系统管理（谁能访问、怎么配置）

> 管理员视角：管人、管权限、管审计。

1. **🟡 用户与角色管理（前端占位）**：后端 `/api/users`、`/api/rbac`（角色/权限/映射）完整保留；前端 `/users` 已收敛为受控占位入口（提示"用户管理入口已保留，银行接入权限不提升用户管理权限"），完整管理界面暂未开放——影响：管理员暂无法经界面创建/停用用户，需走 API 或待 UI 恢复。
2. **✅ RBAC 权限强制**：后端按权限标识强制鉴权（31 项权限目录，见 `docs/permission-catalog.md`），前端菜单按权限渲染；越权 401/403 且不泄露资源存在性。
3. **✅ 企业（租户）数据隔离**：`CompanyScopeService` + `company` 表实现后端企业范围隔离，跨企业 ID 不可读/写/推断；**◻️ 企业管理前端页面**未建（多企业由后端支撑，无独立管理界面）。
4. **✅ 审计中心**：登录、权限拒绝、连接变更、同步、复核、入账、对账、飞书发送、结账均落审计；`/audit` 按角色提供脱敏审计查询。
5. **⏳ 试用账号/角色/31 项权限分配**：排期 9/18 前随部署完成（涉及部署侧 + 管理员协作）。

## 九、退出与安全收尾

1. **✅ 登出**：见"一、登录与会话"第 2 条。
2. **✅ 会话失效保护**：停用用户/高风险权限变更按会话策略撤销既有会话；JWT 过期自动跳登录。
3. **🚫 敏感信息不进浏览器**：前端只调 FINFLOW API，不缓存银行密钥/金蝶凭证/飞书 Secret；错误页不泄露堆栈。

## 十、平台技术底座（支撑以上功能，非直接用户功能）

1. **✅ MOCK Adapter 统一聚合层**：SPI `BankDataAdapter` + 统一 API 聚合层，支持余额/流水/回单/对账单/代发五类查询与同步任务的路由、转换、状态映射、异常隔离、幂等（`bank-data/{resource}`、`/api/bank/...` 等）。
2. **✅ 定时调度与重试韧性**：定时采集、30 天原始数据清理两个 Scheduler；限流/重试/超时参数可配置注入。
3. **✅ 迁移体系**：Flyway V1–V14（V1-V14 不可改，新迁移从 V15 起）；RDS 参数兼容（`explicit_defaults_for_timestamp=OFF` 等，见 `MEMORY.md`）。
4. **◻️ 领域归档（实体/Mapper 按域迁移）**：v0.3 模块化第 3 步待做——当前实体/Mapper 仍集中管理，后续按表归档到模块目录。
