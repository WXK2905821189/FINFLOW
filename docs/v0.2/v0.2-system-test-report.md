## 3. SYS 矩阵结果

| 用例 | 结果 | 判定与证据 |
| --- | --- | --- |
| SYS-03 认证与会话 | 不通过 | JWT 每次请求会重新加载用户，停用账户可望即时失效；但 `AuthController` 没有登出/撤销端点，JWT 不含可撤销标识，也没有服务端撤销或令牌版本校验。正确/错误/停用账号的集成证据未执行。见 DEF-P1-AUTH-001。 |
| SYS-04 RBAC | 部分通过，未完成 | `SecurityConfig` 启用方法安全，控制器普遍使用 `@PreAuthorize`；权限变更后的下一个请求会重新计算用户权限。四角色端点、深链、按钮和撤权后的 `401/403` 端到端证据未执行，不能判为通过。 |
| SYS-05 企业隔离 | **不通过，P0** | 自动入账的批次、流水、详情、复核、制证和对账均没有从会话用户解析企业并过滤；服务层按全局 ID/全表查询。既有 `DEF-P0-AA-001` 仍然成立，见 DEF-P0-SYS-001。 |
| SYS-09 银行原始层 | **不通过，P0** | `BankDataSyncExecutor.execute` 是一个事务：原始响应、同步日志、标准化记录与任务状态同属该事务。标准化或业务写入发生未捕获异常时，原始响应和“已持久化”日志会一并回滚，无法满足“原始层先落库且下游失败可追溯”。见 DEF-P0-SYS-003。 |
| SYS-11 银行状态 | 不通过 | 中信编解码器仅将字面量 `SUCCESS` 视为成功，并把其它业务码折叠为 `FAILED`；未实现 `AAAAAAA`、`AAAAAAE`、`EEEEEEE`、`UNKNOWN` 的受控状态机、外部幂等号查询或乱序回执处理。当前不会把这些未知码自动视为成功，但仍缺少必需处置。见 DEF-P1-BANK-001。 |
| SYS-14 审计 | 不通过 | 自动入账审计表不含企业 ID 和请求编号，迁移未建立只追加的数据库级保护；认证、权限拒绝和转账也没有统一审计写入。审计字段/不可篡改与完整链路复验未完成。见 DEF-P1-AUDIT-001。 |
| SYS-15 脱敏 | 不通过 | 银行查询 API 未返回原始报文正文，日志响应具备基础敏感词和长数字掩码；但默认配置使用仓库内已知 JWT 密钥且启用 MyBatis 标准输出日志。未完成日志、审计、错误、DOM/缓存、导出和告警的运行时扫描。见 DEF-P1-SEC-001。 |

## 4. 缺陷台账

| ID | 级别 | 模块 | 实际结果与可复现证据 | 预期 | 影响/处置 |
| --- | --- | --- | --- | --- | --- |
| DEF-P0-SYS-001（原 DEF-P0-AA-001） | P0 | 自动入账企业隔离 | `StatementController` 的批次、流水、详情、复核、制证、对账调用均未传入主体；`StatementService` 使用 `getById`、`list`、无企业条件的分页与全局流水号去重。迁移 `V2` 的 `statement_import_batch`、`statement_record`、`statement_audit_event` 亦无 `company_id`。 | 仅能按会话企业读写，跨企业资源返回安全拒绝/空结果且无副作用。 | 跨企业读取、推断或修改自动入账事实。修复后必须以两企业同值资源覆盖列表、详情、分页、复核、制证、对账和审计。 |
| DEF-P0-SYS-002 | P0 | 转账状态机与幂等 | `BankAccountService.submitTransfer` 校验余额后直接调用 `BankService.submitTransfer`；请求和响应没有持久化转账申请、外部幂等键、状态机、交易/余额一致性或审计。模拟 SDK 每次调用生成新参考号。重复提交、超时或未知发送结果无法查询/补单，未来替换真实实现会有重复付款风险。 | 同一幂等键最多一笔申请/交易/余额变化；未知结果只能查询或待对账，状态和审计可追溯。 | 资金重复执行风险。先建立受控支付领域状态机、外部幂等和审计后，再允许任何真实 Adapter 验收。 |
| DEF-P0-SYS-003 | P0 | 原始层事务语义 | `BankDataSyncExecutor.execute` 的 `@Transactional` 覆盖原始响应插入、`RAW_MESSAGE_PERSISTED` 日志、标准化和任务更新；下游未捕获异常回滚时原始层也回滚。外层只在回滚后写失败任务日志。 | 外部响应和受控同步日志必须在标准化/业务写入前独立可靠持久化；下游失败仍保留原始引用和安全摘要。 | 失败数据不可追溯，不能证明“原始先落库”。须用注入标准化/写入失败的集成测试证明语义。 |
| DEF-P1-AUTH-001 | P1 | 会话撤销 | 认证接口只有登录、注册和当前用户；JWT 仅验证签名、过期时间和用户启用状态，未见登出、撤销表、`jti` 或令牌版本。 | 登出、密码重置、权限高风险变更和主动撤销应使既有会话按策略立即失效，并有测试证据。 | 退出登录后令牌仍可使用至过期；补会话撤销设计并执行过期、停用、登出、撤权测试。 |
| DEF-P1-BANK-001 | P1 | 银行状态与回执 | `CiticBankDataCodec.parseStatus` 仅识别 `SUCCESS`/其它失败；代码库未发现四个约定银行状态码、回执状态表或查询/补单流程。 | 在银行文档确认前，`AAAAAAA` 只能作为候选成功，`AAAAAAE` 待回执/对账，`EEEEEEE` 失败候选，`UNKNOWN` 不得新建付款；均关联外部幂等号。 | 目前安全地不自动成功，但无法满足回执与恢复验收；需要模拟器与银行沙箱后复验。 |
| DEF-P1-AUDIT-001 | P1 | 审计完整性 | 自动入账审计记录只有流水/批次、动作、结果、前后状态、操作者、详情和时间；缺企业 ID、请求编号，且无只追加约束/触发器或受控写入权限证据。认证、拒绝访问及转账路径未发现统一审计。 | 审计必须含操作者、企业、对象、动作、结果、时间、请求编号和前后状态，并以追加不可改方式保存。 | 审计无法完成跨企业和请求级追溯；补模型、权限和篡改拒绝集成测试。 |
| DEF-P1-SEC-001 | P1 | 敏感配置与脱敏 | 默认 `application.yml` 指定开发 profile、仓库内 JWT 密钥，并启用 MyBatis `StdOutImpl`；`application-prod.yml` 虽要求 `JWT_SECRET`，但无部署前拒绝开发 profile 的证据。 | 生产只能由受控环境变量/密钥管理注入，开发密钥和 SQL/原始载荷不可被带入生产日志；运行时扫描不得含凭据、Token、完整账号、原始敏感载荷或堆栈。 | 发布前须提供生产环境变量清单、启动失败证据及日志/审计/DOM/导出扫描结果。 |

## 5. 已验证的正向控制

- 银行数据同步、任务、流水、余额和查询投影在 `BankDataSyncService` 中按服务端解析的 `companyId` 过滤；此结论不适用于自动入账模块。
- 银行查询 DTO 不返回原始报文 `payload`；日志响应会对常见密钥字段和连续长数字作基础掩码。
- 中信编解码器提供 GBK/Base64 边界及逻辑证书别名校验的单元测试，已随本次后端单元测试执行并通过。
- 前端构建成功，且本次没有启动应用、执行 E2E 或调用真实银行。
