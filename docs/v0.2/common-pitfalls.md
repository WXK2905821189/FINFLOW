# FINFLOW v0.2 常见问题与避坑记录

本文记录开发、联调、测试和部署中已经发现或高概率发生的问题。每次新增问题时，补充现象、根因、解决方式和回归用例。本文不得记录密码、Token、私钥、证书内容、完整账号或生产地址。

## 1. 当前已发现问题

| 编号 | 问题 | 现象 | 根因/风险 | 规避与验证 |
| --- | --- | --- | --- | --- |
| PIT-001 | 自动入账缺企业隔离 | 用户可通过批次/流水 ID 查询或操作其他企业数据 | 旧版 `statement_*` 表缺少 `company_id`，服务层使用全局查询 | 所有表补企业归属，服务端从会话解析企业；用两个企业的同 ID 资源测试列表、详情、复核、制证、对账和审计 |
| PIT-002 | V6 迁移缺失 | CI 或部署门禁要求 V6，但迁移目录只有 V1-V5 | CI、运行手册和数据库实际版本不一致 | 新增迁移前先统一版本清单；禁止手工修改 Flyway 历史表；空库和已有库都执行迁移 |
| PIT-003 | 原始层与下游同事务 | 标准化或业务写入失败后，原始响应和同步日志也消失 | 原始保存、标准化、业务写入被同一个事务包住 | 原始响应和同步日志先独立可靠落库；注入下游失败，确认原始引用仍可追溯且无半成品业务记录 |
| PIT-004 | 只测单元测试就宣布通过 | 单元测试通过，但跨企业、迁移和端到端仍有缺陷 | 单元测试不能覆盖数据库约束、认证上下文和页面链路 | 发布前必须执行集成、迁移、API 权限、双企业和 E2E 测试；报告明确区分已执行与未执行 |
| PIT-005 | Maven 使用错误本地仓库 | Maven 尝试写入 `C:\.m2` 或因权限失败 | 受限环境下未显式指定可写仓库 | 使用项目内受控本地依赖目录；命令行只记录路径，不记录凭据；构建日志确认 Java 17/Maven 版本 |
| PIT-006 | 前端构建工具不在 PATH | `pnpm build` 报 `node is not recognized` | pnpm 脚本找不到工作区 Node，而不是代码必然有错 | 先确认 Node/pnpm 路径，再执行 TypeScript 和 Vite 构建；生产构建通过不等于 E2E 通过 |
| PIT-007 | 前端包体过大 | 构建成功但出现超过 500 kB 的 chunk 警告 | 当前应用将较多页面打入单一入口 | 记录为 P2 性能问题；后续按路由拆包、手动分 chunk，并用首屏性能基线复验 |
| PIT-008 | 把前端隐藏当成安全控制 | 菜单隐藏但直接请求接口仍可访问 | 仅做了 UI 权限判断，缺少服务端方法级鉴权 | 每个读写接口都做服务端鉴权；使用无权 Token、深链和伪造资源 ID 验证 401/403 与无副作用 |
| PIT-009 | 生产配置带开发默认值 | 生产可能连接 localhost 或使用默认数据库用户 | `application-prod.yml` 使用了不安全的默认值 | 生产 DB URL、用户名、密码、JWT 密钥均必须由受控环境注入；缺失时启动失败且不回显值 |
| PIT-010 | 日志泄露敏感数据 | SQL、原始报文、账号、Token 或错误堆栈出现在日志/审计 | 调试日志、原始响应或异常直接输出 | 使用虚拟秘密探针扫描应用日志、审计、错误响应、前端 DOM/缓存、导出和告警 |

## 2. 中信 SDK 联调注意事项

| 编号 | 注意事项 | 正确做法 |
| --- | --- | --- |
| CITIC-001 | SDK 初始化只能执行一次 | 将初始化放在应用生命周期中单例执行；重复初始化可能触发 `ETSK004` |
| CITIC-002 | 证书下载码一次性 | 证书目录需提前创建并具备读写权限；下载成功后保存证书和稳定 token，不要反复尝试下载 |
| CITIC-003 | Token 与证书绑定 | 自定义 token 一旦变更，旧证书可能不可用；容器环境必须使用稳定、受控存储的 token |
| CITIC-004 | IP/MAC 是银行侧白名单 | 本机内网 IP 不是银行要的出口 IP；切换网络、NAT 或网卡后要重新确认白名单 |
| CITIC-005 | 外层和内层报文不同 | 外层通常为 `DLGECOMM`；业务交易码在内层；内层 XML 使用 GBK，再进行 Base64 封装和解码 |
| CITIC-006 | 外层成功不等于业务成功 | 外层 `AAAAAAA` 只说明 SDK/通信层成功；必须继续解码并判断内层业务响应 |
| CITIC-007 | 示例机器信息采集不可照搬 | 示例可能执行系统命令读取硬件信息；生产容器应采用受控稳定 token/MAC 方案，不执行未审查命令 |
| CITIC-008 | 银行查询有窗口和分页限制 | 流水查询按银行允许的日期窗口拆分，处理分页、空页、重复页和乱序；不能把部分结果显示为完整成功 |
| CITIC-009 | 外部编号长度要单独设计 | 银行不同接口对 `clientID` 长度可能不同；内部 `requestId` 与不超过银行限制的外部幂等号分开保存 |
| CITIC-010 | 银行状态需要业务映射 | `AAAAAAE`、`EEEEEEE`、`UNKNOWN` 等状态不能直接映射为付款成功；需按银行文档和沙箱确认后进入状态机 |

## 3. 数据链路不可违反的规则

1. 银行请求和响应先进入受控原始表，并写入同步日志。
2. 原始记录保存后，才允许执行统一数据模型转换。
3. 标准化数据通过校验、去重和企业范围检查后，才能写入业务表。
4. 前端只调用 FINFLOW API，只查询业务表或查询投影。
5. 原始报文、银行专有字段、证书、私钥、Token 和完整账号不得进入普通 API、前端、导出或客户端日志。
6. 定时同步、手动同步和重试必须共用任务、请求编号、幂等和审计模型。
7. 重试不能创建第二条流水、第二个凭证、第二笔支付或第二次余额变化。

## 4. 测试与发布检查

- [ ] 新增表或接口明确 `company_id` 来源，不能接受客户端企业 ID 作为授权依据。
- [ ] 迁移文件按版本顺序存在，未发布迁移不被重写，空库/增量库均已验证。
- [ ] 原始层失败、标准化失败、业务写入失败均有故障注入用例。
- [ ] 后端单测通过后，仍完成集成、权限、双企业、迁移和 E2E 测试。
- [ ] 前端 TypeScript、生产构建、页面状态和 API-only 检查均有记录。
- [ ] 生产配置无默认数据库、开发 JWT 密钥、调试日志和测试凭据。
- [ ] 真实银行 SDK/API 未经单独沙箱准入时，系统保持模拟/未启用状态。
- [ ] 每个 P0/P1 缺陷都有责任角色、修复版本、复验用例和证据。
