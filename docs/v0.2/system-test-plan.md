# FINFLOW v0.2 全量测试方案

## 1. 目标与测试边界

本方案用于验证当前候选版本的完整业务闭环、跨企业安全边界、数据一致性和可发布性。覆盖：认证与会话、RBAC、企业隔离、账户、自动入账、银行接入、银行数据底座、数据库迁移、前端 API 契约、审计和部署配置。主动转账、支付和调拨不属于当前产品。

一期自动入账继续限定为“文件/模拟来源 -> 校验 -> 人工复核 -> 金蝶模拟制证 -> 对账追溯”。银行数据 v0.2 只允许模拟 Adapter 和受控测试桩；真实中信 SDK/API、真实生产密钥、真实资金操作和生产银行数据不在本次执行范围。银行沙箱物料到位后，另行执行 `SANDBOX` 联调，不得把模拟通过结论写成真实银行接入通过。

银行数据链路必须保持以下顺序：

```text
银行 Adapter/模拟器
  -> 原始请求/响应与同步日志落库
  -> 统一银行数据模型
  -> 校验、去重和业务规则
  -> 业务表/查询投影
  -> FINFLOW API
  -> 前端
```

原始结果和同步日志暂保留 30 天；清理或归档的最终规则属于待决策点。前端不得访问银行 SDK、银行原始响应或同步日志全文。

## 2. 测试环境与数据

| 环境 | 用途 | 数据要求 | 外部调用 |
| --- | --- | --- | --- |
| `UNIT` | 单元、领域规则、适配器协议 | 合成数据、虚拟凭据 | 禁止 |
| `INT` | 后端 + H2/MySQL + Flyway 集成 | 两个企业、虚拟账户、可重复夹具 | 仅模拟 Adapter |
| `E2E` | 前后端用户旅程和权限页面 | 专用测试账号，最小化脱敏数据 | 仅 FINFLOW API |
| `SANDBOX` | 银行材料到位后的专项联调 | 银行批准的测试账户和测试凭据 | 仅后端 Adapter，经批准端点 |

固定测试夹具至少包含两个企业、同编号账户/任务/流水、四类角色、导入人和复核人、正常/异常/重复流水、分页数据、GBK 中文数据、四类银行状态和失败/超时结果。真实凭据、私钥、证书、Token 和完整收款信息不得写入仓库、测试报告、日志、浏览器或导出。

## 3. 执行顺序

1. `P0-1` 静态检查、前后端构建、迁移结构检查。
2. `P0-2` 后端单元与集成测试：认证、权限、企业隔离、状态机、事务、银行数据管道。
3. `P0-3` 前端类型检查、构建、页面路由和 API 契约冒烟。
4. `P0-4` E2E 关键用户旅程、重复操作、刷新、会话撤销和窄屏检查。
5. `P0-5` 安全专项：IDOR、敏感数据扫描、审计完整性、配置和依赖检查。
6. `P1` 性能、恢复、告警和迁移演练。
7. `SANDBOX` 仅在银行材料、出口 IP/MAC 白名单和书面测试范围齐备后执行。

## 10. 产品验收审查基线

本节是对产品需求、一期范围和 v0.2 银行数据底座的验收审查，不替代研发测试报告。用例被列入矩阵只表示“应执行”，不表示该项已通过；未提供可复核的版本、环境、请求编号、数据结果和审计证据时，状态只能是“待执行”或“不通过”。

### 10.1 一期范围与三域隔离判定

| 域 | 一期允许行为 | 禁止跨域行为 | 对应 SYS 用例 |
| --- | --- | --- | --- |
| 自动入账 | 文件/模拟来源导入、校验、去重、落库、人工复核、金蝶模拟制证、对账追溯 | 发起/审批/执行付款或调拨；改银行可用余额；把模拟凭证当作付款或真实总账结果 | SYS-05、SYS-08、SYS-13、SYS-14、SYS-15 |
| 资金管理（支付/调拨） | 申请、审批、执行、取消、冲正、交易和余额记录 | 以导入流水替代支付申请；让自动入账、银行查询或对账投影直接改支付/调拨状态 | SYS-05、SYS-06、SYS-07、SYS-13、SYS-14 |
| 银行接入/银行数据底座 | 模拟连接状态、任务、原始层、标准化、受控查询投影、只读追溯与审计 | 伪造真实直联；前端直连 SDK/原始报文；查询修改余额、主动支付、复核或制证；自动创建流水或付款指令 | SYS-05、SYS-09、SYS-10、SYS-11、SYS-12、SYS-13、SYS-15、SYS-16 |

三域隔离的通过判定为：任意域的页面、API、任务或重试均不能越过自身写入边界；允许的跨域关联仅为服务端授权后的只读引用；同一次验收需同时留存“被拒绝的越权动作”和“原对象状态未变化”的证据。

### 10.2 真实银行验证口径

- 当前版本没有中信正式 SDK/API、银行字段字典、签名/证书资料、授权沙箱端点或真实回执协议的通过证据。
- SYS-09 至 SYS-12、SYS-16 中的银行相关验收，当前只可证明模拟 Adapter、内部数据管道、只读 API 和边界控制；不能证明真实余额、流水、回单、对账单、支付、代发、签名、分页、限流、回执或生产放款。
- 真实银行验证的前置条件和追加用例以 `bank-data-delivery-backlog.md` 第 10 至 12 节、`bank-data-test-plan.md` 的 `SANDBOX` 用例为准。前置条件未齐备时，结果必须登记为“未执行”，不得以模拟器成功代替。

## 13. 当前产品验收结论

当前结论：**不通过，禁止作为 v0.2 发布批准或真实银行接入批准的依据。**

- DEF-P0-AA-001 为未关闭的自动入账企业隔离 P0 缺陷，直接阻断 SYS-05 和发布出口。
- SYS-01 至 SYS-16 当前仅完成测试设计和追踪审查，尚未形成全量可复核执行证据。

重新进入产品验收的最低条件是：关闭并复验 DEF-P0-AA-001；完成 SYS-01 至 SYS-16 的 P0 执行证据；完成三域隔离专项；记录未执行银行项、风险接受和责任人。真实银行相关结论仅在独立 `SANDBOX` 联调和生产准入后另行评审。
