执行日期：2026-08-27。范围仅覆盖构建、迁移、部署、健康检查、回滚和真实银行边界；不代表业务功能、双企业 API、E2E 或银行沙箱验收通过。

## 结论

**阶段结论：待集成复验，禁止生产发布。**

- H2 空库的 Flyway V1 -> V6、厂商 V7、V8 和本机健康检查已通过。
- GitHub Actions 最新候选提交的后端 Java 17/Maven 与前端 Node 20/pnpm 作业均通过。
- 本机没有 Node.js、pnpm、MySQL、MySQL 客户端或 Docker，不能替代远端前端构建或完成 MySQL 空库/增量/重复启动、备份恢复演练。
- 真实银行 SDK/API、证书、私钥、Token、生产密钥和真实银行调用均未使用；静态扫描未发现银行数据模块的 HTTP 客户端痕迹或受控材料。

## 迁移与 CI 门禁

- 迁移目录当前包含 `V1__init_rbac_and_bank_accounts.sql` 至 `V6__tenant_statement_payment_and_session_safety.sql`。
- CI `Release contract` 要求基础迁移 V1-V6、厂商 V7、V8 和生产数据库 URL/用户名/密码均采用环境变量，并拒绝不安全的数据库 URL 默认值。
- 生产库只允许在已批准的测试服务器使用一次性、最小权限测试账号进行验证；任何测试前先验证目标不是生产实例、备份可恢复且连接串未写入日志。

## P0/P1 缺陷与阻断

| 编号 | 级别 | 内容 | 放行条件 |
| --- | --- | --- | --- |
| DEP-P1-005 | P1 | H2 文件库重复启动验证未保留 Flyway 历史，可能与当前本机进程终止方式或 H2 文件路径/关闭行为有关。 | 在可控环境使用持久化 H2 或 MySQL 完成空库、增量与重复启动，保留 `flyway_schema_history` 证据。 |
| DEP-P1-006 | P1 | 本机缺 Node.js 20、pnpm 9、MySQL 与 Docker。 | 安装受控版本，或引用成功的 CI 制品和隔离 MySQL 验证记录；本机缺失不能被表述为本机构建通过。 |
| DEP-P1-007 | P1 | 生产缺变量在 Flyway 初始化时才失败，缺少更早、更明确的独立启动前校验。 | 在部署平台实施变量存在性闸门，或增加经测试的应用启动校验；错误只能输出变量名，不得输出值。 |
| DEP-P1-008 | P1 | MySQL 备份恢复、回滚和健康检查尚无隔离服务器执行证据。 | 完成下列演练并记录制品版本、数据库版本、操作人、时间及脱敏结果。 |

当前未发现本范围内的 P0 发布工程缺陷；以上 P1 未关闭前，生产发布仍保持待集成复验。

## MySQL 与回滚演练步骤

1. 确认目标为隔离测试 MySQL，记录实例标识、库名、版本、测试账号权限和备份位置；禁止使用生产库或生产凭据。
2. 从空库启动候选制品，确认 Flyway 依次应用 V1-V6、厂商 V7 和 V8，并核对 `flyway_schema_history`、应用日志和 `/v3/api-docs` 的 200 响应。
3. 从已完成 V1-V5 的数据库副本启动同一制品，确认仅应用 V6、对应厂商 V7 和 V8；再次重启，确认没有新增 Flyway 历史记录或校验错误。
4. 在迁移前执行可恢复备份；按平台恢复流程恢复到独立实例，校验历史版本、关键表和应用健康检查。不得手工修改 `flyway_schema_history`。
5. 回滚应用时先把流量切回上一已验证制品，再确认健康检查、错误率、登录和关键只读 API；数据库使用备份恢复或经评审的前向修复迁移，不执行手工 SQL 回退。

## 真实银行闸门

- `bankdata.adapter.mode` 与一期运行手册保持 `mock` 边界；真实适配器、真实 SDK/API、证书、私钥、访问令牌、生产端点和真实业务数据不在本次执行范围。
- 任何真实外部调用计数非 `0`、仓库中出现受控材料或机密、或 CI 扫描发现银行 HTTP 客户端痕迹，均为 P0，立即停止发布并禁用调度。
- 真实银行验证仅能在书面批准的 `SANDBOX` 阶段由后端适配器执行，不能用本报告的模拟/H2 结论替代。
