# FINFLOW 产品模块收口记录

更新时间：2026-08-31

本记录用于区分“已经能在当前 MOCK/测试边界内使用的产品模块”和“仍需外部物料或后续需求才能放行的能力”。它不替代产品需求文档，也不把 MOCK 结果描述成真实银行、真实金蝶或真实飞书结果。

## 已接入工作台

| 模块 | 当前状态 | 说明 |
| --- | --- | --- |
| 自动入账 | 已接入 | 文件/模拟来源导入、校验、人工复核、金蝶 MOCK 制证、对账追溯；不创建付款、转账或调拨对象。 |
| 连接与运营 | 已接入 | 连接元数据、同步任务、运行日志、六类银行数据只读投影；页面只调用 FINFLOW API。 |
| 银行数据底座 | 已接入 | Adapter、原始请求/响应先落库、同步日志、统一模型、业务投影、分页窗口、幂等、30 天受控清理。真实银行调用保持 0。 |
| 飞书协同 | MOCK 已接入 | 连接、接收对象、通知策略、事件幂等、Outbox/发送记录和失败重试；不调用真实飞书。 |
| 规则与映射 | MOCK/内部能力已接入 | 校验规则和入账科目映射以版本化草稿维护，启用后由后端消费；规则责任人、阈值和凭证模板仍需业务确认。 |
| 结账管理 | 内部能力已接入 | 按账期检查待复核、异常和已复核未制证流水；仅无阻断时可确认结账，结账后不覆盖历史事实。 |
| 审计中心 | 已接入基础版 | 展示当前企业范围内的脱敏系统审计事件，支持动作、对象和请求号筛选；后续应继续汇聚登录、权限拒绝和既有业务审计事件。 |

## 明确不在当前版本

- 主动转账、付款、资金调拨、支付审批和支付执行不属于当前产品，历史代码/表仅为后续独立模块保留，前端不提供入口。
- 真实银行 SDK/API、证书、网络白名单、生产密钥和真实数据采集不启用；需等待银行物料和独立 SANDBOX 门禁。
- 真实金蝶接口不启用；当前只验证模拟凭证状态、幂等和追溯。
- 真实飞书租户授权、机器人/群组发送、签名验签和生产 Token 不启用；当前只验证 MOCK 通知。

## 下一轮验收缺口

1. 在隔离 MySQL 完成 V1-V11 空库、增量、重复启动、备份恢复和厂商 V7 迁移验证。
2. 用浏览器完成 1440、1024、375 三个视口的权限、筛选、详情抽屉、敏感信息和无溢出验收。
3. 把既有自动入账、同步、飞书、结账和连接操作审计统一映射到审计中心，保持企业范围和请求号链路。
4. 由财务确认规则责任人、金额阈值、复核层级、科目/凭证模板，以及差异关闭和结账日历。
5. 银行、金蝶和飞书真实接入分别走资料评审、密钥/网络、安全、沙箱、回执和生产灰度门禁，不能用本记录的 MOCK 证据替代。
