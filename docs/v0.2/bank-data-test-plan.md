# FINFLOW v0.2 银行数据接入测试计划

## 1. 目标与范围

本计划验证 v0.2 银行数据接入底座从银行适配器模拟器到 FINFLOW 业务表和前端查询的受控链路：企业隔离、定时与手动同步、原始报文、标准化、组合去重、回执、重试、审计和领域一致性。

受测处理顺序必须为：

```text
适配器模拟器或银行 SDK/API
-> 同步任务与不可变请求摘要
-> 原始报文与同步日志
-> 标准化映射
-> 校验、组合去重与领域服务
-> 业务表、审计和查询投影
-> FINFLOW API
-> 前端
```

前端不得访问适配器、SDK 响应、原始报文、同步日志或银行专有字段；原始层、标准化层和业务层均为不可相互覆盖的历史事实。

**本计划不授权真实资金操作。** 真实凭据、私钥、访问令牌、生产证书和生产端点在所有环境、测试数据、日志、审计、导出、浏览器存储及截图中均禁止使用或出现。

## 2. 执行标记与风险接受

| 标记 | 执行环境与含义 | 发布判断 |
| --- | --- | --- |
| **SIM** | 适配器模拟器、虚拟企业和合成数据即可验证。模拟器必须可注入确定成功、业务失败、超时、重复回执和乱序回执。 | P0 用例必须通过。 |
| **INT** | 前后端、数据库、任务调度、日志/审计和模拟器已部署的非生产联调环境。 | P0 用例必须通过，留存请求编号和数据库证据。 |
| **RA-DATA** | 受“测试/非生产环境临时允许真实银行业务数据”风险接受影响。仅可使用已批准范围内的真实业务数据副本或银行沙箱业务数据；仍遵守最小访问、脱敏、加密、审计、禁止不受控导出和退出条件。 | 只能作为临时风险接受下的联调证据，不能视为生产放行批准。正式沙箱联调前必须复核数据范围、角色、脱敏、导出、保留和清理。 |
| **SANDBOX** | 仅在银行 SDK/API、测试证书、签名规则、沙箱端点、错误码说明和授权故障矩阵就绪后执行。 | 未完成不得将模拟器通过表述为真实银行接入通过。 |
| **PROD** | 候选生产环境的只读配置、网络、监控和数据保护核查；不得发送真实资金指令。 | 生产放行前必须通过。 |

### 风险接受适用边界

- 标有 **RA-DATA** 的用例因需要核对银行字段映射、分页窗口、历史业务数据边界或回执语义，可能临时使用获批的真实业务数据。该风险接受**不**允许真实凭据、私钥、Token、生产证书或生产端点。
- 即使适用 **RA-DATA**，原始报文、日志、审计、导出、错误响应、浏览器控制台和前端本地存储仍须脱敏；仅受授权角色可查看受控最小化内容，且必须有访问和清理审计。
- 未标 **RA-DATA** 的用例必须优先使用合成数据或银行沙箱数据。生产环境不应使用该风险接受作为降低隔离、脱敏、审计或外部调用控制的理由。

## 3. 准入条件、角色与测试数据

### 准入条件

- 候选版本已部署，迁移完成，且可查询任务、同步日志、原始报文元数据、标准化记录、业务记录、审计与查询投影。
- 模拟器支持：分页、固定银行侧请求号、成功、明确失败、超时/未知、重复回执、乱序回执和重复拉取注入。
- 定时调度器可在隔离窗口触发；手动触发接口要求受控权限与幂等键；所有路径产生 `request_id`。
- 原始报文采用加密存储或受控密文，保存 `received_at`、`retention_until`、内容摘要、方向、企业、任务及银行侧请求号；普通 API 和前端无直接读取端点。
- 第二企业准备相同银行账户标识、相同流水号、相同时间金额组合和相同银行侧请求号，用于企业隔离验证。

### 最小测试角色

| 角色 | 允许能力 | 不允许能力 |
| --- | --- | --- |
| 同步操作员 | 授权手动创建本企业同步任务、查看本企业任务结果 | 查看原始报文明文、跨企业任务、绕过幂等和审计。 |
| 调度服务账号 | 仅以受控服务身份运行定时任务 | 以任意企业身份读取/写入或跳过企业范围。 |
| 业务查看者 | 查看经过授权、脱敏的业务投影与查询结果 | 查看原始报文、同步日志敏感字段、触发任务或修改业务状态。 |
| 受控审计员 | 在环境策略许可时查看最小化原始报文/日志证据 | 导出明文、修改/删除原始数据、任务或审计。 |
| 无权用户 | 无银行数据权限 | 列表、详情、原始层、任务、回执与查询投影访问。 |

### 固定数据集

| 数据集 | 内容 | 用途 |
| --- | --- | --- |
| `BD-BASE-01` | 两笔收入、两笔支出、唯一银行流水号、相同企业的启用账户、精确到两位小数金额 | 完整拉取、标准化、自动入账投影和查询事实。 |
| `BD-DUP-01` | 重复银行流水号；无稳定流水号但相同企业/账户/交易时间/金额的记录；第二企业同值记录 | 组合去重、降级判定和企业隔离。 |
| `BD-RECEIPT-01` | 对同一外部幂等号的 `ACCEPTED`、最终成功、明确失败、重复成功、乱序成功/失败回执 | 异步回执、支付尝试与转账状态机。 |
| `BD-PAGING-01` | 多页数据、页间重复、页间乱序、窗口重叠和空页 | 适配器分页、手动/定时重叠与去重。 |
| `BD-FAIL-01` | 解析失败、映射版本不识别、数据库唯一冲突、原始报文落库失败、超时、调度重启 | 原始先落库、恢复、失败重试和一致性。 |
| `BD-RA-01` | 已批准的非生产真实业务数据最小副本或银行沙箱业务数据，不含任何凭据 | **RA-DATA** 字段映射、历史窗口、分页与脱敏复核。 |

## 4. 核心不变量

| 对象 | 必须满足的约束 |
| --- | --- |
| 企业范围 | `company_id` 由服务端认证上下文决定；连接、任务、日志、原始报文、标准化记录、业务表、回执与查询投影均强制过滤。客户端企业 ID、Header、URL 或请求体不能扩大范围。 |
| 同步任务 | 定时和手动均先创建任务、请求编号和不可变请求摘要；同一业务窗口/操作的重试使用同一幂等语义，不能绕过任务、审计或原始落库。 |
| 原始层 | 银行请求/响应及同步日志在标准化、业务写入前持久化；原始消息不可由业务写入覆盖，普通前端/API不可读取；接收后保留 30 天，并有可配置清理/归档、豁免与清理审计。 |
| 标准化层 | 每条记录含来源系统、来源记录 ID、映射版本、原始消息引用、来源时间和企业；银行专有字段不扩散到通用业务表或前端。 |
| 去重 | 对流水号和“企业 + 银行账户 + 交易时间 + 金额”执行服务端判重及数据库企业范围唯一约束；命中返回既有记录和依据。无稳定流水号时记录降级判定与人工复核原因。 |
| 回执与支付 | `ACCEPTED`、超时和未知结果仅可进入等待异步回执、待对账或人工处置状态；只有明确最终成功回执才可进入 `EXECUTED`。重复/乱序回执不得重写最终事实、重复交易或重复余额变更。 |
| 前端 | 只调用 FINFLOW API 获取经权限过滤的业务表/投影；无数据、未启用、加载和失败状态必须区分，失败显示请求编号，不能缓存/渲染原始银行响应。 |

## 5. 可执行测试用例

| ID | 优先级 | 环境 | 场景与操作 | 通过标准与证据 |
| --- | --- | --- | --- | --- |
| BD-01 | P0 | SIM, INT | 以两个企业的同 ID 连接、账户、任务、原始消息、标准化记录、回执和查询投影交叉访问列表、详情、搜索、分页及下载入口；伪造企业参数。 | 服务端仅返回当前企业数据；跨企业读写返回 `403` 或安全空结果，不泄露对象存在性。保存请求/响应、数据库行属主和权限拒绝审计。 |
| BD-02 | P0 | SIM, INT | 分别用定时调度器和授权人工对同一账户/时间窗口同步 `BD-BASE-01`，再并发触发和网络重试。 | 两入口均创建可追溯任务，具备触发方式、幂等键、请求编号、窗口和审计；只产生一组业务事实，重试返回既有任务/结果而非绕过持久化。 |
| BD-03 | P0 | SIM, INT | 对拉取、提交、回执查询分别在适配器调用后注入标准化失败、业务校验失败和领域写入失败。 | 原始请求/响应与同步日志先于下游数据持久化，能由任务和请求编号追溯；失败不删除或覆盖原始层，业务层不出现半写入。 |
| BD-04 | P0 | INT, PROD | 读取普通业务前端/API、业务查看者、无权用户和受控审计员对原始报文/同步日志的访问；检查网络响应、前端缓存、日志和导出。 | 普通前端与业务用户无原始层端点或字段；无权返回 `401/403`。受控审计读取仅在策略许可时提供最小化、脱敏内容并留痕；无明文凭据、私钥或 Token。 |
| BD-05 | P0 | SIM, INT | 将 `BD-BASE-01` 分别通过适配器模拟器的流水、回单、对账单、支付回执和代发结果映射到统一模型。 | 每条标准化记录含企业、来源、来源记录 ID、映射版本、来源时间及原始消息引用；业务表/前端无银行专有字段。保存映射版本、输入摘要、输出摘要和审计。 |
| BD-06 | P0 | SIM, INT, RA-DATA | 使用 `BD-DUP-01` 的重复流水号、组合重复、无流水号降级场景、页间重复、定时/手动重叠和网络重试。 | 服务端和数据库共同去重；重复返回既有标准化/业务记录及命中依据，不创建第二条业务事实。降级判定与人工复核原因可追溯。**RA-DATA** 仅用于复核真实业务字段的组合稳定性。 |
| BD-07 | P0 | SIM, INT | 对映射版本升级前后同一原始消息重跑标准化；提交未知版本、已废弃版本和字段缺失版本。 | 已处理历史保留原映射版本和原输出，不被新版本覆盖；未知/不兼容映射安全失败，原始层和日志仍可追溯，且不写错误业务事实。 |
| BD-08 | P0 | SIM, INT | 对 30 天边界前、边界时和边界后的原始报文/同步日志执行保留扫描、清理/归档和争议豁免。 | 到期策略可配置；清理或归档记录操作者/任务、范围、时间和请求编号；豁免数据不被清理。普通业务数据和审计引用不因清理损坏。最终物理删除/归档方案未决时，未获批准不得在生产执行不可逆清理。 |
| BD-09 | P0 | SIM, INT | 用 `BD-RECEIPT-01` 提交转账：依次返回 `ACCEPTED`、超时、未知、最终成功和明确失败。 | 每次操作关联任务、外部幂等号、银行侧请求号、原始回执与 `payment_attempt`；`ACCEPTED`/超时/未知不生成已付款交易、不扣/覆盖余额、不标记 `EXECUTED`。只有最终成功可驱动一次一致的交易、余额与转账状态变更。 |
| BD-10 | P0 | SIM, INT, SANDBOX | 先后发送重复成功、重复失败、成功后失败、失败后成功和乱序回执。 | 状态转换只接受合法且版本匹配的回执；终态不可被旧回执覆盖。相同外部幂等号最多一笔交易、一次余额变化和一个最终业务结果。**SANDBOX** 必须按银行提供的真实回执语义复验。 |
| BD-11 | P0 | SIM, INT, SANDBOX | 注入银行网络超时、进程重启、银行已受理但本地未知、可重试明确失败和重复查询。 | 任务进入明确可恢复状态；未知结果使用同一外部幂等号查询或进入待对账/人工处置，不能盲目发起新支付。明确可重试失败遵循退避、次数和审计；所有尝试形成一条关联链。**SANDBOX** 验证实际补单/查询协议。 |
| BD-12 | P0 | SIM, INT | 在原始落库、标准化、去重、自动入账待复核写入、支付尝试更新、交易写入、余额更新和审计写入处注入异常。 | 每一阶段要么回滚本地同一业务事务，要么留下规定的可恢复任务状态；不存在“已执行无交易”“交易无余额变化”“标准化无原始消息”或“成功无审计”状态。 |
| BD-13 | P0 | INT | 检查银行数据页面、网络请求、前端状态管理、缓存、浏览器存储和错误处理；用原始报文中故意加入银行专有字段作探针。 | 前端仅调用 FINFLOW API，查询业务表/投影；探针字段不出现在响应、DOM、缓存、控制台、路由参数或导出。未启用/空态/失败态不伪造余额、流水、回单或支付事实，失败含请求编号。 |
| BD-14 | P1 | SIM, INT, RA-DATA | 对多页窗口、时区边界、夏令时适用银行、历史补拉、账户状态变更和金额精度执行拉取/标准化。 | 分页无漏项/重复项，时间窗口与银行/系统时区有明确规则，金额精确；账户映射与企业范围正确。**RA-DATA** 仅用于真实历史数据的字段、时区和分页窗口复核。 |
| BD-15 | P1 | INT, RA-DATA | 检查临时真实业务数据在数据库、日志、审计、导出、对象存储、测试报告和支持工单中的访问、脱敏、加密、最小保留与清理。 | 仅获批角色和环境可访问；导出受限并审计；测试证据使用掩码；到期数据按批准方案清理/归档。该用例受风险接受影响，未完成专项决策不得提升为生产证据。 |
| BD-16 | P1 | INT, PROD | 触发任务失败、原始层写入失败、解析失败、去重冲突、回执乱序和保留清理；检查指标、告警、值班与审计。 | 监控按企业/任务/适配器版本聚合，不泄露敏感数据；告警携带请求编号、任务号和安全摘要。定时任务责任人、升级路径和 SLA 未决时，记录为发布风险并获得书面批准。 |
| BD-17 | P0 | SANDBOX | 使用银行提供的 SDK/API、测试证书与授权沙箱逐项验证鉴权、签名/验签、时间戳、防重放、分页、错误码、限额、超时、重复/乱序回执、查询/补单和网络出口。 | 调用仅经后端适配器；银行侧请求号、内部请求编号、外部幂等号和业务对象可双向追溯。验证证书与凭据不泄露。未完成前，真实接入状态必须为未验证，不得宣称银行直联可用。 |
| BD-18 | P0 | PROD | 候选生产环境检查适配器版本、生产端点闸门、密钥管理引用、网络白名单、日志级别、30 天策略、原始层访问策略、告警和只读烟囱。 | 不含测试凭据、真实凭据明文或前端 SDK 依赖；生产外部调用仅在另行批准的真实接入放行后允许。本 v0.2 底座验收默认不发起真实资金或银行查询。 |

## 6. 联调顺序与出口条件

1. **数据模型与隔离**：执行 BD-01、BD-04、BD-05，确认企业过滤、原始层禁入前端和映射版本追溯。
2. **同步与原始层**：执行 BD-02、BD-03、BD-08，确认手动/定时统一任务模型、先落原始层和 30 天策略。
3. **标准化与去重**：执行 BD-06、BD-07、BD-14，确认组合唯一、版本兼容和分页窗口。
4. **回执与领域一致性**：执行 BD-09 至 BD-12，确认异步状态、重复/乱序、重试与余额/交易/转账一致性。
5. **前端与可观测性**：执行 BD-13、BD-16，确认前端事实边界、请求编号、告警和失败可恢复性。
6. **风险接受与银行验证**：在专项数据使用批准后执行 BD-15；SDK/API、沙箱材料就绪后执行 BD-17；候选生产上线前执行 BD-18。

每一阶段的 P0 失败均阻断后续阶段。所有 P0 通过前，禁止将模拟器结果标记为真实银行集成可用，禁止启用真实资金相关能力。
