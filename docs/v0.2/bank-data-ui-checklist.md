# FINFLOW v0.2 银行数据管道 UI 验收清单

> 适用版本：v0.2
>
> 依据：[UI/UX 规范](../ui-specification.md)与[产品需求第 15 节](../product-requirements.md)。
>
> 目标：验收银行数据接入后，前端以安全、可解释、只读的方式呈现 FINFLOW 业务事实和查询投影，不直接接触银行。

## 1. 范围与不可逾越的边界

本清单覆盖 v0.2 银行数据管道的前端体验：定时和手动同步触发、同步任务与请求编号、银行数据查询、异步回执、组合去重、受控追溯、企业隔离和响应式呈现。

前端只调用 FINFLOW API，且只读取服务端按企业、账户和角色过滤后的业务表或查询投影。以下内容不得通过浏览器请求、前端状态、页面、下载、日志详情、错误提示或开发者可见的调试数据暴露：

- 银行 SDK/API 响应、银行专有字段和原始请求/响应报文。
- 原始同步日志全文、完整银行账户号、私钥、证书、凭据、访问令牌和会话令牌。
- 可识别的完整收款账号、原始文件载荷、未脱敏错误堆栈或跨企业资源标识。

原始报文、标准化记录、业务事实和查询投影属于不同层次。前端不得允许用户编辑其中任何一层，也不得以本地缓存、前端去重或前端轮询结果覆盖服务端状态。

## 2. 页面与权限边界

沿用“银行接入”下的连接监控、采集任务、失败日志和五类数据查询入口；自动入账、资金管理仍是独立域。银行数据查询只可跳转到已有的自动入账或资金管理详情，不能出现修改资金、审批、复核、制证、重放银行请求或直接更新余额的入口。

| 能力 | 前端入口/页面 | 最低权限 | 可见动作 | 禁止动作 |
| --- | --- | --- | --- | --- |
| 查看同步状态与计划 | 直联状态监控 | `operation:monitor` | 查看计划摘要、健康、最近结果 | 暴露连接密钥或原始报文 |
| 查看任务 | 任务执行 | `operation:monitor` 或 `bankdata:view` | 查看任务、请求编号、脱敏参数、状态时间线 | 修改任务参数或覆盖结果 |
| 手动发起同步 | 任务执行或对应数据查询页 | `bankdata:sync:trigger` | 发起当前账户/范围的同步 | 绕过企业、账户、幂等或审计检查 |
| 重试可重试任务 | 任务执行详情 | 后续独立重试权限 | 显示确认后请求服务端重试 | 重试成功任务或生成重复业务事实 |
| 查询余额/流水/回单/对账单/支付/代发 | 对应银行数据查询页 | 对应 `bankdata:*:view` | 筛选、查看列表与安全详情 | 编辑、删除、导入原始报文 |
| 查看受控追溯 | 任务或数据详情抽屉 | 与对象的查看权限一致 | 查看来源、任务、时间、请求编号、状态和保留状态 | 查看原始报文正文或银行私有字段 |

权限加载中采用骨架或保守隐藏，不能短暂出现同步、重试或敏感详情操作。没有查看权限时隐藏导航；通过深链接、搜索参数或历史 URL 访问时进入现有 403 页面。服务端仍是每一次资源、查询和动作请求的最终鉴权者。

## 3. 任务触发与状态表达

### 3.1 定时同步

- 定时计划在直联状态监控和任务执行页以只读方式展示：计划名称、账户/连接范围、频率、最近一次开始和结束时间、最近结果、下次计划时间、最近请求编号。
- 前端不得在浏览器中自行调度，也不得以页面打开、自动刷新或后台轮询触发银行同步。
- 定时任务的健康状态只能由 FINFLOW API 返回。没有运行结果时显示“暂无运行记录”，不能显示“正常”。
- 计划被暂停、未配置、失败或需要人工处理时使用文字、图标和颜色共同表达，并提供任务详情或联系运营入口。

### 3.2 手动同步

手动同步入口仅在有 `bankdata:sync:trigger` 权限且已选择允许的企业内账户/范围时显示。触发流程为“选择账户和时间范围 -> 确认影响 -> 创建 FINFLOW 同步任务 -> 查看任务状态”，而不是“浏览器直接请求银行”。

- 确认弹窗展示账户掩码、日期范围、任务类型、去重规则说明和“数据由 FINFLOW 服务端同步”的提示。
- 点击确认后按钮进入 loading 并禁用重复提交；成功仅表示“同步任务已创建”，必须显示任务编号和请求编号，不能表示“银行数据已更新”。
- 若服务端返回同一幂等任务已存在，提示“已复用进行中的同步任务”，展示已有任务编号、当前状态和请求编号，不创建第二条任务记录。
- 任务创建失败时保留用户选择，显示安全错误摘要、请求编号和重试入口；重试结果以服务端幂等响应为准。
- 用户离开页面不取消后台任务。返回查询页时，应通过 API 读取最新任务状态，不能凭本地 loading 状态猜测成功或失败。

### 3.3 统一任务状态

| 服务端状态 | 页面文字 | 允许的用户理解与动作 | 不允许的表达 |
| --- | --- | --- | --- |
| 已创建/排队中 | 等待同步 | 可查看任务编号和请求编号 | 已开始拉取、已更新数据 |
| 执行中 | 正在同步 | 显示阶段和最近更新时间，可离开页面 | 已完成、余额已刷新 |
| 成功 | 同步完成 | 显示处理数量、重复数量、异常数量和结果入口 | 暗示所有记录都已入账或已制证 |
| 部分成功 | 已完成，存在待处理项 | 显示有效、重复、异常各自数量和筛选入口 | 全部成功 |
| 失败 | 同步失败 | 显示可公开原因、请求编号和符合权限的重试入口 | 银行拒绝的内部详情或堆栈 |
| 已取消 | 已取消 | 说明未继续处理的范围 | 成功或已回滚全部业务事实 |
| 需人工处理 | 等待人工处理 | 跳转到有权限的复核/对账视图 | 自动完成或已支付 |

## 4. 只读数据查询体验

### 4.1 通用查询规则

余额、流水、回单、对账单和代发五类页面均使用“账户 + 时间范围 + 状态/关键字”的紧凑查询区。余额使用当前快照；其余页面默认最近 30 天，但页面初始不自动拉取全量数据，必须由用户执行查询或恢复已确认的 URL 筛选条件。

- 查询期间保留筛选和上次成功数据，在表格区域显示 loading，不清空为零或空表。
- 每个结果区展示数据来源、最后同步时间和相关同步任务/请求编号；这些字段来自 FINFLOW API，而非银行原始响应。
- 行点击或查看图标打开右侧详情抽屉，抽屉包含概览、关联对象、状态时间线/审计和受控追溯摘要；关闭后恢复原筛选、分页、滚动位置和焦点。
- 账号默认掩码；金额右对齐，人民币保留两位小数；长流水号、任务号和请求编号可复制但不扩张表格列宽。
- 查询域严格只读。前端不得在详情抽屉内提供编辑、删除、人工复核、制证、审批、执行转账或更新账户余额按钮。

### 4.2 各类结果的最低可见字段

| 查询页 | 列表最低字段 | 详情允许呈现 | 关键禁止项 |
| --- | --- | --- | --- |
| 余额 | 账户名称、掩码账号、可用/账面余额、币种、更新时间、来源状态 | 同步任务、请求编号、更新时间 | 以 `0.00` 代替未获取余额 |
| 流水 | 流水号、日期、脱敏摘要/对方、方向、金额、账户、状态、来源 | 关联自动入账/交易引用、去重摘要、任务时间线 | 原始银行字段或复核/制证操作 |
| 回单 | 回单号、关联支付/流水号、日期、金额、状态、来源 | 安全元数据、任务、请求编号 | 未提供受控文件时显示伪下载按钮 |
| 对账单 | 账期、账户、期初/期末余额、收入、支出、差异状态、来源 | 差异关联和受控追溯摘要 | 直接修改余额或差异结论 |
| 代发 | 批次号、类型、笔数、金额合计、账期、状态、来源 | 掩码明细、任务、回执状态 | 无权限展示收款人完整信息 |

## 5. 异步回执与支付状态

支付详情与银行数据查询中的回执状态必须以服务端标准化状态为准。银行受理、网络超时、未知结果或收到技术回执均不是付款成功。

| 业务阶段 | 建议标签 | 前端反馈 | 可跳转对象 |
| --- | --- | --- | --- |
| 已提交银行 | 已提交，等待回执 | 显示外部处理尚未确认、请求编号和最近查询时间 | 同步任务/支付详情 |
| 银行受理 | 银行已受理，等待结果 | 不显示“付款成功”；提示仍可能被后续回执拒绝或需对账 | 回执时间线 |
| 超时/未知 | 结果待确认 | 提示不要重复发起支付；按权限显示查看任务/对账入口 | 同步任务、对账详情 |
| 等待对账 | 等待对账确认 | 保持金额和余额为既有服务端事实，不自行推算 | 对账与追溯 |
| 最终成功 | 已确认成功 | 仅在服务端回执/对账确认后显示，可查看关联交易 | 交易、转账详情 |
| 最终失败/拒绝 | 未成功 | 显示安全原因摘要和请求编号；不显示内部银行错误码正文 | 支付详情 |

刷新、重新打开详情、轮询或重试查询只更新页面状态，不生成新支付请求。显示状态转换时，时间线至少包含变更时间、来源、请求编号、结果和可公开说明。

## 6. 组合去重与可解释反馈

银行流水去重由服务端以企业范围内的银行流水号，以及“银行账户 + 交易时间 + 金额”组合规则共同判定。前端不保存判重缓存、不在浏览器端自行决定重复，也不允许用户绕过提示强制写入。

| 结果 | 用户可见反馈 | 可执行动作 | 禁止行为 |
| --- | --- | --- | --- |
| 新记录 | 显示“已写入待复核/查询投影”，包含任务号、请求编号和数量 | 查看结果或对应自动入账队列 | 表述为已入账、已制证或已付款 |
| 完全重复 | 显示“未新增业务记录”，说明命中银行流水号或组合规则的安全摘要 | 查看已有记录或任务详情（仍逐项鉴权） | 暴露其他企业记录或完整敏感字段 |
| 部分重复 | 分别显示新增、重复跳过、异常待处理数量 | 通过预设筛选查看各类结果 | 将批次整体误报为全失败或全成功 |
| 去重规则无法判定 | 显示“需人工处理”，保留任务/请求编号 | 跳转有权限的人工复核或对账视图 | 前端自动合并、删除或猜测归属 |

重复命中说明只展示当前企业且当前用户有权访问的已有记录摘要，例如内部记录号、状态和时间；若无权查看关联对象，显示通用的“已存在匹配记录”，不得透露对象是否存在、归属账户或金额。

## 7. 30 天原始数据的受控追溯

原始报文按接收时间保留 30 天是后端受控事实，前端不得提供原文预览、下载、复制或以浏览器缓存保留。前端仅可在有对象查看权限的任务或业务详情中展示“受控追溯摘要”。

| 追溯项 | 允许显示 | 不允许显示 |
| --- | --- | --- |
| 保留状态 | 在保留期内、已到期清理/归档、不可用 | 原始内容、存储路径、对象存储签名 URL |
| 关联性 | 同步任务号、内部请求编号、银行侧请求号的脱敏/受控标识、标准化记录号、业务对象号 | 银行完整请求/响应、银行私有字段 |
| 时间与结果 | 接收时间、标准化时间、处理结果、安全摘要、清理/归档审计时间 | 内部堆栈、凭据、证书、令牌 |
| 到期处理 | 显示“原始数据已按策略清理或归档”，保留审计引用 | 让用户恢复、编辑或绕过保留策略 |

若原始数据尚在保留期但当前用户不具备对象权限，页面仍只返回 403 或安全空结果。若原始数据已到期，业务记录、标准化结果、任务和审计时间线仍按保留策略可查；UI 不得将“原始数据不可用”解释成“该业务不存在”。

## 8. 状态、空态、失败与 403 验收

| 场景 | 页面表现 | 验收要点 |
| --- | --- | --- |
| 未配置/未启用连接 | 显示“未配置”或“未启用”，不显示正常、成功或 `0.00` | 不自动触发同步，不伪造银行数据 |
| 模拟环境 | 在标题、结果和详情中显示“模拟数据” | 模拟结果不与真实来源混排且无误导性成功文案 |
| 加载 | 骨架尺寸与表格行高稳定 | 不闪现无权操作、无数据或错误状态 |
| 查询无结果 | 区分“当前筛选无数据”“暂无同步结果”“未启用/未配置” | 提供清除筛选、查看任务或配置入口，按权限显示 |
| 网络/服务失败 | 保留筛选和上次成功数据，显示安全错误摘要、请求编号、局部重试 | 不丢失筛选，不显示堆栈或银行原始错误 |
| 权限撤销/会话失效 | 重新请求后清除已无权数据，转登录或 403 | 不保留旧企业数据或可操作按钮 |
| 跨企业/无权深链接 | 显示 403 或安全空结果 | 不泄露对象存在性、任务标题、金额或账户信息 |
| 任务完成后刷新 | 使用 API 获取最新状态和结果 | 不根据本地计时器直接判定完成 |

## 9. 桌面与移动端约束

### 桌面端（`>= 1024px`）

- 使用现有可折叠的“银行接入”侧栏分组、`24px` 内容边距和固定操作列。
- 同步任务和银行查询采用高密度服务端表格；任务号、请求编号、状态、金额和最近更新时间固定为关键列，其余字段进入详情抽屉。
- 顶部筛选区保持一行或两行稳定布局；手动同步按钮放在标题行右侧，页面仅保留一个主操作。
- 详情抽屉包含概览、关联对象、状态时间线/审计和受控追溯摘要；关闭后回到触发元素。

### 移动端（`< 768px`）

- 三级导航和筛选条件进入独立抽屉；同步确认、任务详情和数据详情为单列，不出现双栏对照。
- 列表优先保留时间、状态、金额、任务/请求编号和关联号；其余信息进入详情。长编号使用截断和复制，不能撑破容器。
- 状态标签、错误摘要、请求编号和追溯保留状态允许换行；触控目标最小 `44 x 44px`。
- 同步按钮、重试按钮和支付回执状态不得被软键盘、固定底栏或安全区遮挡；用户完成确认后必须能看到任务编号和请求编号。

## 10. 联调验收清单

下列项目应在前后端联调时逐项记录环境、企业、测试账户、操作者角色、请求编号、截图/录屏和结果；测试数据必须是已获授权的隔离数据。

- [ ] 前端网络请求只指向 FINFLOW API；没有浏览器直接调用银行域名、SDK 或下载原始报文。
- [ ] 定时与手动同步均产生同一任务模型中的任务、任务编号和请求编号；手动入口不绕过鉴权、幂等和审计。
- [ ] 对同一账户范围连续触发、网络重试和刷新页面时，页面可解释地复用或展示已有任务，且不出现重复业务结果。
- [ ] 同步任务的排队、执行、部分成功、失败、取消、人工处理和完成状态均有文字、图标和安全反馈。
- [ ] 余额、流水、回单、对账单、代发五类查询结果均来自只读查询投影，详情没有写入动作。
- [ ] 银行受理、超时和未知结果均呈现为中间状态；只有服务端最终确认后才显示“已确认成功”。
- [ ] 组合去重反馈显示新增、重复、异常的计数与安全依据摘要；无权限时不泄露被命中的记录。
- [ ] 受控追溯只展示保留状态、关联编号、时间、结果和审计摘要；30 天期满后不再显示或缓存原始内容。
- [ ] 账户、收款方、凭据、令牌、原始载荷和堆栈在表格、抽屉、下载、toast、错误、浏览器状态和日志中均已脱敏或不可见。
- [ ] 企业 A 不能通过筛选参数、任务号、流水号、回执号或历史 URL 查看企业 B 的连接、任务、业务结果或追溯摘要；结果为 403 或安全空结果。
- [ ] 在 `1440px`、`1024px` 和 `375px` 宽度下，任务状态、请求编号、金额、错误提示和操作按钮无重叠、截断误读或横向页面溢出。

## 11. 关键决策

1. v0.2 前端是 FINFLOW API 的只读消费者，银行适配、原始报文和同步日志全部留在服务端受控边界内。
2. 定时与手动同步是同一任务和审计模型的两种触发方式；UI 以任务编号、请求编号和服务端状态解释进度，不以本地状态猜测结果。
3. 支付受理、超时和未知回执均为中间状态，不能被设计为付款成功；最终状态由异步回执或对账确认驱动。
4. 去重由企业范围内的服务端组合规则裁决，前端只解释结果并按权限呈现已有记录摘要。
