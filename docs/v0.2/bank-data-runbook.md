# FINFLOW v0.2 银行数据管道运行手册

本手册覆盖 v0.2 银行数据接入底座的上线前检查、受控运行、健康检查、告警占位和回滚。它适用于当前仅有模拟适配器的版本，不授权接入真实银行 SDK、API、证书、私钥、访问令牌或生产密钥。

## 运行边界

- 银行 SDK/API 仅能在后续经单独批准的后端适配器版本中接入；当前版本的真实银行 SDK/API 调用次数基线为 `0`。
- 当前数据管道使用 `MOCK` 适配器。任何同步任务、日志、监控面板或告警都必须把结果标记为模拟，不能表示真实余额、真实流水、真实回单、真实支付或真实银行连通。
- 前端只读取 FINFLOW API 的企业范围业务投影；原始报文、同步日志和银行专有字段不作为普通前端资源提供。
- 凭据、私钥、访问令牌、签名原文和完整账号不得写入仓库、部署变量清单、原始报文、同步日志、审计、导出、告警或客户端。不得用本手册中的任何占位名称替代真实机密。

## 上线前门禁

在发布窗口开始前，`Release contract`、后端 Maven 构建和前端 pnpm 构建必须全部通过。`Release contract` 会验证：

1. Flyway 迁移按 V1、V2、V3、V4 存在，且 V4 为 `V4__bank_data_access_foundation.sql`。
2. V4 定义 `bank_data_raw_message.retention_until`，同步执行器将其设置为接收时间加 30 天。
3. 定时同步入口、授权手动同步入口和请求编号传递已存在。
4. 原始报文到期清理任务必须是受调度的任务，并同时覆盖保留截止时间与清理审计；只有设置 `retention_until` 不构成 30 天保留任务已完成。
5. 已提供按请求编号的授权检索入口；任务、日志、原始报文、标准化流水和审计事件必须能以同一请求编号受控关联。
6. `bankdata` 模块不包含 HTTP 客户端或真实银行调用痕迹，且仓库中不出现明确命名的银行或金蝶生产凭据。

当前 CI 若因第 4 或第 5 项失败，表示 v0.2 运行保障尚未具备，发布必须停止，不能通过手工跳过检查上线。

## Flyway V4 预检

1. 在隔离环境从空库执行 V1 -> V2 -> V3 -> V4，确认 `flyway_schema_history` 的版本、校验和和执行顺序正确。
2. 从已完成 V1/V2/V3 的副本执行 V4 增量迁移，确认 `company`、`bank_data_sync_task`、`bank_data_raw_message`、`bank_data_statement` 和 `bank_data_sync_log` 可创建且外键、企业范围索引和去重唯一约束有效。
3. 验证 V4 将既有用户、银行账户和连接运营对象回填到受控企业范围；不得出现 `company_id` 为空的可查询业务对象。
4. 对迁移后的库执行只读核验：`bank_data_raw_message` 必须包含 `retention_until` 及其索引，`bank_data_sync_task` 与 `bank_data_sync_log` 必须包含 `request_id` 及企业范围检索索引。
5. 记录迁移版本、开始/结束时间、数据库实例标识、操作者和结果。失败时停止应用扩容，按既有部署指南的数据库回滚原则处理；不得手工修改 Flyway 历史表。

## 中信 SDK 接入准备

本节只定义真实 SDK/API 交付后的验证条件。当前仓库不包含中信 SDK、证书、密钥库、私钥、测试账号、端点或真实报文；在下列条件全部满足并经单独批准前，真实适配器保持未启用，真实外部调用计数必须为 `0`。

### Java 17 与 Java 8 SDK 兼容性验证

中信 Java 8 SDK 即使字节码版本兼容 Java 17，也必须在本机和测试服务器各完成一次离线验证。验证使用银行正式交付的受控副本，不把 JAR、依赖、证书或输出写入仓库、构建缓存、应用日志或发布包。

1. 记录本机与测试服务器的操作系统、CPU 架构、JDK 发行版、完整 Java 17 版本和时区；两端应使用与候选生产相同的 JDK 主版本和运行参数基线。
2. 在隔离目录执行 `java -version`、`jdeps --multi-release 17 --ignore-missing-deps <sdk-jar>`，并用 `javap -verbose` 检查银行声明的入口类。Java 8 编译物的类文件主版本应不高于 `52`；任何依赖 JDK 内部 API、已移除模块或未声明的本地库均阻断继续。
3. 仅执行银行提供的离线加载/自检或最小初始化验证，禁止配置端点、测试账号、证书、令牌、签名请求或网络出口。成功标准是 SDK 可在 Java 17 进程中加载并正常关闭，且网络调用计数为 `0`。
4. 将 JDK 版本、SDK 名称与校验摘要、依赖清单摘要、命令结果、操作人、时间和结论写入受控发布证据系统；不得记录 SDK 内容、证书路径细节、机密或完整错误载荷。
5. 本机通过不代表测试服务器通过；测试服务器通过也不代表授权沙箱或生产准入。SDK 版本、JDK、操作系统、CPU 架构或依赖变更后必须重新验证。

### 证书目录、日志目录与敏感配置注入

证书和 SDK 目录仅在银行材料经批准交付后由平台管理员在目标服务器创建，不能由应用启动脚本下载、生成或复制。建议使用独立的只读挂载目录和最小权限运行账户：

| 资源 | 权限与运行要求 |
| --- | --- |
| SDK 目录 | 仅应用运行账户可读取和执行；部署账户可更新；不允许 Web 进程、普通用户或前端容器写入。目录中只放受控交付物，版本和摘要在发布证据中登记。 |
| 证书/密钥库目录 | 仅应用运行账户可读取，目录禁止组和其他用户访问，禁止列目录、下载、导出、备份到普通日志或镜像层。应用不得回显文件名、内容或口令。 |
| 日志目录 | 应用运行账户可追加写入，日志采集账户仅可读取；目录不能与 SDK、证书或临时原始报文目录共用。轮转、保留和访问均须审计。 |
| 原始报文受控存储 | 与应用日志分离，加密或使用受控密文存储；普通用户、前端和日志采集账户不得直接读取。 |

使用 KMS、密钥管理服务或部署平台的短期挂载/注入机制提供机密引用。CI、镜像、代码库、环境清单和命令历史只能包含非秘密的引用标识与版本，不能包含值。注入前后分别核对：运行账户权限、注入范围、日志脱敏、重启后的轮换行为和撤销访问后的失败行为。任何明文机密、世界可读目录、证书写入日志或将机密作为 JVM 参数的情况都阻断发布。

### 网络白名单、IP 与 MAC 变更

当前模拟版本不申请、不使用也不验证银行网络出口。银行授权沙箱或真实接入准备时，网络变更必须走变更单并在获批窗口实施：

1. 由网络团队确认固定出口 NAT IP、目标域名/IP、端口、DNS、TLS 策略、代理要求和允许时间窗；将银行提供的规则、责任人和回退时间登记在变更单，不写入本仓库。
2. 银行如要求 IP 白名单，提供实际固定出口地址及变更前后的连通性验证记录。禁止用开发机、动态公网地址或前端浏览器出口替代服务器出口。
3. 云环境的 MAC 地址通常不是稳定的跨实例身份。只有银行书面要求 MAC 白名单时，才记录目标网卡的受控资产标识、实例替换影响和审批；不得假设容器或弹性实例的 MAC 可作为长期准入凭据。
4. 网络、IP、MAC、DNS、代理、证书链或出口实例任何一项变更后，先撤销旧规则或将其设为短期重叠，再在授权沙箱完成最小连通性验证。未经真实接入批准，验证不得调用业务接口或发起资金动作。
5. 回滚时先禁用真实适配器和调度，再撤销新增出口和白名单规则；保留变更单、时间线、请求编号和脱敏网络证据。

## 同步运行与健康检查

### 手动同步

由具备 `bankdata:sync` 权限的已认证用户触发 `POST /api/bank-data/sync-tasks`。每次演练必须记录返回的任务编号、`X-Request-Id`、企业范围、适配器代码、开始/完成时间、原始记录数、标准化记录数、重复数、无效数和结果。

成功条件：适配器代码为 `MOCK`，任务结果为成功或可解释的部分成功，生成的流水可通过 FINFLOW API 查询，原始内容不出现在普通页面或日志中。若同步失败，保留任务和脱敏日志，用请求编号检索，不要重试到产生重复业务事实。

### 定时同步

仅在演练环境显式启用定时同步。启用后，在一个调度周期加宽限时间内确认每个允许的模拟连接最多创建一次受控任务，并核对任务请求编号、企业范围、模拟标签和日志。定时与手动入口同时运行时，重复命中必须计入重复数并返回既有事实，不能产生第二条标准化流水。

生产发布的默认姿态是不开启任何真实银行调度；是否启用模拟调度须由发布单明确记录。定时任务不得以“连接成功”或“已同步银行数据”描述模拟结果。

定时任务演练还必须确认：应用只运行一个授权调度实例或具备分布式互斥；调度开关、固定延迟、时区和责任人已记录；重启不会补发超出幂等范围的任务；禁用开关后不再创建新任务。真实 SDK/API 未批准前，定时任务只允许 `MOCK` 适配器，真实银行调用计数持续为 `0`。

### 健康检查和告警占位

平台应保留以下告警规则占位，并在上线前指定责任人、接收人、升级路径、静默时间和处置 SLA。规则名称可按监控平台调整，但触发条件不得降低：

| 告警占位 | 触发条件 | 首要处置 |
| --- | --- | --- |
| `BankDataScheduledSyncMissing` | 启用模拟定时同步后，一个调度周期加宽限时间内没有新任务或心跳。 | 检查调度开关、应用实例、连接状态和请求编号日志；不要补发真实银行请求。 |
| `BankDataManualSyncFailed` | 手动任务状态为 `FAILED`、出现未解释的 `PARTIAL`，或请求编号没有对应日志。 | 按请求编号检查任务和脱敏日志，修复后用新的受控演练重试。 |
| `BankDataSyncStale` | 任务长期处于 `RUNNING`，超过发布单定义的超时阈值。 | 停止重复触发，保留原始与同步证据，按幂等和补单流程人工处置。 |
| `BankDataRetentionOverdue` | 已过 `retention_until` 的原始报文未被清理或归档，或没有清理审计。 | 停止放行，先完成受控清理/归档、豁免和审计验证。 |
| `BankDataUnexpectedExternalCall` | 非生产或生产运行中，真实银行 SDK/API 调用计数不为 `0`。 | 立即禁用该适配器/调度并保留审计证据，按安全事件处理。 |
| `BankDataTenantBoundaryFailure` | 企业隔离冒烟返回了另一企业对象、泄露存在性或缺失访问审计。 | 停止发布和相关查询入口，修复服务端范围过滤后重测。 |
| `BankSdkCompatibilityFailure` | Java 17 离线加载验证失败、SDK/JDK/OS/依赖版本与已批准基线不一致，或发现未声明的本地库依赖。 | 禁止部署或回退到模拟适配器，保留脱敏验证摘要并由供应商/平台团队处理。 |
| `BankCredentialOrDirectoryViolation` | 证书/密钥库目录权限过宽、日志目录混放敏感文件、密钥出现在进程参数/日志，或注入撤销后应用仍可访问。 | 停止发布，撤销访问并轮换受影响机密；按安全事件保留审计证据。 |
| `BankNetworkChangeMismatch` | 固定出口 IP、批准的 DNS/端口/代理、MAC 资产或白名单变更与变更单不一致。 | 禁止真实适配器启用，回退网络规则并由网络团队复核。 |

## 原始报文 30 天保留验证

1. 在隔离环境执行一次模拟同步，记录原始报文接收时间与 `retention_until`；两者的差必须为 30 天。
2. 通过受控测试数据创建已到期与未到期两类原始报文。运行清理任务后，验证已到期数据按批准策略清理或归档，未到期数据不受影响。
3. 验证每次清理或归档产生只追加的审计记录，至少包含任务/批次标识、企业范围、处理数量、策略、豁免标记、操作者或调度身份、请求编号、时间和结果；审计记录中不含原始载荷或机密。
4. 对争议或审计保留豁免执行一次演练，确认豁免在到期清理中被跳过，并能由授权人员查询到豁免原因和失效时间。
5. 在清理任务、审计和豁免机制尚未实现或未验证前，不得把 V4 的 `retention_until` 字段当作保留策略已生效，且不得发布 v0.2。

清理任务启用后，还应设置 `BankDataRetentionOverdue` 告警并每日至少核对一次：到期记录数量、清理/归档数量、豁免数量、失败数量和清理审计完整性。清理失败只能重试受控清理作业，不能为避免告警而直接删除数据库行或关闭审计。

## 请求编号检索与追溯

请求编号是银行数据管道的主要运行关联键。操作人员只可在当前企业、当前角色授权范围内，以精确请求编号检索同步任务、脱敏同步日志、原始报文摘要、标准化流水、业务关联和审计事件。

检索演练必须证明以下关联完整：`request_id -> task_no -> bank_request_no -> raw message digest -> normalized statement -> audit event`。查询结果应返回脱敏摘要、时间和状态，而不是原始载荷、凭据或完整账号。若当前 API 尚未提供授权的请求编号筛选，发布单必须标为阻断项，直到该入口及其企业范围测试完成。

## 企业隔离冒烟

1. 为企业 A 创建模拟同步任务，记录其任务 ID、流水 ID 和请求编号。
2. 使用企业 B 的有效会话分别访问企业 A 的任务详情、标准化流水详情和请求编号检索；每项均应被服务端拒绝，且响应不得确认企业 A 对象存在。
3. 在企业 B 触发模拟同步，确认任务、日志、原始摘要和流水只关联企业 B；列表、统计和对账不能包含企业 A 数据。
4. 记录会话所属企业、请求编号、端点、预期结果、实际状态码和审计事件。任何跨企业可读、可写、可推测对象存在或没有审计记录的结果都阻断发布。

## 非生产真实业务数据临时例外

测试与非生产环境可临时使用真实银行业务数据，但这不是接入真实银行 SDK/API 的许可，也绝不允许使用真实凭据、私钥或访问令牌。每个例外环境必须由部署平台设置以下非秘密标签，并在到期前移除：

| 标签 | 要求 |
| --- | --- |
| `data-classification=bank-business-data-temporary` | 明确该环境包含临时真实业务数据。 |
| `bank-data-exception=approved-temporary` | 关联已批准的风险接受记录。 |
| `exception-expires-on=YYYY-MM-DD` | 固定失效日期；到期即停止访问并清理或归档。 |
| `data-owner` 与 `approval-reference` | 指定数据负责人和审批追溯编号，不填写账号、密码或令牌。 |

访问此类环境必须记录访问主体、时间、环境、企业范围、操作/查询类型、返回记录数、请求编号、结果和审批引用。访问权限遵循最小化和按时限授予；禁止原始报文导出、复制到个人设备、写入普通应用日志或用于生产以外的目的。每周复核例外标签、访问审计和到期时间；到期后撤销访问并完成处置记录。

## 发布、回滚与证据

发布前保留以下证据：全部 CI 结果、V4 迁移记录、手动/定时模拟同步结果、30 天保留任务演练、请求编号追溯、企业隔离冒烟、告警规则配置截图或链接，以及外部调用计数为 `0` 的监控记录。SDK 到位后的单独放行还必须包含本机/测试服务器 Java 17 兼容性记录、目录权限核验、敏感配置注入与撤销演练、网络白名单/IP/MAC 变更单和授权沙箱最小连通性记录。

若发现真实外部调用、企业隔离失败、原始报文超期未处理、请求编号无法追溯、告警未配置、SDK 兼容性失败、目录/注入违规或网络白名单不一致，立即停止放量，禁用真实适配器与所有银行数据调度，撤销新增网络规则和机密挂载，保留脱敏任务和审计证据，再回切到上一已验证应用版本。数据库迁移不采用手工回退：按备份恢复或经评审的前向修复迁移处理，并重新完成本手册所有阻断项验证。
