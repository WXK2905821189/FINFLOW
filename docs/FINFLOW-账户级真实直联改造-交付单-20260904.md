## 一、这次改了什么

### 1. 问题根因（不是"mock 被当真"，是"状态算错了行"）

| # | 缺陷 | 位置 |
|---|---|---|
| A | 后端连接状态无 per-provider 维度：全局 `enabled/status` 只由 CMB 一个开关决定，文案写死"招行 CMB" | `ConnectionOperationsService` |
| B | 账户页「直联状态」列用**全局布尔**渲染在**每一行**：CMB 一接通，中信行也变绿 | `frontend/.../bank-access/pages.tsx` |
| C | V1 迁移种了 2 个中信模拟账户（带模拟余额 986400.52 / 300000）作为历史遗留 | `V1__init_rbac_and_bank_accounts.sql` |

判定粒度按小棵要求进一步**从 per-provider 细化到 per-account**（招行接口天生是账户维度：`DCLISACC` 返回可经办账号清单，`NTQADINF` 余额 / `trsQryByBreakPoint` 流水都以 `accnbr` 为请求主键，单账户独立成败）。

### 2. 实现内容

**后端**

| 文件 | 改动 |
|---|---|
| `bank/AccountDirectStatusService.java`（新增） | 账户级判定引擎。两证：`REAL` 装配（registry 中该 bankCode 有 REAL 适配器）+ 该账户最近一次真实同步 `SUCCEEDED` 心跳。三态 `DIRECT_CONNECTED` / `ONBOARDED` / `NOT_CONNECTED`，带 `lastRealSyncAt` 证据时间戳。**模拟适配器跑出来的成功不算证据** |
| `bankdata/aggregation/BankDataAdapterRegistry.java` | 新增 `realAdapterCodes()` / `isRealProvider()`：从 bean 装配推导"哪些银行真的接了"，不读配置、不读 DB |
| `bank/dto/BankAccountResponse.java` | 增加 `directStatus` + `lastRealSyncAt` 两个行级字段 |
| `bank/BankAccountService.java` | 列表走批量解析（一次聚合查询，无 N+1）；建档/更新也返回该行状态 |
| `operations/ConnectionOperationsService.java` | provider 层状态改为按 registry 装配推导，每行独立 `REAL`/`NOT_CONNECTED`；`enabled/status/message/supportedProviderTypes` 全部动态，**不再透传 DB 的 `connection_profile.status`**（可漂移），删掉写死的"招行 CMB"文案 |

**前端**

| 文件 | 改动 |
|---|---|
| `modules/bank-access/types.ts` | `BankAccount` 增加 `directStatus` / `lastRealSyncAt` |
| `modules/bank-access/pages.tsx` | 删除全局 `connected` 布尔与写死文案，账户行**消费行级 `directStatus`** 三态渲染 |
| `modules/shared/format.ts` | 三态配色语义（`DIRECT_CONNECTED` 绿 / `ONBOARDED` 金 / `NOT_CONNECTED` 灰红），不再是"非红即蓝" |
| `modules/shared/components.tsx` | `DirectStatusTag`：三态中文标签 + 证据时间 tooltip |

### 3. 顺带修掉的 4 处回归（mock-clean 改造遗留，非本轮引入）

全量测试时有 11 条失败，根因是并发进行的「删除通用 MOCK 适配器 + registry 失败即关闭」改造未同步更新旧 mock-first 契约测试。**已全部修复，全量恢复绿**：

| # | 问题 | 修复 |
|---|---|---|
| 1 | `BankDataQueryService.tasksById()` 的 `select` 漏了 `status` → 投影新增的 `taskStatus` 字段恒为 null（**生产回归**） | select 增加 `getStatus` |
| 2 | `BankDataScheduledSyncService` 硬编码 `adapterCode="MOCK"` → 通用 MOCK 删除后**所有定时同步静默失败**（异常被逐 profile 吞掉） | 改为按连接档案的 `providerType` 路由，未接的银行对该档案 fail-closed（**生产修复**） |
| 3 | V02 / TraceTest 依赖已删除的 `MOCK`/`CMB_MOCK`/`CITIC_MOCK` 适配器 | 改为显式路由到测试上下文自己的测试桩；TraceTest 补三个桩并保留厂商词汇（方向 `C`/`IN`、状态码 `SUC0000`/`AAAAAAA`）归一化验证 |
| 4 | `BankDataAdapterRegistryTest` 自身矛盾：注册了 CMB 却期望 `resolveCode(null,"CMB")` 抛错 | 修正预期——调用总开关归 `BankAdapterCallExecutor`，registry 只负责路由；补一条测试固化该分工 |

## 四、部署侧操作与验收

```bash
# 1. 备份
ssh root@101.200.72.87 'cp /opt/finflow/app.jar /opt/finflow/app.jar.bak-$(date +%Y%m%d-%H%M)'

# 2. 上传后核对 MD5（必须与上表一致）
md5sum /opt/finflow/app.jar

# 3. 重建容器
cd /opt/finflow && docker compose build app && docker compose up -d --force-recreate app
```

**验收步骤**

1. 打开「银行账户」页：中信两行（V1 遗留的基本户/一般户）应显示**未直联（灰/红）**，即便招行已接通
2. 招商银行账户：建档后为**待首查（金）**；对其发起一次 STATEMENT_PULL 同步成功后变**已直联（绿）**并带最近同步时间
3. 连接概览页：文案按实际已装配银行动态生成，不再写死"招行 CMB"；未接银行行显示 `NOT_CONNECTED`
4. 银行数据查询页：行为不变（仍只投影真实直联数据）

**注意**：中信两行的模拟余额（986400.52 / 300000）是 V1 历史种子数据，本轮未删除（D1 处置待小棵拍板）。若要彻底清除需单独执行数据清理。
