# 财务平台质量与安全检查清单

适用范围：MVP 单企业、人民币财务系统。检查项覆盖认证、RBAC、自动入账、银行接入、审计、数据迁移、配置、接口、前端端到端测试和发布验收；主动转账、支付和调拨不属于当前产品。

## 使用规则

- **P0**：上线阻断项。任一失败均不得发布。
- **P1**：高风险项。发布前必须修复；若确需带风险发布，须有书面批准、补偿控制和明确期限。
- **P2**：重要质量项。发布前完成，或登记为有负责人和截止日期的缺陷。
- 每项记录：测试环境/版本、执行人、执行时间、结果、证据链接或截图、缺陷编号。涉及接口的检查同时保留请求方法与路径、脱敏请求体、响应状态和响应体摘要。
- 测试数据使用专用虚拟账号、账户号和金额，不得使用真实生产凭证或真实收款信息。

## 1. 认证与会话安全

| 优先级 | 检查项 | 验证方式与通过标准 |
| --- | --- | --- |
| P0 | 未认证访问保护资源 | 清空会话后直接访问每个受保护页面及接口；页面跳转登录，接口返回未认证结果，不返回业务数据，并保留请求编号（如有）。 |
| P0 | 登录错误信息不枚举账号 | 分别使用不存在账号、错误密码、已停用账号、未激活账号登录；对外提示统一为“账号或密码错误”，响应状态、响应体结构和耗时不得明显泄露账号状态。 |
| P0 | 密码安全 | 检查数据库、日志、审计、错误响应和网络抓包；密码仅以强哈希存储，任何位置均无明文密码。注册/重置拒绝少于 8 位或不同时含字母和数字的密码。 |
| P0 | 重置凭证与会话失效 | 使用一次性、限时凭证验证成功、过期、重复使用和篡改场景；重置成功后所有旧会话访问保护接口均失效。 |
| P0 | 停用和角色变更即时生效 | 用户已登录后被停用或降权；下一次受保护请求不得继续使用旧权限，服务端拒绝超范围操作。 |
| P1 | 登录、重置和敏感操作限流 | 对连续失败登录、重置申请和凭证校验施加限流；达到阈值后拒绝或延迟请求，且不影响正常用户的统一错误提示。 |
| P1 | 会话令牌保护 | 验证令牌不可预测、仅经 HTTPS 传输，Cookie（如采用）具备 Secure、HttpOnly 和合适的 SameSite 属性；登出后令牌不可继续访问。 |
| P1 | 常见 Web 安全控制 | 检查 HTTPS、CSP/安全响应头、CSRF 防护（Cookie 会话）、输入输出编码和依赖漏洞扫描；扫描结果无未接受的高危项。 |
| P2 | 登录后回跳 | 未登录访问有权限的目标页面，登录后回到目标页面；无权限目标不得通过回跳绕过授权。 |

## 2. RBAC、职责分离与企业隔离

| 优先级 | 检查项 | 验证方式与通过标准 |
| --- | --- | --- |
| P0 | 服务端执行权限矩阵 | 用系统管理员、财务专员、财务经理、业务查看者逐一调用所有读写接口；结果与需求权限矩阵一致。前端隐藏菜单不能作为通过依据。无权限返回 `403`，且不泄露资源存在性或敏感字段。 |
| P0 | 企业数据隔离 | 创建两个企业及同编号资源；将企业 ID、资源 ID、筛选条件、分页参数互换并调用列表、详情、统计、搜索接口；始终只返回当前会话企业数据，跨企业资源统一拒绝且不暴露对象存在信息。 |
| P0 | 当前企业上下文不可伪造 | 篡改请求中的企业 ID、Header、查询参数和请求体；服务端以会话上下文为准，不接受客户端企业 ID 作为授权依据。 |
| P0 | 转账职责分离 | 创建人审批本人申请、审批人执行本人审批申请，分别从界面和直接接口验证；操作入口不可用，服务端返回 `403`，无状态或余额变化。 |
| P0 | 关键状态不可越级 | 对草稿、待审批、已批准、已驳回、已执行、已取消逐一尝试非法状态转换、编辑、删除和恢复；只允许需求定义的转移，已执行/已取消不可编辑或删除。 |
| P1 | 管理员最小权限 | 管理员可管理用户和银行账户，但未分配财务经理角色时不能审批；财务专员不可管理账户或用户；查看者不能出现或调用写操作。 |
| P1 | 管理员生命周期规则 | 尝试停用/删除唯一启用系统管理员；操作被阻止。存在未完成草稿或待审批任务时显示风险提示，且不自动转移任务。 |
| P1 | 权限缓存失效 | 角色修改、停用、退出、密码重置后检查各类已有令牌、缓存和多标签页；权限在下一次鉴权请求生效，不需要重新发布。 |

## 3. 转账输入、状态与幂等性

| 优先级 | 检查项 | 验证方式与通过标准 |
| --- | --- | --- |
| P0 | 输入白名单与边界 | 对付款账户、收款人、收款账号、银行、金额、摘要、计划日期提交空值、超长值、非法字符、非法账号格式、负数/零、超两位小数、极大数和错误日期；请求被拒绝，字段级错误明确，不落半成品数据。 |
| P0 | 余额与账户状态复核 | 创建、提交、执行分别使用余额不足、账户停用、账户不存在和并发余额变化数据；每个阶段按规则拒绝，失败不扣余额、不生成交易，已批准申请保持已批准并记录原因。 |
| P0 | 服务端状态机 | 绕过前端直接重复提交、审批、驳回、取消、执行及修改请求；服务端按当前状态和操作者校验，非法操作无副作用。 |
| P0 | 提交幂等 | 同一幂等键并发发送、网络重试和浏览器重复点击；只产生一条申请和一个转账编号，重复响应可识别且不重复写入。不同幂等键才允许创建不同申请。 |
| P0 | 执行幂等与原子性 | 并发执行同一已批准申请、超时后重试、服务在扣款/写交易/改状态各阶段故障；最多一次成功，最多一笔关联交易和一次扣款，事务失败时三者均回滚或由可靠补偿机制恢复到一致状态。 |
| P0 | 并发审批/执行 | 两个审批或执行请求同时到达；只有一个合法状态转换成功，另一个得到状态已变化提示，不产生重复审计、交易或扣款。 |
| P1 | 金额精度与汇总 | 使用边界金额、两位小数及多笔累计金额；数据库、余额、交易、仪表盘和接口汇总均以精确货币数值计算，不出现浮点误差。 |
| P1 | 失败可重试 | 模拟可重试网络错误和业务失败；客户端不会静默重复提交，服务端返回稳定请求编号/幂等结果，用户能明确知道是否成功。 |
| P1 | 冲正规则 | 对已入账交易创建相反金额且引用原交易的冲正；原记录不可修改，双方可追溯，余额和统计按冲正结果更新，重复冲正按业务规则拒绝。 |
| P2 | 查询参数防滥用 | 对日期、类型、状态、关键字、排序和分页使用非法值、超大页大小和深分页；按白名单/上限处理，不产生越权、超时或异常堆栈。 |

## 4. 审计、日志与敏感数据

| 优先级 | 检查项 | 验证方式与通过标准 |
| --- | --- | --- |
| P0 | 关键事件完整性 | 覆盖登录成功/失败、登出、用户和角色变更、账户变更、转账全生命周期、交易创建/冲正、权限拒绝和系统异常；每条含时间、操作者 ID、企业 ID、操作类型、目标资源 ID、结果、请求编号及适用的变更前后摘要。 |
| P0 | 审计追加不可改 | 以业务用户和数据库应用账号尝试修改/删除审计记录；均被拒绝。验证数据库权限、应用接口和管理页面均无删除/编辑通道。 |
| P0 | 敏感数据脱敏 | 检查应用日志、审计详情、错误响应、链路追踪、前端状态、浏览器存储和导出；密码、重置凭证、会话令牌、完整银行账号和不必要的收款账号均不得出现，账号展示最多末四位。 |
| P0 | 异常不泄露内部信息 | 触发校验、数据库、权限和未知资源错误；对用户仅返回安全提示和请求编号，不返回 SQL、堆栈、令牌、密钥或其他企业数据。 |
| P1 | 审计留存与检索 | 验证保留策略不少于 365 天、按企业隔离、时间/操作者/资源检索和权限控制；审计查看者范围与需求一致。 |
| P1 | 时钟与一致性 | 校验服务、数据库、日志和审计时区/时间同步；同一请求的请求编号和时间线可关联，审计时间不可由客户端伪造。 |
| P2 | 告警与监控 | 为连续登录失败、权限拒绝突增、重复执行冲突、审计写入失败和异常事务配置可观测指标及告警，并验证告警不含敏感值。 |

## 5. 数据库迁移与回滚

| 优先级 | 检查项 | 验证方式与通过标准 |
| --- | --- | --- |
| P0 | 迁移可重复与可追踪 | 在干净库和已存在部分数据的库分别执行迁移；版本记录准确，重复执行不会重复建表/数据或破坏数据，迁移脚本纳入版本管理并可审查。 |
| P0 | 约束保障业务不变量 | 检查外键、唯一键、非空、金额精度、状态值、企业 ID 和审计追加权限；直接写入非法状态、跨企业关联或重复幂等键时由数据库或服务端拒绝。 |
| P0 | 现有数据迁移校验 | 迁移前后核对行数、关键金额汇总、余额、转账关联、企业归属和审计记录；差异有可解释记录，不能静默丢失、截断或改变金额。 |
| P1 | 备份与恢复演练 | 发布前生成经过验证的备份，在隔离环境恢复；恢复后抽样查询用户、账户、交易、转账和审计，数据可用且权限正确。 |
| P1 | 失败回滚/前向修复 | 在每个关键迁移步骤注入失败；系统不会留下半迁移状态。验证回滚或前向修复方案、耗时、锁影响和操作手册。 |
| P1 | 大数据量与兼容性 | 用接近生产规模的数据执行迁移，记录锁等待、耗时、空间和应用兼容性；不造成超出发布窗口的不可控停机。 |
| P2 | 破坏性变更审批 | 删除列、改类型、改约束等不可逆操作有数据负责人批准、备份证据和回滚/恢复方案；未满足条件不得执行。 |

## 6. 环境变量与部署配置

| 优先级 | 检查项 | 验证方式与通过标准 |
| --- | --- | --- |
| P0 | 必需配置显式校验 | 在启动时缺少数据库、会话签名、加密、邮件/重置等必需配置；应用快速失败并指出变量名，不输出变量值或密钥。 |
| P0 | 生产密钥隔离 | 检查测试、预发布、生产的密钥和数据库凭证均不同，生产密钥不进代码库、镜像、前端构建产物、日志或客户端可见配置。 |
| P0 | 安全默认值 | 未配置调试、允许来源、Cookie、安全传输和日志级别时采用安全默认值；生产禁止调试模式、宽松跨域和明文传输。 |
| P1 | 配置清单与轮换 | 为每个变量记录用途、来源、是否必需、格式、责任人和轮换方式；轮换会话/加密密钥时按方案验证旧数据和会话处理。 |
| P1 | 配置注入与回滚 | 在发布候选环境注入合法、缺失、空值、错误格式配置；启动检查、健康检查和回滚行为明确，不因错误配置产生半部署状态。 |
| P2 | 依赖与版本锁定 | 锁定运行时和依赖版本，构建可复现；生产依赖扫描无未处理高危漏洞，镜像/构建产物不含 `.env`、密钥或测试数据。 |

## 7. 接口自动化测试

| 优先级 | 检查项 | 验证方式与通过标准 |
| --- | --- | --- |
| P0 | 认证与授权矩阵自动化 | 为每个接口覆盖未登录、四种角色、停用用户、降权旧会话、跨企业资源；断言状态码、数据边界和无副作用。 |
| P0 | 转账关键流程自动化 | 覆盖创建、提交、审批、驳回、取消、执行、冲正及所有非法状态转换；断言状态、交易、余额、审计和错误响应一致。 |
| P0 | 幂等与并发自动化 | 重复请求、相同幂等键、并发审批/执行和事务故障注入均可重复运行；断言唯一编号、唯一交易、余额只变更一次。 |
| P0 | 输入与错误契约 | 对所有外部字段做边界、类型、编码、超长和注入类测试；错误响应结构稳定、无内部信息，非法请求不写入业务数据。 |
| P1 | 查询/分页/排序 | 覆盖组合筛选 AND 逻辑、稳定排序、空结果、最后一页、超大页、无效筛选和企业隔离；列表与汇总一致且无重复/漏项。 |
| P1 | 数据库事务与恢复 | 注入数据库超时、唯一冲突和连接中断；断言事务回滚、可重试性、请求编号和审计结果符合预期。 |
| P1 | API 契约与兼容性 | 校验必填/可选字段、金额格式、状态枚举、错误码和版本兼容；契约变更有评审并同步更新客户端测试。 |
| P2 | 性能与限流基线 | 对登录、仪表盘、列表和执行接口进行代表性并发测试；响应、错误率、数据库负载和限流行为不超过已批准阈值。 |

## 8. 前端与端到端测试

| 优先级 | 检查项 | 验证方式与通过标准 |
| --- | --- | --- |
| P0 | 关键用户旅程 | 使用管理员创建账户并邀请专员/经理、完成激活、专员提交转账、经理审批、专员执行；页面状态、接口结果、交易、余额、仪表盘和审计均一致。 |
| P0 | 权限呈现与后端兜底 | 四角色登录后检查菜单、按钮、详情操作和深链接；隐藏入口之外，直接请求接口也必须被服务端拒绝。 |
| P0 | 重复提交与刷新 | 快速双击、刷新、后退、网络延迟和执行接口重试；按钮状态明确、无重复申请/交易/扣款，状态变化提示可理解。 |
| P1 | 表单校验与可用性 | 覆盖键盘输入、粘贴、中文/特殊字符、金额精度、空状态、服务端错误和字段回显；错误定位准确，内容不显示敏感原值。 |
| P1 | 会话异常 | 在页面打开后停用账号、过期令牌、重置密码或降权；下一次操作提示会话/权限变化并跳转或刷新，不显示旧数据。 |
| P1 | 脱敏和响应式检查 | 在桌面和窄屏检查银行账号、收款账号、错误信息、审计摘要和金额格式；无横向溢出、遮挡或敏感字段泄露。 |
| P2 | 兼容性与可访问性 | 在支持的浏览器验证核心流程、焦点顺序、键盘操作、表单标签、错误提示和对比度；关键控件可操作且无阻断性可访问性错误。 |

## 9. 发布前验收门槛

| 优先级 | 检查项 | 验证方式与通过标准 |
| --- | --- | --- |
| P0 | 需求验收回归 | 逐项执行产品需求中的关键流程和验收标准，特别是企业隔离、职责分离、重复执行、事务一致性、冲正和审计；所有 P0 通过。 |
| P0 | 缺陷与安全风险 | 无未批准的 P0/P1 缺陷、越权、敏感数据泄露、重复扣款、金额不一致、迁移数据损坏或密钥暴露。 |
| P0 | 构建与部署可回滚 | 固定版本构建产物、数据库迁移、配置清单、备份证据和回滚步骤已归档；在预发布完成一次部署及回滚演练。 |
| P0 | 生产配置复核 | 双人复核生产环境变量、数据库目标、域名/来源、HTTPS、日志级别、管理员账号和初始权限；确认无测试数据与测试凭证。 |
| P1 | 监控、告警与值班 | 健康检查、错误率、延迟、数据库、余额/交易一致性、权限拒绝、审计写入失败和备份均有监控；告警接收人和值班流程已验证。 |
| P1 | 应急与审计准备 | 已批准的回滚、密钥轮换、账号停用、异常转账处置、数据恢复和安全事件升级联系人可用；审计留存和访问权限已确认。 |
| P1 | 上线后核验 | 先用受控测试账号验证登录、权限、创建/查询和小额虚拟转账流程；核对应用、数据库、审计和监控无异常后再开放业务用户。 |
| P2 | 发布签字 | QA、安全、研发、产品/财务负责人确认测试报告、风险接受记录、迁移结果、备份恢复结果和回滚负责人；缺少任一签字则保持待发布。 |

## 10. 最低自动化回归集

每次合并和发布候选版本至少运行以下用例集：

1. 四角色权限矩阵、未登录、停用账号、角色变更和跨企业 IDOR。
2. 转账金额/账号/日期边界，余额不足，账户停用，非法状态转换和职责分离。
3. 重复提交、相同幂等键、并发审批、并发执行及事务失败回滚。
4. 执行成功后的转账-交易-余额一致性、冲正和仪表盘汇总。
5. 审计事件字段、追加不可改、日志/响应脱敏和 365 天留存策略。
6. 管理员邀请激活、登录、重置密码、登出和关键端到端用户旅程。

## 11. 自动入账一期（2026-09）

**范围边界**：仅验证 `FILE` 文件导入和 `MOCK` 模拟来源，从批次采集、校验、复核到金蝶模拟制证、模拟对账和审计追溯。真实银行 SDK/API、自动拉取银行文件、真实银行余额/回单、真实金蝶接口及真实总账/银行对账均不在本期测试范围；测试中不得访问、配置或调用它们。

| 优先级 | 检查项 | 验证方式与通过标准 |
| --- | --- | --- |
| P0 | 来源边界与模拟标识 | 分别提交固定模板文件和 `MOCK` 来源；两者仅进入自动入账域，不创建付款/调拨申请、不修改银行账户余额。模拟流水、模拟凭证和模拟对账在接口、页面、审计中均明确标识，不得表示为真实银行或真实金蝶结果。 |
| P0 | 导入幂等和重复识别 | 对同一文件/同一来源流水并发提交、浏览器刷新重试、同批次重复行和跨批次重复流水号执行导入；服务端按企业、来源、账户、流水唯一标识和文件/请求幂等依据判重。最多生成一条业务流水和一次制证机会；重复仅计入批次统计并可定位原记录。 |
| P0 | 金额、方向与币种精度 | 覆盖 `0`、负数、三位小数、极大值、科学计数法、空金额、非法方向、非 `CNY` 币种及收入/支出边界；金额以 `BigDecimal`/`DECIMAL(19,2)` 等精确口径处理，金额均为正数且方向决定口径，不允许舍入后静默入账。 |
| P0 | 校验异常不入账 | 对文件级错误、缺失最小识别信息、非法流水号、账户不存在/停用、时间/摘要/对手信息错误、非法金额和重复行分别验证；无法形成最小识别信息的行不写入流水表，有可追溯标识的异常行仅以 `INVALID` 记录且不可复核、不可制证。批次有效/无效/重复/总数准确。 |
| P0 | 批次与流水状态机 | 逐项验证批次 `PROCESSING -> COMPLETED/PARTIAL_COMPLETED/FAILED`，流水 `VALID/INVALID/DUPLICATE`、复核 `PENDING -> APPROVED/REJECTED`、推送 `NOT_PUSHED -> PUSHING -> PUSHED/PUSH_FAILED` 及受控重试。绕过前端调用非法跃迁时返回稳定错误且无数据副作用。 |
| P0 | 复核职责分离 | 使用导入人、复核人、制证人三类不同账号验证：导入人不得复核本人导入流水，直接调用接口返回 `403`；复核仅可处理 `VALID + PENDING`，驳回原因必填。并发复核只有一次成功，原始流水和已完成复核结论不可覆盖。 |
| P0 | 金蝶模拟制证单次性与重试 | 仅允许 `VALID + APPROVED + NOT_PUSHED/PUSH_FAILED` 流水由 `voucher:push` 推送。对重复点击、网络重试、并发请求、模拟成功、确定失败及结果未知分别注入测试；成功仅产生一个模拟凭证号，失败不改变复核结论，重试保留完整事件链，未知结果不得虚报成功或另建凭证。 |
| P0 | 对账差异定位 | 按批次和日期范围核对来源输入、有效落库、已复核、已模拟制证的收入/支出笔数与金额；刻意制造缺凭证、金额/方向/关键字段不一致和计数不平情况，均标记 `MISMATCH` 并定位到流水、批次和差异类型。不得把模拟对账表述为真实银行或总账对账。 |
| P0 | 全链路追溯与审计不可篡改 | 从批次号、流水号和模拟凭证号任一入口双向查询来源、批次、校验、复核、推送、对账和审计。每个关键事件含操作者、时间、前后状态、结果、请求编号和脱敏摘要；业务用户与数据库应用账号均不能修改/删除审计或成功凭证历史。 |
| P0 | 自动入账权限矩阵 | 对未登录、无自动入账权限、`statement:view`、`statement:import`、`statement:review`、`voucher:push`、`reconciliation:view` 及四类业务角色分别测试页面、深链接和所有接口。无权请求返回 `401/403`，不可借由批次、流水、凭证、企业 ID 或查询参数访问其他企业数据。 |
| P1 | 批次恢复与可观测性 | 模拟解析、落库、审计写入、制证调用、网络超时与服务重启；批次/流水保持可解释的失败或处理中状态，重试不重复入账。记录批次号、流水号、请求编号、错误分类、处理时长及重复/失败指标，告警不含原始载荷或完整账号。 |
| P1 | 前端联调与安全呈现 | 校验预检不写入正式流水，处理期间防重复提交，服务端结果是唯一成功依据；异常、部分成功、重试、403、会话失效和并发状态变化均有明确反馈。默认只显示对手账号末四位，原始载荷与错误消息不进入浏览器本地存储或控制台。 |
| P1 | 效益复盘 | 以财务负责人确认的上线前连续自然月为基准，对可比业务量记录导入、异常处理、复核、模拟制证和追溯工时。2026-09 后首个完整自然月目标节省 6-7 人天/月；未达标则形成原因、补偿措施、负责人和完成日期。 |

## 12. 银行接入模块一期

**范围边界**：银行接入是独立于自动入账的连接、采集运维与查询模块，包含银行连接、采集监控与日志、五类只读数据查询。2026-09 一期只允许受控的未启用/模拟展示和系统内事实数据查询；不得配置、调用或暗示已接入真实银行 SDK/API。专项用例和证据模板见 `docs/operations-module-test-plan.md`。

| 优先级 | 检查项 | 验证方式与通过标准 |
| --- | --- | --- |
| P0 | 可折叠导航、权限与深链接 403 | 使用未登录、无权限、只读、运维和管理员账号，在侧栏展开、折叠、刷新及恢复上次导航状态后检查四个分组及页面入口；折叠只能改变展示，不能暴露无权子项或绕过守卫。无权入口隐藏，直接访问深链接和接口返回 `401/403`，不泄露页面、任务、日志或账户对象存在性。前端隐藏不能替代服务端鉴权。 |
| P0 | 直联一期边界与文案 | 检查直联管理、状态监控、任务详情、帮助文案、接口响应和审计记录；一期明确显示“未启用”或“模拟”，不得出现已连接、已拉取、已同步、真实余额/流水等误导性成功表述。发现真实银行 SDK/API、真实凭据或真实网络调用即阻断发布。 |
