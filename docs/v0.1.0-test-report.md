## 3. 高风险问题（P1）

| 编号 | 领域 | 证据与影响 | 建议 |
| --- | --- | --- | --- |
| P1-01 | 生产配置默认值 | [application.yml:4-5](../backend/src/main/resources/application.yml) 将默认 profile 设为 `dev`，且包含固定开发 JWT 密钥和 `mock-mode: true`（26-40 行）。若生产部署遗漏 `SPRING_PROFILES_ACTIVE=prod`，会以开发密钥和模拟支付启动。 | 生产必须显式启用 `prod`，缺失时快速失败；将开发密钥与模拟器限定在本地开发配置，加入启动时环境校验。 |
| P1-02 | 生产数据库传输 | [application-prod.yml:6](../backend/src/main/resources/application-prod.yml) 提供 `useSSL=false` 和 `allowPublicKeyRetrieval=true` 的默认 JDBC URL。 | 移除不安全默认 URL，要求由生产环境注入启用 TLS 且受证书校验的连接串。 |
| P1-03 | API 文档暴露 | [SecurityConfig.java:64-73](../backend/src/main/java/com/finance/system/config/SecurityConfig.java) 对 `/doc.html`、OpenAPI 和 Swagger 资源全部 `permitAll()`，没有按 profile 限制。 | 生产关闭文档端点，或仅在受控网络/管理员授权下暴露。 |
| P1-04 | JWT/RBAC 已有基础但不完整 | 后端使用 BCrypt（[SecurityConfig.java:31-34](../backend/src/main/java/com/finance/system/config/SecurityConfig.java)）、HMAC JWT 并在每次带令牌请求时重新加载用户及权限（[JwtAuthenticationFilter.java:36-46](../backend/src/main/java/com/finance/system/security/JwtAuthenticationFilter.java)）；银行、用户、角色接口也存在方法级 `@PreAuthorize`。但 JWT 无撤销/会话版本，且全部实体和查询均不含企业上下文。 | 保留现有服务端方法授权；补充企业范围过滤、会话/令牌失效策略、登录限流和相应自动化测试。 |
| P1-05 | 输入与金额校验 | [BankTransferRequest.java:12-18](../backend/src/main/java/com/finance/system/bank/dto/BankTransferRequest.java) 仅限制最小金额，无 `@Digits` 或小数位上限；请求中没有计划日期、申请编号或幂等键。前端账号格式仅允许 10-30 位数字，后端允许 8-64 位字母数字，契约不一致。 | 定义并共享金额精度、账号格式和字段长度契约；服务端以货币精度、白名单和幂等键为准。 |

| P1-07 | 生产银行适配器未实现 | 生产 `mock-mode=false` 时 [ExternalCiticBankSdkAdapter.java:20-29](../backend/src/main/java/com/finance/system/bank/citic/ExternalCiticBankSdkAdapter.java) 恒返回 `501`。 | 在银行直连范围内实现、签名、证书和回执处理并完成沙箱验收；在此之前禁止将该接口定位为真实支付能力。 |
| P1-08 | 审计与错误关联缺口 | 全局异常响应只返回时间，不包含需求要求的请求编号（[ApiResponse.java:8-18](../backend/src/main/java/com/finance/system/common/api/ApiResponse.java)）；全仓库无审计实体、表或写入服务。 | 增加不可修改的审计存储、请求关联 ID、访问控制、保留策略和失败告警。 |

## 4. 已观察到的正向控制（不构成发布批准）

| 领域 | 观察结果 |
| --- | --- |
| 后端认证基础 | Spring Security 使用无状态会话、BCrypt 和 JWT 签名；非法 JWT 会清除安全上下文。 |
| 后端方法授权 | 用户、角色、银行账户和转账入口使用 `@PreAuthorize`；未认证请求默认需要认证。 |
| 账号展示 | `GET /api/bank-accounts` 的响应经 `maskAccountNumber` 仅返回末四位（[BankAccountService.java:79-84](../backend/src/main/java/com/finance/system/bank/BankAccountService.java)）。 |
| 迁移基础 | Flyway 已启用，V1 包含 RBAC 外键和复合主键约束。 |
| 生产密钥引用 | `application-prod.yml` 将数据库密码和 JWT 密钥引用为环境变量，而非直接写入生产值。 |

## 最终结论

**v0.1.0 发布验收不通过。** 当前实现可作为本地 UI/后端原型继续开发，但不具备企业财务系统上线所需的真实认证、前后端权限闭环、企业隔离、资金状态机、幂等与原子性、审计留存及可重复测试证据。任何真实数据、真实账户或真实支付能力上线均应在上述阻断项关闭并完成独立复审后进行。
